# ADR-011: Stage 0 Lowering — the Grammar Protocol onto the Parser Backend

**Status:** Accepted
**Date:** September 7, 2026
**Target Version:** Nikaia 0.0.8 (bootstrap compiler)
**Implements:** [ADR-009](adr-009.md) D1-D3 and D5 on the Nikaia side; Part II, 10.1/10.5/10.7
**Related:** [ADR-001](adr-001.md) (Stage 0 is a transpiler), [ADR-004](adr-004.md) (the rustc
executor), [ADR-007](adr-007.md) (the DSL protocol), [ADR-008](adr-008.md) (views and the input
lifetime)

---

## 1. Context

Everything the parallel grammar protocol needs has existed upstream since ADR-009 landed:
`#[frame(boundary = …)]` and its check, `frame_end`, bounded repetition, `par_fold`, and the
generated `frames_<RULE>` / `merge_<RULE>` / `parse_<RULE>_pieces` trio. Nikaia could not reach
any of it. `examples/1brc.nika` says so in a comment, and the compiler said so in its AST: a
`grammar` item was

```rust
Grammar { name: Ident, content: String }
```

A string is a shape no compiler can do anything with. It cannot verify a frame, cannot find the
entry rule of a `dsl … from …`, cannot decide the driver's `Parallelism` from the profile, and
cannot even rewrite `@frame` to `#[frame]` without parsing it first. The README's roadmap line —
"Bootstrap Compiler: a transpiler written in Rust (Stage 0)" — is exactly this gap.

This ADR records what the lowering *is*, and, more importantly, what it deliberately refuses to
do.

---

## 2. Decisions

### D1 — A grammar is parsed, not carried as text.

`grammar Name { … }` becomes a structure: rules, alternatives, patterns, the commit point,
repetition bounds, `fold`/`par_fold` with their expressions, and the keyed `@frame` attribute.
`dsl Name from input` becomes an expression that names a grammar in the same file.

The alternative — keep the body as text and re-emit it — fails at the first question anyone asks
of it. Which rule does `dsl Measurements from data` enter through? Is it a `par_fold`, so that a
piece driver exists? Does this grammar even declare a frame? All three are answered by looking at
the rules, and none can be answered by a string.

### D2 — The lowering is syntactic, and never guesses a meaning.

Every action block, every `init`/`step`/`merge`, every function body is emitted as written, name
for name. Where Nikaia and Rust disagree about what a name means, the emitted program says so by
failing to compile — the printer does not invent semantics to paper over it.

The concrete case this rules on: `1brc.nika` writes

```nika
par_fold(MEASUREMENT, Summary::new, fn(acc, m) { acc.record(m) }, Summary::merge)
```

where `record` and `merge` are `&mut self` methods. A monoid's step and merge are
`(Acc, Item) -> Acc` and `(Acc, Acc) -> Acc`, so making this fit means emitting
`|mut acc, m| { acc.record(m); acc }` — inferring from the *shape* of the tail expression that
the method mutates and that the accumulator should be threaded. Rejected: `acc.merged(m)`, a
method that returns a new accumulator, has the same shape and would be silently mis-lowered. The
adapter is a typing question, and it is answered once the compiler lowers `impl` blocks and knows
the receivers — not before, and never in an emitter.

Consequence, stated plainly: the *grammar half* of `1brc.nika` lowers today; the file as a whole
does not, and the parts that do not are named in §4.

### D3 — `@frame` lowers key for key, and Nikaia does not re-implement its check.

`@frame` → `#[frame]`, `@frame(boundary: "\n")` → `#[frame(boundary = "\n")]`,
`@frame(boundary: "\n", unchecked)` → `#[frame(boundary = "\n", unchecked)]`. The boundary keeps
its escape text: what the source wrote as `"\n"` is what the backend is handed.

The check that a boundary cannot occur inside a frame stays upstream, where it already is. Two
implementations of ADR-009 D1's "checked, never rewritten" would eventually disagree about what
is safe, and the version of that disagreement that matters is the one where Nikaia accepts a
grammar the backend rejects — a compile error against generated code, blaming a line the user
never wrote. One verdict, one place.

`unchecked` is passed through for the same reason: it is the user's assertion to the checker, and
Nikaia adding a second opinion about it would only be a second thing to get wrong.

### D4 — The profile chooses the `Parallelism`, and nothing else.

`dsl Name from input` lowers to

```rust
Name::parse_<rule>_pieces(input, ParseContext::<()>::default, Parallelism::Auto)?
```

under Advanced, and the identical call with `Parallelism::Off` under Lite. That is the whole of
ADR-009's "under Lite a `par_fold` degrades to a sequential fold": same accumulator, same merge,
same result, no threads, and the driver defines `Off` to be the plain parser.

The two emitted programs differ in one token. Nothing else in the lowering reads the profile,
because nothing else may: a profile is a runtime, not a dialect, and the moment it changes what a
program *means* the language has two of them.

A grammar whose entry rule is not a `par_fold` has no pieces to cut and no merge to apply, so it
gets the sequential driver instead — the rule's own parser, run once over the whole input.

### D5 — A rule that *is* a `par_fold` gets its binding from the compiler.

ADR-009 D2 requires a `par_fold` to be the whole body of its rule, so there is nothing an action
block could add: the value of the rule is the value of the fold. Nikaia therefore accepts the rule
without one — as `1brc.nika` writes it — and the emitter supplies the binding the backend wants
(`folded:par_fold(…) -> { folded }`).

Everywhere else an action is required, which is Part II, 10.1's note ("action blocks are required
today") doing double duty: it is also what makes a rule's pattern unambiguous, because the pattern
ends at its `->` rather than wherever the next rule happens to begin.

### D6 — A view takes the input's lifetime, and the struct that holds it comes along.

`&str` in a rule's return type is emitted as `&'a str`, `'a` being the lifetime the parser backend
gives its input. A struct with a view field is emitted with `<'a>` and named with it wherever it
appears, transitively — `Reading` holds a `&str`, so `MEASUREMENT -> Reading` becomes
`MEASUREMENT -> Reading<'a>`.

How it is *spelled* follows the position, and only that: named (`'a`, `Reading<'a>`) inside the
grammar module and on the structs it builds, where the two have to be tied together; elided
(`&str`, `Reading<'_>`) in a function signature, which declares no lifetime and would not compile
with one named.

This is ADR-008 in the only place a bootstrap compiler can express it: the source never writes a
lifetime, because `&` is a view marker there and nothing else. The tether-state lattice is not
implemented — every view is emitted as `Borrowed` — which is correct for the grammars written so
far and wrong the moment one escapes its buffer. That is a named limitation, not a design.

### D7 — Comments are whitespace, and string literals are Nikaia's own.

Both are properties of the compiler's own grammar, and both were missing because no sample had
needed them. `WS = (WSE | COMMENT)*` is the only place comment skipping can be said, since the
backend inserts `WS` between the tokens of every syntactic rule. The built-in `string` recognizes
`\\` and `\"` and no other escape — one short of `"\n"`, which is the boundary every frame in the
corpus is written with — so the compiler brings its own lexical `STRING`, which keeps escapes as
written. Keeping them is what makes D3's "the backend is handed the same `"\n"`" true.

### D8 — A grammar reaches the parser backend through the transpiler, and the Bridge IR path says so.

Stage 0 has two backends and they are not interchangeable. `--backend rust` emits Rust source and
is the one that carries grammars; the Bridge IR (ADR-004) has no representation for a macro
invocation, so a `grammar` item on that path is an error naming the backend to use — never a
silently dropped item, which would compile a program with its parser missing.

## 3. What this makes of the corpus

* **`tests/fixtures/measurements.nika`** — the grammar half of 1BRC, cut to what Stage 0 lowers
  end to end. Its emitted Rust is checked in, and the test that guards it does not only compare
  text: it `include!`s the file, so the backend has to accept every line, and it runs the
  generated driver at five different cuts to check that the answer does not depend on how the
  input was divided — on an input it accepts and on one it rejects.
* **`examples/1brc.nika`** — the `grammar Measurements` block and `Reading` lower unchanged. The
  rest of the file does not parse yet (§4), so the example still does not compile; what changed is
  which half is missing.

## 4. What is deliberately not here

Named, so that "the compiler lowers the grammar protocol" is not read as more than it is:

* **`impl` blocks and methods.** Without them the fold's `Summary::new`, `record` and `merge` have
  no definitions to check against, which is the other half of D2.
* **`throws` / `catch` / `??` and string interpolation.** `1brc.nika`'s `main` uses all four.
* **The tether-state lattice** (ADR-008 D2): views are emitted as plain borrows (D6).
* **`sync` checking** (Part II, 12.1). The keyword parses and is recorded; nothing verifies that a
  parallel section contains no pause. ADR-009 D3 lists this as Nikaia's own, and it stays open.
* ~~**Spans.** Errors are reported against the generated Rust, not the `.nika` line.~~ Closed by
  [ADR-012](adr-012.md): the lowering emits a source map and `nikaia --explain` reports rustc's
  diagnostics against the `.nika` file. Expression-level granularity is still open (ADR-012 D4).
* ~~**`std` mapping.**~~ Closed by [ADR-013](adr-013.md) D1: `std` is a crate, and a program that
  imports from it gets `pub use nikaia_std::prelude::*;` so the names resolve as written.
* **Input provenance, and therefore the hasher.** [ADR-010](adr-010.md) decided this at the
  specification level: `fs::map` is a trusted source (D2), so `1brc.nika`'s station map should get
  a fast hash *with nothing written in the source about hashing* (ADR-010 §3). Stage 0 cannot do
  it. Choosing the hasher means knowing that a map's keys are views into a buffer that came from
  a trusted source, which is dataflow through the grammar's return types and a struct field -
  a semantic inference, and D2 above forbids the emitter from making one.

  So Stage 0 does the only correct thing available to it: **it behaves as though every buffer
  were untrusted.** `nikaia_std`'s `HashMap` is Rust's, whose `RandomState` is exactly ADR-010
  D5's `Untrusted` row - a keyed hash with a per-process random seed. That is not a bug to be
  fixed by annotating the example; it is ADR-010 D1's own rule ("barriers widen to `Untrusted`")
  applied to the widest barrier there is, an analysis that did not exist yet.

  **Closed.** The analysis exists (ADR-020's ledger says which `std` calls are sources and who
  chose their bytes; `contracts::trust` joins them), and a map keyed by the input gets the hash
  that answer picks. Measured with callgrind on 200 000 rows, the same tree built twice - once
  with the hash chosen and once with it forced back to the hardened one, byte-identical output:

  | | hardened | chosen |
  | :--- | ---: | ---: |
  | instructions | 120.0 M | **89.1 M** |
  | per row | 600 | **446** |

  **26 % of the instructions on the flagship**, which is the item this section called the
  largest single one left. It is above the 22 % predicted here because the prediction was taken
  against a slower baseline; what the two columns above share is one tree, one input and one set
  of flags, so the ratio is the hasher and nothing else.

  What Stage 0's analysis is, exactly, so that a later one is not mistaken for it: **one buffer,
  because ADR-008 gives a compilation unit one input lifetime.** The join over a program's
  sources is therefore not a coarsening of a per-buffer analysis - it is the per-buffer analysis,
  for the one buffer this representation can express. `nikaia --trust` prints it (D7), and the
  provenance is a *choice* in the build cache's key alongside the profile, because it decides the
  code that comes out.

  Not true either, and smaller: D5 requires the build to *fail* on a target with no entropy
  source rather than seed predictably. Rust's `RandomState` makes no such promise, so neither
  does Nikaia today.

## 5. Rejected alternatives

* **Keep the grammar as text and re-emit it verbatim** — rejected in D1: it answers none of the
  questions the lowering has to ask, and `@frame` → `#[frame]` alone already requires parsing.
* **Re-implement the frame check in Nikaia** so errors point at `.nika` lines — rejected in D3.
  The right fix for the error's provenance is spans (§4), not a second checker whose verdicts can
  drift from the first.
* **Infer the accumulator threading from the step's shape** — rejected in D2. It is a semantic
  decision made in a printer, and it is wrong for a step that returns a new accumulator.
* **Parallelise a plain `fold` under the Advanced profile** — rejected upstream in ADR-009 and not
  reopened here: a merge over floats would make the answer depend on the core count, and the user
  asking for `par_fold` is exactly the statement that it does not.
* **A `--profile` that changes more than the executor** — rejected in D4. Two profiles that mean
  different things are two languages.

## 6. Risks

* **A syntactic lowering reports its errors in the wrong language.** A Nikaia name that does not
  resolve in Rust surfaces as a rustc error against generated code. Its *position* is corrected by
  [ADR-012](adr-012.md); its *wording* stays Rust's, which is bearable precisely because the
  lowering is name for name (D2) and unbearable the moment that stops being true.
* **The struct-literal ambiguity.** `Reading { name, temp }` and the brace that opens a block are
  told apart by parsing `if`/`for` heads with a brace-free expression rule — the same restriction
  Rust imposes. A struct literal in one of those heads must be parenthesised, and the error if it
  is not will be about the block, not about the literal.
* **The checked-in expected output is a test of the emitter, not of taste.** It will churn on any
  formatting change to the emitter. That is intended: the file is compiled by the test, so churn
  is visible and cheap, and a diff in it is a diff in what the backend is handed.
