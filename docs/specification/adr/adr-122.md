# ADR-122: A Function-Typed Parameter Lowers by Its Type — the Future Shape Unless It Says `sync`

**Status:** Accepted · **Built:** no — see §5
**Date:** September 16, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-102](adr-102.md) D2, D3 and D5 (the type says what the code
may do; run-or-kept is inferred; the lowering follows), [ADR-009](adr-009.md)
D4 (measure before choosing a shape), [ADR-055](adr-055.md) D1 (a pausing
function is an `async fn`)

## 1. Context

A lambda whose body pauses has no lowering the language below offers as a
closure: Rust has no stable `async` closure, and the way out has been known
all along — a closure that **returns** a future. [ADR-102](adr-102.md) gave a
callee's parameter a type that can say it takes such a thing, and said how a
*kept* parameter lowers (a boxed closure over a boxed future). What it left
between two sentences was the case the whole question exists for: a *run*
parameter — one the callee calls and does not store — handed a lambda that
pauses. A run parameter lowered *"as `std`'s do today, a closure argument"*,
which is `impl Fn(A) -> R`, and a pausing lambda cannot be written into one.

## 2. Decisions

### D1 — The parameter's type decides the shape, and nothing inferred stands behind it.

A parameter whose type may pause — `fn(A) -> R` without `sync`, which is the
default — lowers to the future shape whether the callee runs it or keeps it:
a closure returning a boxed future, called with an `.await`. A parameter
whose type says `sync` lowers to a plain closure. A reader can tell what a
signature costs by reading it.

### D2 — The refusal of a pausing lambda at a run parameter goes with it.

A lambda that pauses fits a parameter whose type allows pausing, run or kept
([ADR-102](adr-102.md) D2). The build-time refusal `open-work.md` carried as
*a lambda that pauses is refused* has no case left.

### D3 — The box is measured, not assumed.

A run parameter handed a lambda that does *not* pause now pays a heap
allocation and a dynamic call it did not before. That is the cost of D1, on
the common case, and it is measured on the corpus before the record is
closed as built — the standard [ADR-009](adr-009.md) D4 set for choosing a
shape. `std`'s own entries are untouched: they are Rust with hand-written
signatures, so `map` and its kin pay nothing new.

## 3. Consequences

* `examples/fortunes.nika`'s route handler, `.route("/fortunes") fn {
  fortunes(db) }`, is writable: `route`'s parameter allows pausing, and the
  lambda is lowered to the shape that can.
* One rule where there were two sentences, and it is readable off the type.
* A library author who wants a callback with no box writes `sync` on the
  parameter, which is what the word already promises.
* **What it costs:** the emitter reading the type where it read the run-kept
  answer, and D3's measurement.

## 4. What this does not decide

* Whether an `async` closure, should the language below stabilise one,
  replaces the boxed future shape; the surface would not change.
* `sync` as a performance word. It is not one here: it lowers to the plain
  closure because that is what *never pauses* means.

## 5. What is built

Nothing. A run parameter lowers to `impl Fn`, and a pausing lambda handed to
one is refused. The order of work:

1. the emitter lowering by type, D1;
2. the refusal removed, D2, and its test inverted;
3. the measurement, D3, with the number in this record's §3;
4. `fortunes.nika` as the corpus program.

`docs/open-work.md` carries it.
