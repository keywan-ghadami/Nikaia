# ADR-047: A Package Is a Directory, and a Library Arrives by Path

**Status:** Accepted · **Built:** nothing — see §5
**Related:** [ADR-046](adr-046.md) D1 (what `use` does; this record decides what
it *names*, and moves that boundary from the file to the package),
[ADR-002](adr-002.md) D1 §5 and D4 (the three things the toolchain refuses to
guess at, and the path `std` already arrives by), [ADR-045](adr-045.md) §3 (the
portability rule this makes reachable), [ADR-043](adr-043.md) D6 (the overflow
check, whose foreign/own split D2.5 assigns rather than inherits),
[ADR-020](adr-020.md) (the ledger a consumer reads).

## 1. Context

There is no way for one Nikaia package to depend on another. Part III 13.2's
manifest shows a Nikaia package beside a Rust one and refuses the first with its
reason: no record names a registry, a name space or a distribution format, so the
compiler does not guess ([ADR-002](adr-002.md) D1 §5). `type = "rust"` resolves
through Cargo; `std` arrives by path into a sysroot. Between them, nothing.

**And that is not only a missing convenience.** The reason a crossing verdict may
not consult `user_parallelism` is that *a library built at one setting has to stay
usable at the other* — the sentence that decided the shape of
[ADR-045](adr-045.md) D1. It is a correct rule and it should stay. But it protects
a situation nothing can construct: there are no Nikaia libraries, because there is
no way to depend on one.

**A second half arrived with the first.** With file = module there is no
**re-export**: no way for a unit to offer a name another unit declares. A library
is many files, so a consumer must name the file a declaration happens to sit in —
the library's *internal layout is its public surface*, and moving a declaration
between files breaks every consumer.

## 2. Decisions

### D1 — A package is a directory, and its files share one namespace.

The files in it see one another with **no `use` at all**. What the package offers
outward is whatever says `pub`, in whichever file it is declared. A consumer
writes `use http` and names the **package**, never a file inside it.

**This removes the re-export problem rather than patching it.** There is nothing
to re-offer, because the names inside a package already share a space — so no new
form is needed at all. And a library's internal file layout stops being its public
surface by construction: moving a declaration from one file to another is
housekeeping, and breaks no consumer.

**The field points the same way.** Java, Go and Rust all put the boundary of
privacy and publication *above* the single file. Python is the one that puts it at
the file, and `__init__.py` — a front door maintained by hand, forgotten names and
all — is the consequence rather than an accident of it.

**The alternative, considered and refused:** keep file = module and add a
re-export form. Not wrong, and it would leave Part I 9.2 untouched. It costs a new
form in a language that has just withdrawn two ([ADR-022](adr-022.md),
[ADR-041](adr-041.md)), and it moves the upkeep onto every library author forever.

**What it changes, and this is written down rather than discovered:** Part I 9.2's
privacy boundary moves from the file to the package — a declaration is private to
its *package* unless it says `pub` — and two files of one package may not declare
the same name. Those sentences are rewritten rather than extended.

### D2 — A package may be depended on by **path**, and by nothing else yet.

`std` already arrives that way ([ADR-002](adr-002.md) D4), so this generalises a
mechanism rather than adding one.

**No registry, no name space, no distribution format.** The three things
[ADR-002](adr-002.md) D1 §5 refuses to guess at stay open, deliberately. Go went
years with the fetch location as the identity; Rust and JavaScript built their
registries early and carry decisions made when there were three packages. A
registry is built when there are libraries, not before.

Five rules come with it, or they get decided by accident:

1. **The manifest key is the name.** `use` writes the key and the path says where
   it comes from. Two libraries that both want to be `http` are therefore the
   consumer's to name apart, which is the authority [ADR-046](adr-046.md) D3
   already gives them.
2. **Transitive dependencies are not visible.** If A depends on B and B on C, A
   does not see C. Otherwise a library's surface is everything it happens to use,
   and swapping an internal dependency breaks consumers.
3. **The same path is the same package; a different path is a different package**,
   identical contents included. With no versions there is nothing to unify, and
   two paths to two copies would be two types of one name.
4. **A dependency's `[build]` section is ignored, and the compiler says so.** A
   package is built with the settings of the program that uses it. Anything else
   would put two answers to the parallelism question in one build
   ([ADR-037](adr-037.md) D2).
5. **A Nikaia dependency is part of the program, not a foreign package.**
   [ADR-043](adr-043.md) D6 turns overflow checks on for the program and off for
   every foreign package. A Nikaia dependency is written in this language and
   carries this language's promise, so an overflow in it is the same broken state.
   Without this stated it lands on the foreign side by accident — that is where a
   dependency mechanically appears — and then a library computes silently wrong
   numbers while the program calling it aborts.

## 3. Consequences

**[ADR-045](adr-045.md)'s portability rule becomes testable.** It has protected a
situation nothing could construct; a path dependency is the smallest change that
makes the first Nikaia library the first real test of something so far only
argued.

**[ADR-046](adr-046.md)'s boundary moves and its rules stand.** `use` still names
a unit and brings nothing in; the unit is a package. D4's "a prefix must be
introduced" and D5's "one name per file" are unchanged in what they say and
changed in what they range over.

**`docs/open-work.md` §1.1 half disappears.** Naming a type across a *file*
boundary stops being a thing that happens; what remains is the cross-package case,
which is what the entry was always really about.

**And §1.6 changes shape.** A `Shared` field's count is decided per file today,
and the fail-closed floor that keeps two files agreeing is not needed between two
files of one package — they are one analysis. It is needed across a package
boundary, where the count cannot be agreed at all without something written down.

## 4. What this does not decide

A registry, a name space, a distribution format and versions — D2 says so, and
each is a decision this project will make when it has libraries to learn from.
Nothing here should be read as a first step toward a particular one of them.

## 5. What is built

**Nothing.** A file is still a module (Part I, 9.1), `use` still names a file
beside the entry, privacy is still per file (`NK1110`), and a Nikaia package
cannot be depended on at all — Part III 13.2 refuses one with the reason
[ADR-002](adr-002.md) D1 §5 gives.

What exists is one half of the machinery D1 needs, built for the file boundary and
reusable one level up: `Ledger::absorb` qualifies both the key and the types inside
an entry, so a name from another unit resolves to one type
(`docs/open-work.md` §1.1).
