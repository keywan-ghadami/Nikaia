# ADR-004: One Lowering, Two Exits — `rustc_ast` Built Once, Printed or Driven

**Status:** Accepted · **Built:** D1 and D2; D3's direct-driver exit is not
**Related:** [ADR-003](adr-003.md) (Bridge-IR, which this consumes),
[ADR-001](adr-001.md) D4 (Stage 0 is a transpiler — D2 is what keeps that true),
[ADR-012](adr-012.md) (diagnostics, which need the generated source to be
readable)

## 1. Context

The executor turns Bridge-IR into a binary. Two things are wanted from it that
pull apart: the fastest path is to hand `rustc` an AST in memory and skip its
parser, while debugging the compiler needs the generated Rust as text a person
can read.

Doing both the obvious way means two backends — a string builder and an AST
builder — which is double the maintenance and guaranteed drift between what is
debugged and what is shipped.

## 2. Decisions

### D1 — There is one lowering, and it builds `rustc_ast`.

`BridgeModule` → `rustc_ast::Crate`, in a single pass. The mapping for a
construct — `BridgeLet` to `ast::Local` — exists in exactly one place.

Building the AST rather than concatenating strings also makes a syntactically
invalid program unrepresentable: the types refuse it, where a string builder
would emit it and fail later in a place that does not name the cause.

### D2 — Text is produced by printing that AST, not by a second code generator.

`rustc_ast_pretty::pprust` serialises the same `rustc_ast::Crate` back to Rust
source. Inspectable output is therefore a *view* of what is compiled, never a
parallel implementation of it.

This is what makes [ADR-001](adr-001.md) D4's "Stage 0 is a transpiler" cheap to
keep true, and it is the path that ships today: the executor prints the crate
and invokes `rustc` as a subprocess.

### D3 — The in-memory exit stays open, and costs nothing to keep open.

Feeding the same `rustc_ast::Crate` to `rustc_interface::run_compiler` skips
`rustc`'s parser. Because D1 already produces the AST, this is a different
*consumer* of it rather than a different backend, and can be added when the
subprocess cost is worth removing.

Not built. `rustc-executor` links `rustc_driver` for the AST types; the
compilation itself is the subprocess.

## 3. Consequences

The `rustc_private` exposure is real and is confined to one crate: a nightly
that moves `rustc_ast` costs an update to the lowering mappings and nothing in
any frontend ([ADR-003](adr-003.md) D1).

Printed output is machine-formatted and carries no comments — Bridge-IR does not
transport them. So the generated Rust is readable but is not a source file
anybody edits, which is the intent: the `.nika` file is the source, and
[ADR-012](adr-012.md) is what makes an error point back at it.
