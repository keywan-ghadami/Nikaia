# ADR-007: Scannerless Grammar Protocol & Hybrid DSL Binding

**Status:** Accepted
**Date:** September 5, 2026
**Target Version:** Nikaia 0.0.7
**Supersedes:** the `unsafe asm` core construct (Part III, Chapter 16, as of 0.0.5)
**Related:** [ADR-001](adr-001.md) (parser toolchain), [ADR-002](adr-002.md) (multi-language
toolchain), [ADR-005](adr-005.md) D4 (tethered slices)

---

## 1. Context

This ADR recovers and re-decides the content of **RFC 0.0.6** ("Grammar Protocol, Scannerless
Parsing & Typed Bindings", 24 January 2026).

That RFC was merged into `main` as PR #2, its RFC file was deleted a day later
("done"), and the spec text it produced was then reverted wholesale by commit `c6ff1fa`
("update spec", 19 February 2026). The 0.0.6 spec files therefore describe the *0.0.5*
grammar model, while the version label moved on. The full forensic record is in
[`docs/analysis/branch-review-0.0.5-v0.0.6.md`](../../analysis/branch-review-0.0.5-v0.0.6.md).

We are **not** reverting the revert. The RFC's proposals are re-examined here on their merits
and adopted, deferred, or rejected individually — with the significant advantage that the
parser backend has since been built, so several proposals are no longer speculative.

### 1.1. What the implementation already settled

Between the RFC and today, the toolchain moved from `syn-grammar` to
[`winnow-grammar`](https://github.com/keywan-ghadami/winnow-grammar) (ADR-001) for reasons
that had nothing to do with the RFC: the `syn` token stream could not express Nikaia syntax.

That move independently produced the RFC's central architectural demand. `winnow-grammar`
parses `&str` / `&[u8]` rather than a token stream — it is **scannerless**. Two proposals
arrived at the same place from opposite directions, which is the strongest evidence available
that the direction is right:

| RFC 0.0.6 proposal | Status in `winnow-grammar` |
| :--- | :--- |
| Scannerless parsing, no global lexer | **Implemented** — text/byte input; lexical (UPPERCASE) vs. syntactic (lowercase) rules replace the lexer/parser split |
| Commit Points, spelled `=>` | **Implemented** — the cut operator, same symbol, same semantics |
| Error recovery / synchronization points | **Implemented** — `recover(rule, sync)` |
| Zero-copy token handling | **Implemented differently** — a string interner (`Symbol`), see §4; currently unusable, see D7 |
| Auto-AST (generate structs/enums when no `->` mapping) | **Not implemented** — action blocks are required |
| Regex terminals compiled to DFAs | **Not implemented** — fixed built-in terminals instead |

## 2. Decisions

### D1 — Scannerless parsing is a language guarantee, not an implementation detail

The core parser maintains no global token stream. A grammar consumes the raw character
stream, and whitespace handling is a per-rule property (lexical vs. syntactic rules).

**Rationale.** A global lexer cannot tokenize embedded languages with conflicting delimiters —
JSON's `}` against a Nikaia block end, a Rust lifetime `'a` against a character literal. Any
host language that wants to embed foreign syntax must give up the global lexer; this is the
same conclusion `syn-grammar`'s failure forced on us in practice.

**Consequence.** Nikaia cannot later adopt a token-stream-based frontend without breaking the
`dsl` feature. This is accepted.

### D2 — DSL blocks terminate explicitly with `} eod`

```nika
let query = dsl mysql {
    SELECT name FROM users WHERE age >= :target_age
} eod
```

**Rationale.** Given D1, the core parser cannot find the end of a DSL block by counting braces
— the body is foreign syntax where `}` may be a string character, an operator, or absent
entirely. It has exactly two options: run the DSL parser to find the end, or scan for an
explicit marker. The marker is chosen because it also buys parallelism: having located the
block boundary, the core parser can skip the body and continue with the rest of the file
while the DSL parser works.

**Accepted limitation.** A DSL body containing the literal sequence `} eod` cannot be written
inline; such content must be loaded via `dsl G from "file"` instead. We consider this
acceptable for the target languages (SQL, assembly, JSON, HTML) and prefer it to a
configurable or heuristic terminator, which would reintroduce the ambiguity D1 removes.

### D3 — `dsl` is an expression; one syntax for compile time and runtime

```nika
const CONFIG: Json::Value = dsl Json from "config.json"   // compile time, build fails on error
let data = dsl Json from user_input                       // runtime, throws ParseError
let query = dsl mysql { … } eod                           // inline body
```

**Rationale.** 0.0.5 promised "Dual-Mode Parsing" but delivered two unrelated mechanisms:
`from … with …` for constants and a generated `Parser::parse()` method for runtime. The
promise is only real if the two modes share a syntax. Which mode applies follows from the
context (`const` vs. `let`), not from a different spelling.

**Replaces.** `const T: X = from "f" with P` and `P::parse(input)`.

### D4 — Hybrid binding: immediate capture vs. deferred parameter

Grammar authors declare holes in the AST using two intrinsics:

* `meta::capture(id)` — **immediate**: resolved from the surrounding scope at compile time.
* `meta::parameter(name, type)` — **deferred**: a named runtime parameter.

**Rationale.** This is the RFC's sharpest observation and it survives review unchanged. Pure
scope binding is correct for assembly, where `$v = in(reg) val` must refer to *this* `val`
here and now. It is actively wrong for SQL prepared statements: baking the values into the
statement definition destroys the reuse that makes a prepared statement worth having. One
mechanism cannot serve both; two must be named.

**Cross-cutting note.** This is the same immediate/deferred axis the language already uses for
lambda capture (`@immediate` / `@detached`, Part I 5.4) and for resource teardown
(`task::scope` vs. parked cleanup, [ADR-006](adr-006.md) D3). Three independent design tracks
landed on it. It is recorded as a language principle in Part II, 10.5.

### D5 — Shadow types and the typed spread `...args: Self::dsl`

A DSL block containing `meta::parameter` causes the compiler to generate a **shadow type**
carrying the signature of the parameters found:

```nika
// dsl mysql { … :id … :active } eod   ==>   SqlAst[Signature = {id: i32, active: bool}]

impl SqlParser {
    pub fn execute(self; ...args: Self::dsl) -> Result[Row] { … }
}

stm.execute(; target_id: 501)
```

DSL parameters are **Configuration**, so they are named arguments after the `;` — the
Subject `;` Config protocol (Part I, 5.1) applies to metaprogramming without exception.
The `args` struct is monomorphized per DSL string and stack-allocated.

**Rationale.** Without a generated type, the compiler cannot check that every `:name` in the
DSL body is supplied at the call site, which is the entire safety argument for embedding SQL
instead of writing strings.

**Risk, stated honestly.** This is the least proven decision here. It requires the compiler to
synthesize a type from content produced by a user-defined parser, which no part of the current
toolchain does. It is specified now so the grammar protocol is coherent, and flagged as the
piece most likely to need revision once implemented.

### D6 — Hardware instructions leave the language core

`unsafe asm` with its register-constraint table (`reg`, `freg`, `mem`, `imm`, `reg_or_mem`)
and `clobber` is **removed** from the language. Assembly becomes a library-provided DSL:

```nika
use std::backend::x86

dsl x86 {
    $v = in(reg) val
    $r = out(reg) result
    mov $r, $v
} eod
```

**Rationale.** Register constraints in the core couple the language to register-based CPUs.
Nikaia's Lite profile targets WebAssembly (Part III, Chapter 15), and WASM is a **stack
machine** with no registers to constrain. A core construct that cannot be given meaning on a
first-class target is a defect in the core, not in the target. As a DSL, `dsl backend::x86`
and `dsl backend::wasm` coexist, each validating its own operands.

This uses D4's immediate capture: unlike the SQL case, the assembly DSL resolves `val`,
`ptr`, and `result` from the current scope and injects machine code at the call site.

**Consequence.** The `unsafe` keyword loses its only specified use. It is retained as reserved
for future FFI work rather than removed from the grammar.

### D7 — Deferred: Auto-AST and regex terminals

Both are **specified as goals, not as current behaviour**, because the backend does not
provide them:

* **Auto-AST** — generating structs for labelled sequences and enums for alternatives when no
  `-> { … }` mapping is given. Desirable (it removes most boilerplate from a grammar), but
  `winnow-grammar` requires action blocks today.
* **Regex terminals** — the RFC proposed `regex("…")` compiled to DFAs. `winnow-grammar`
  offers fixed built-in terminals (`ident`, `string`, `float`, `hex_digit1`, …) instead. The
  *intent* — efficient terminal matching directly on the byte stream — is met; the specific
  mechanism is not adopted.

**Identifier interning** is a third deferred item, for a different reason: the backend
implements it, but the handle round-trip is off by one. `lasso::Spur` stores `index + 1`
internally, and `winnow-grammar`'s `Symbol` adds another on the way back:

```rust
pub fn from_spur(spur: Spur) -> Self { Self(spur.into_inner()) }               // index + 1
pub fn into_spur(self) -> Spur { Spur::try_from_usize(self.0.get() as usize) } // index + 2
```

So `InternerContext::resolve` returns the *next* symbol's text, or panics with
`Key out of bounds` on the most recently interned one. Reproduction: parse
`fn foo() {} fn main() {}` with a rule binding `name:ident`, then resolve the first
function's symbol — it yields `"main"`; with a single function it panics. The suggested fix is
`Spur::try_from_usize(self.0.get() as usize - 1)`, plus a test that resolves the *last*
interned symbol (`tests/interning_test.rs` upstream only compares symbols to each other, so it
passes either way).

Until that is fixed the grammar binds the non-interning `raw_ident` terminal and the AST
stores `String`. This does not change §4's design conclusion — it defers half of its
implementation.

Spec text must not promise any of the three as available.

## 3. Rejected alternatives

**Reverting `c6ff1fa` and restoring the 0.0.6 text verbatim.** Rejected. The reverted text
contains a claim now known to be wrong (see §4) and predates the backend, so it promises
features that do not exist (D7). Re-deciding costs more than reverting and produces a spec
that matches reality.

**A configurable or inferred DSL terminator.** Rejected under D2 — it reintroduces exactly the
delimiter ambiguity that scannerless parsing exists to remove.

**Keeping `unsafe asm` in the core and adding a WASM special case.** Rejected under D6. The
special case would have to be a second, register-free syntax, which is a DSL with extra steps
and a permanent fork in the language core.

**One binding mechanism instead of two.** Rejected under D4 — see the prepared-statement
argument.

## 4. Zero-copy: correcting the record (three answers, one problem)

The section on zero-copy parsing (Part II, 10.6) has now been written three times
independently. The convergence, and one error, are worth recording.

| Source | Mechanism | Verdict |
| :--- | :--- | :--- |
| RFC 0.0.6 | Parser yields slices; "the borrow checker ensures you cannot use a token after the original text has been deleted" | **Wrong** |
| ADR-005 D4 | Tethered slices: a `Shared` handle on the buffer plus offsets (the `bytes::Bytes` model) | Correct for bulk text |
| `winnow-grammar` | String interner: identifiers become `Symbol` handles into a shared arena | Correct for identifiers |

The RFC's formulation inverts the actual behaviour. The borrow checker does not *ensure* that
a stored token stays valid — it **rejects** the program, which is precisely the problem
ADR-005 exists to solve. The corrected text must state the guarantee positively: the source
buffer cannot be freed while a token points into it.

The two correct answers are complementary, not competing, and the spec adopts both with a
rule for choosing:

* **Identifiers and keywords → interned `Symbol`.** Small, highly repetitive, compared often.
  Interning deduplicates them and makes equality an integer comparison.
* **Bulk text (string literals, comments, doc text, DSL bodies) → tethered slice.** Large,
  rarely repeated, rarely compared. Interning would waste arena space; a tether costs one
  shared handle for the whole buffer.

The RFC's implementation notes (parsers compiled to direct byte-stream consumers,
context-aware SIMD for the specific embedded syntax) remain valid as non-normative
optimization avenues, consistent with ADR-005 D4's note on compiler-verified self-referential
storage.

## 5. Consequences

* Part II, Chapter 10 is rewritten for the scannerless protocol (10.1, 10.2, 10.5, 10.6, 10.7).
* Part III, Chapter 16 no longer specifies a core construct; it documents the backend DSL pattern.
* Part III, Chapter 15 (`dsl js`) and Chapter 17 (`dsl sql`) adopt `} eod` and parameter holes.
* The specification moves to **0.0.7**. The label 0.0.6 stays with the borrow and cleanup work
  ([ADR-005](adr-005.md), [ADR-006](adr-006.md)); this ADR is the grammar half that the version
  number lost.
* ADR-001 records the backend features this protocol depends on.
* Three items to raise against `winnow-grammar` upstream (it is a separate repository, so they
  are recorded here rather than tracked in this one): the `Symbol` off-by-one above, auto-AST,
  and error recovery that accumulates diagnostics instead of discarding the skipped input.
