# ADR-015: The Backend's Lazy Diagnostics — and What They Did to 1BRC

**Status:** Accepted
**Date:** September 9, 2026
**Target Version:** Nikaia 0.0.8 (bootstrap compiler)
**Supersedes:** the measurement in [ADR-014](adr-014.md) D3
**Related:** [ADR-011](adr-011.md) D4 (the driver call), [ADR-009](adr-009.md) D2 and D5,
[ADR-013](adr-013.md) D7 (where the example says what Stage 0 will not infer)

---

## 1. Context

Two things had been measured on this branch and neither had an answer inside Nikaia.

The first: on 8 million rows, `--profile lite` took 3.99 s against 0.85 s for the same program
written by hand in Rust — 4506 instructions per row against 839. The second was the reason, found
by a single experiment. A file whose temperatures are *all negative* — so that the `neg:"-"?` in
`TENTHS` succeeds instead of failing — parsed in 1.91 s rather than 3.97 s. **One failing optional
per row cost 52 % of the runtime**, and the hand-written parser, which also looks for a `-` and
also usually does not find it, paid nothing for it. The cost was not the failure; it was the
bookkeeping the parser did *about* the failure, on a path where the parse then succeeded and
nobody ever read it.

`winnow-grammar` has since done the thing that observation asks for, and this ADR records the
upgrade to it: what had to change in Nikaia, and what the numbers became.

---

## 2. Decisions

### D1 — Nikaia moves to the lazy-diagnostics backend, and adds nothing of its own.

Upstream's ADR 17: an entry point first parses with a zero-sized error type, and only *if that
fails* parses again with the diagnosing engine — for a `par_fold` rule, starting from the item the
fast pass stopped in rather than from the beginning. The mode is a field of `ParseContext`
(`Diagnose::{Replay, ReplayInPlace, Off, Eager}`) and defaults to `Replay`.

Nikaia emits no choice here. The default is right for every program the lowering produces: full
speed on the accepted path, a full message on the rejected one, and the second pass paid only by
inputs that were going to fail anyway. A `--profile` that picked a `Diagnose` would be ADR-011 D4's
line crossed — a profile that changes what a program *means*, since `Off` changes an error's
content. If a program ever needs `Off`, it is a property of that program and belongs in its source,
not in the runtime it is built for.

### D2 — Three migrations, and the one that is Nikaia's own bug.

* **`parse_<rule>_pieces` takes a context, not a factory.** `ParseContext::<()>::default` became
  `&ParseContext::<()>::default()`; the factory form is now `parse_<rule>_pieces_with`, for a
  `user_state` that must start empty in each piece rather than be cloned. Nikaia's driver has no
  user state, so it takes the simpler one. One line in the emitter (ADR-011 D4).

* **A repetition of a character class yields the text it matched.** `digit{1,2}` is `&'a str`, not
  `Vec<char>` — no allocation per item, which upstream measures as `TENTHS` 60 ns → 29 ns. The
  corpus says `for d in whole.chars()` where it said `for d in whole`, in `examples/1brc.nika` and
  in `tests/fixtures/measurements.nika`. It is ADR-013 D7's rule applied once more: the lowering is
  syntactic, so where a type changed the source says so.

* **A rule binding may not be called `input`.** The generated parser's closure takes a parameter of
  that name, and every action now ends with `let _state = &mut input.state;`. Nikaia's own grammar
  bound `input:head_expr` in `dsl_from_expr` — the one rule whose subject is, in Nikaia's own
  vocabulary, an input — and shadowed it. The binding is `source` now.

  This is Nikaia's to carry, not upstream's to fix. Every macro that hands a user's block a scope
  reserves names in it, and the alternative — hygiene for the injected binding — would make
  `_state` unreachable from the action that wants it, which is the whole point of injecting it. The
  price is that the reserved names are part of the protocol; a comment at the binding says so.

### D3 — The measurement, re-taken, and the claim it makes is a different claim.

8 million rows (105 MB) of `station;temperature`, 4 cores, release, best of five. `naive` and
`hand-tuned` are the same aggregation written directly in Rust — the second with a word-at-a-time
FxHash and one `memchr_iter` over the whole buffer.

| | wall | instructions/row |
| :--- | ---: | ---: |
| Nikaia `--profile lite` | **0.57 s** | **659** |
| Nikaia `--profile advanced` | **0.19 s** | (the same work, on 4 cores) |
| Rust, naive | 0.78 s | 840 |
| Rust, hand-tuned | 1.20 s | 688 |

Instruction counts are callgrind over 200 000 rows; the two Rust programs measure within one
instruction per row of what they measured before this upgrade, which is what makes the comparison
the same comparison.

Against the previous measurement: **lite 3.99 s → 0.57 s (7.0×), advanced 1.05 s → 0.19 s (5.5×),
4506 instructions per row → 659 (6.8×).** Output is byte-identical across both profiles and against
the naive Rust program.

And the decisive experiment, re-run: the all-negative file now takes 0.55 s against the mixed
file's 0.57 s — on 4 % more bytes, so the same speed per byte. **The 52 % is gone**, which is the
measurement that says the fix was the right fix rather than a general speed-up that happened to
help.

### D4 — What this settles, and what it does not.

A generated parser, from a grammar written down declaratively, is now **below hand-tuned Rust on
instructions per row** for this workload, and ahead of both hand-written programs on the clock
before any parallelism is switched on. That is the claim ADR-007 makes — "if it is slow, the
argument in ADR-007 is wrong" is written at the top of `1brc.nika` — and it is the first time the
measurement has supported it rather than embarrassed it.

It is not a claim about the 1BRC leaderboard. The top entries there are not parsers; they are
SWAR over raw bytes, custom hash tables sized to the key count, and no UTF-8 validation. Nikaia's
own `fs::map` validates 13 GB up front at 1358 MB/s, serially, which is ~10 s before a single row
is read. The distance to the top league is architectural and is the subject of the escape-hatch
work, not of this ADR — what changed here is that the *normal* path is no longer the thing standing
in the way.

## 3. What is still not true

* **`sync` is still unchecked** (ADR-011 §4, ADR-014 §4). Untouched by this.
* **UTF-8 validation is serial and up front.** It is the largest fixed cost left on the 1BRC path
  and it is in `nikaia-std`, not in the parser.
* **The Ir/row comparison is one workload.** 1BRC is a good stress for scannerless parsing and
  zero-copy slices and says nothing about a grammar with backtracking across long alternatives.
