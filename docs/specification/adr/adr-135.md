# ADR-135: A List Literal Is `[1, 2, 3]`, the Empty One Takes Its Type From Its First Use, and a `[` at the Start of a Line Begins a Literal

**Status:** Accepted · **Built:** no — see §5
**Date:** September 19, 2026
**Target Version:** Nikaia 0.0.18
**Related:** [ADR-060](adr-060.md) (a literal no use constrains takes the first type that holds it), [ADR-051](adr-051.md) D1 (what a reserved word costs), [ADR-098](adr-098.md) (a `let` takes one name or a flat tuple), Part I 2.2 and 4.5

## 1. Context

A list is the language's most-written container and there is no way to write
one down. `let xs = [1, 2, 3]` does not parse: the grammar has no `[` in
expression position at all, so the syntax is free and the only cost of taking
it is the two questions below. Every program in `examples/` that wants a list
builds it a `push` at a time, and `language-review.md` §3.1 calls the literal
table stakes.

Two things are the owner's rather than the compiler's.

**What `[]` is.** An empty literal carries no element type. Either it takes
one from a later use — which is [ADR-060](adr-060.md)'s rule for a number
literal applied to a container — or it is refused with a request for the type.

**What a `[` at the start of a statement means.** After an expression
statement, a line beginning `[` is either an index of what came before or a new
literal. Rust reads it as an index and needs a `;`; JavaScript reads it the
same way and is famous for it.

## 2. Decisions

### D1 — `[a, b, c]` is a list, and `[]` is an empty one.

```nika
let xs = [1, 2, 3]
let empty: Vec[i64] = []
let rows = [Row(id: 1), Row(id: 2)]
```

The elements are expressions, a trailing comma is allowed, and the type is
`Vec[T]` where `T` is what the elements agree on. A literal whose elements do
not agree on a type is refused naming the two, exactly as a `let` with an
annotation is.

### D2 — `[]` takes the type from the first use, and is refused where none exists.

This is [ADR-060](adr-060.md)'s rule one level up: a number literal with
nothing beside it is a value rather than a type, and the first use that needs
a type is what gives it one. So `let xs: Vec[i64] = []` is an `i64` list,
`let mut xs = []` followed by `xs.push(1)` is an `i64` list, and
`let xs = []` with no use at all is refused — *this empty list has no element
type; write one, or give it a first element*.

**Refused and not guessed.** A default element type would be a type nobody
wrote, and the one thing this checker may never do is claim something the
program does not say ([Part III C.4](../30-nikaia-tooling.md)).

### D3 — A `[` at the start of a line begins a literal.

An index is written on the line its receiver is on. A statement that begins
with `[` is a list literal, always, and there is no lookahead and no `;` to
write.

**An index across a line break is a shape nobody writes**, which is the whole
argument: the alternative costs every reader of every list literal a moment of
doubt, to keep working a line nobody has typed. Rust and JavaScript both chose
the other way and both have the footgun in their style guides.

## 3. Consequences

* `let xs = [1, 2, 3]` is a program, and `examples/` stops building lists a
  `push` at a time.
* One more rule about where a statement may begin, and it is a rule that
  removes a question rather than adding one.
* **What it costs:** a rule in the expression grammar, an AST node, the
  element-type agreement in the checker, D2's inference and its refusal, and
  the lowering — `vec![…]`, which is what a `Vec` already is below.

## 4. What this does not decide

* **A map literal**, `{k: v}`, which collides with a block and with a struct
  literal and is a question of its own.
* **A list comprehension**, which is a construct and not a literal.
* **A fixed-size array** distinct from a list; Part I 2.2 offers one container
  and this writes one down.

## 5. What is built

Nothing. `[` does not parse in expression position. The order of work:

1. the grammar rule and the AST node, with the trailing comma;
2. the element-type agreement and its refusal;
3. D2's inference from the first use, and the refusal where there is none;
4. the lowering, and `examples/` rewritten where a literal is what was meant.

`docs/open-work.md` carries it.
