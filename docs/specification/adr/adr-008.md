# ADR-008: Tethered Slices in User Structs (the Tether-State Lattice)

**Status:** Accepted
**Date:** September 6, 2026
**Target Version:** Nikaia 0.0.8
**Refines:** [ADR-005](adr-005.md) D4 (tethered slices), Spec Part I 6.6, Part II 10.6
**Related:** [ADR-005](adr-005.md) D3 (Borrow Contract Ledger), D8 (byte-determinism),
[ADR-007](adr-007.md) §4 (interner vs. tether), [ADR-006](adr-006.md) (`Cleanup`)
**Closes:** gap **G3** in [`examples/README.md`](../../../examples/README.md)

---

## 1. Context

ADR-005 D4 settled what happens to a slice that a *parser* yields and something *stores*:
transient = borrow, stored = tether. It did not settle what happens when the **user's own**
struct holds one. `examples/1brc.nika` is exactly that case:

```nika
pub struct Reading { name: &str, temp: i32 }        // built ~10^9 times
pub struct Summary { stations: HashMap[&str, Stats] } // ~10^4 entries
```

Writing that example exposed two problems.

**Problem 1 — the current rule is stated over the wrong event.** Part I 6.6 says a slice
"stored in a struct" is tethered, and the code comment in `1brc.nika` repeats it. Taken
literally, every `Reading` carries a `Shared` handle on the mapped file. In the Advanced
profile `Shared` is `Arc`, so a billion-row run performs a billion atomic increment/decrement
pairs on **one** refcount word shared by every worker thread — the worst possible access
pattern a parallel loop can have (a single contended cache line, `lock xadd` on every row).
The rule as written turns the flagship benchmark into a cache-coherency stress test. Yet
nothing in that program actually escapes: `data` (the `fs::map`) outlives `totals`, so the
correct lowering for *both* the `Reading` field and the `HashMap` key is a plain `&'buf str`
at zero cost. Storage is not the event that matters. **Escape** is.

**Problem 2 — the surface-syntax question.** Should Nikaia distinguish view types (`&str`)
from owned types (`String`) at all, given D1 ("no lifetime annotations, ever")? Four candidate
designs were on the table: view types + escape analysis (1); one `String` type with automatic
heap promotion on escape (2a); one `String` type with a hard error on escape (2b); explicit
region binding, `let mut stats = HashMap::new() in file_scope` (3).

This ADR decides both, and states the rule in terms the code generator can execute.

## 2. Decisions

### D1 — View types stay. `&str` in a struct field is a *view marker*, not a lifetime.

Nikaia keeps two syntactic categories: **owned** (`String`, `List[T]`, `Bytes`) and **views**
(`&str`, `&[u8]`, `&T`). A struct declaring a view field declares that it may point into
someone else's buffer. This is the whole annotation burden — a single sigil, with no region
name, no parameter, no propagation into the struct's own type. D1 of ADR-005 stays absolute:
there is still no lifetime syntax.

**Why not one type (options 2a/2b).** With a single `String` type the tether state becomes a
*hidden* type parameter that is inferred from use. Three consequences follow, and all three are
worse than the sigil:

1. The declaration no longer carries the information the diagnostic needs, so every cost and
   every error must be explained at a site remote from the declaration — the "action at a
   distance" that ADR-005 §3 rejected in-source annotations to avoid. The Ledger can *narrate*
   that chain; it cannot make it local.
2. A struct's representation becomes an emergent property of the whole program: adding one
   call site in a distant module flips `Reading`'s layout, or (2b) turns a compiling program
   into a rejected one, with no edit near either.
3. It breaks the existing spec text and every example. Not decisive on its own, but the fact
   that the 0.0.7 example authors reached for `&str` without being told to is evidence about
   what reads naturally.

### D2 — The Tether-State Lattice, solved per construction site, not per type.

Every view value has one of three internal states. The user never writes them.

| State | Representation | Cost | Chosen when |
| :--- | :--- | :--- | :--- |
| **Borrowed** | native `&'r str` (ptr, len) | zero | the solver proves every use lies inside the buffer's live range |
| **Tethered** | buffer handle + `(offset, len)` | one `Shared` handle **per container**, no allocation | the value escapes that range and the buffer is `Shared`-capable |
| **Owned** | `String` | one allocation + copy | **only** where the source says `.to_owned()` |

Order: `Borrowed ⊑ Tethered ⊑ Owned`. Inference computes the least state that makes the
program valid. This replaces "stored ⇒ tethered" with:

> **Transient = borrow. Escaping = tether. Copying = yours to ask for.**

"Escapes" means: outlives the buffer's owning scope — returned past it, captured by a
`@detached` lambda, written into a longer-lived container or a global. A struct field is *not*
an escape by itself; a struct that lives and dies inside the buffer's scope keeps native
references, which is what makes the 1BRC inner loop free.

### D3 — Uniform state per struct instance: at most three layouts per struct type.

All view fields of one struct instance share one state. A struct with *k* view fields therefore
has at most 3 layouts, not 3^k, and monomorphization over states is bounded by the lattice
height (3) rather than by field count. Owned fields declared as `String` are unaffected —
they are a different type, not a state.

The cost of uniformity is a struct that would want one borrowed and one tethered field; it is
lifted to the join (tethered). This is a pure representation choice, never an allocation, so it
cannot silently cost the user a copy.

### D4 — The refcount lives on the **container**, not on the element.

This is the decision that makes tethering affordable at 10^9 rows, and the one Problem 1 above
gets wrong today.

> When a value tethers, the `Shared` handle is taken by the **owner of the escape** — the
> struct, collection or task that outlives the buffer — not by each slice inside it.

A `HashMap[&str, Stats]` that outlives its buffer holds a small **buffer table** (a `Shared`
handle per distinct source buffer) and its keys stay `(buffer_index, offset, len)`. Where the
compiler proves a single buffer — the common case, including 1BRC's chunks, which are all
subranges of one map — the index is elided and a key is 8 bytes of offset+len. Inserting a
million keys performs **zero** refcount traffic; merging two containers merges two buffer
tables, a handful of handle clones.

Consequences worth stating explicitly:

* Handle traffic is O(containers × buffers), never O(elements). Per-element atomics, the
  failure mode described in §1, cannot occur by construction.
* This recovers what Option 3 (explicit region binding) offers — a collection bound to a
  buffer's lifetime — without a user-written region name, and it recovers it *automatically*.
* `Eq`/`Hash` on views are **content-based**, never `(buffer, range)` identity. Two chunks
  yield different offsets for `Hamburg`; a map keyed by identity would silently split
  stations across workers. In the Borrowed state hashing reads the fat pointer directly; the
  Tethered state resolves the handle once per lookup, not per byte.

### D5 — Promotion to `Owned` is never automatic. Option 2a is rejected.

ADR-005 §3 already bans compiler-inserted clones ("Nikaia never inserts a clone the user
didn't write"); this ADR confirms it for the struct case and gives the performance argument.
An implicit `.to_string()` on escape has *unbounded*, invisible cost that scales with the data
(a refactor three modules away silently converts 10^9 zero-copy slices into 10^9 mallocs) and
it can inject allocation into a `sync` body that the user believes is allocation-free — the
exact opposite of what the `sync` marker is for. A tether's cost, by contrast, is bounded by
D4 and independent of the row count.

The residual case where neither Borrowed nor Tethered applies — the buffer is not
`Shared`-capable (a stack array, an FFI pointer, a slice the caller lent us) — is a **hard
error** with a fix-it that names `.to_owned()` and the two other ways out (return the buffer
to the caller, or take the buffer by value). This is Option 2b's error, kept for the case where
it is the truth, instead of made the default rule.

### D6 — `@borrowed`: the opt-in "no tether here" assertion.

Predictability is 2b's one genuine advantage: a hard error on escape means the hot path can
never quietly change representation. Nikaia takes that advantage without the default cost:

```nika
@borrowed
pub struct Reading { name: &str, temp: i32 }
```

`@borrowed` on a struct (or a single field) asserts that this value never tethers. An escape
that would promote it is a compile error naming the escape site, the buffer, and the scope
that outlives it. It changes no semantics — it forbids a state transition — so it can be added
to a hot struct after profiling and removed without touching any other code.

The inverse tool is inspection rather than assertion: because the tether state of every field
lands in the Ledger (D7), `nikaia explain --tethers` prints the solved state of every view in
the program, and a state change shows up as a Ledger diff in review.

### D7 — Tether state is part of the Borrow Contract Ledger, and inherits D8's determinism.

ADR-005 D3 already promises the Ledger records "every tethered struct field". This ADR fixes
what is recorded: per function, the state of every view in its signature; per struct, the
solved state and the buffer-table shape. Three properties follow:

* **Determinism is free.** The state lattice is a 3-element chain and the constraints are
  monotone, so the state solver is the *same* monotone constraint system as D3's region
  solver, with the same unique least fixpoint. ADR-005 D8 (byte-deterministic ledger,
  ban list, double-build and cross-OS CI) applies unchanged; no new determinism surface.
* **Profile neutrality holds** (D8c): the state is identical under Lite and Advanced;
  only `Shared`'s expansion to `Rc`/`Arc` differs.
* **Barriers, not blowup.** Crossing a `dyn` boundary or a published non-generic API is a
  **state barrier**: the value is widened to **Tethered** — the widest representation, never
  to Owned. Separate compilation and dynamic dispatch therefore need one ABI, not one per
  state, and the D3 trait-method join rule stays sound without ever costing an allocation.

### D8 — Retention is a lint, not a silent leak.

A tether keeps the **entire** buffer alive — `bytes::Bytes`' known space-leak shape. Holding a
12-byte station name from a 13 GB map pins 13 GB. The compiler warns where a small extract
escapes a large buffer at a scope boundary (`NK`-coded lint, fix-it: `.to_owned()`), and
`fs::map`'s documentation states the rule. This is an accepted, named cost, not a surprise.

Interaction with ADR-006: a tethered container keeps the mapped file's handle alive, so its
`Cleanup` runs when the last tether dies, not at the end of the mapping scope. The `Cleanup`
diagnostic must say so when the two orders differ.

### D9 — Explicit region binding (Option 3) is rejected as the core mechanism.

`let mut stats = HashMap::new() in file_scope` is honest and predictable, but the region name
is a lifetime with a friendlier spelling: it is viral (every function touching `stats` must
name the region), it leaks buffer provenance through abstraction boundaries (the caller of a
`grammar` would have to know which scope the parser's buffer lives in), and it re-opens the
door D1 nailed shut. D4 delivers the same guarantee — a container bound to a buffer's life —
by inference. The idea is kept on the shelf in one narrower form: an explicit **arena** for
*owned* data (`List`, `String`) as a future allocator feature, which is an allocation strategy
and not a lifetime construct.

## 3. Worked check: 1BRC under these rules

| Value | Escapes? | State | Cost |
| :--- | :--- | :--- | :--- |
| `NAME` slice inside `measurement` | no | Borrowed | zero |
| `Reading.name` (≈10^9 constructions) | no — dies inside the `fold` | Borrowed | zero, **no atomics** |
| `Summary.stations` key (≈10^4) | no — `totals` dies before `data` | Borrowed | zero |
| chunk from `split_aligned` | no | Borrowed | one handle per chunk (D4), 8–128 total |
| the same `Summary` returned from `main`'s scope | yes | Tethered | one handle for the map, keys 8 bytes |

The program as written in `examples/1brc.nika` therefore allocates **nothing** per row and
performs **no** refcount traffic in the parallel section. Had the same program been written
under option 2a, the last row would have been a billion allocations, chosen silently.

## 4. Rejected alternatives

* **Option 2a (auto-promotion / silent copies)** — rejected: unbounded invisible cost, breaks
  ADR-005 §3, can allocate inside `sync`. See D5.
* **Option 2b (single type, hard error on escape)** — rejected as the *default* rule, adopted
  as the residual case (D5) and as an opt-in assertion (D6). It is implementable — whole-program
  compilation is already assumed by D3 — but as the default it (a) makes the struct's
  representation an emergent whole-program property (D1), (b) forces a branch/container join
  between tethered and owned values whose only answers are a silent copy (banned) or an error
  the user cannot act on locally, and (c) presents the user with a lifetime error in plain
  words, which is ADR-005 §3's rejected alternative #4 ("the full Rust lifetime model with
  hidden inference only") arriving through the struct door. D4 already guarantees the buffer
  outlives the tokens; there is no soundness reason left to reject the program.
* **Option 3 (explicit regions)** — rejected as core mechanism, see D9.
* **Per-element refcounts** (the naive reading of "stored ⇒ tethered") — rejected: contended
  atomics per row, see §1 and D4.
* **Unsafe self-referential codegen** — still the recorded future optimization from ADR-005
  D4, unchanged and unscheduled. D4 above reduces its value: with container-level handles the
  refcount is no longer on any hot path.

## 5. Consequences

* **Spec:** Part I 6.6 is restated over *escape* rather than *storage* and gains the lattice;
  Part II 10.6 inherits it; `@borrowed` and the retention lint enter Part III (Appendix C for
  the diagnostics).
* **Frontend:** the region solver gains a second, tiny lattice; the Ledger schema gains a state
  column and a buffer-table shape per struct.
* **Examples:** G3 is closed. `1brc.nika`'s comment on `Reading.name` was wrong in the same way
  the spec was and is corrected. G4 (line-aligned chunking) is untouched and still open.
* **Open:** the buffer table's index width and its growth policy for containers fed by many
  distinct buffers (a streaming parser over thousands of files) are unspecified; the single-buffer
  case, which is what the benchmarks exercise, is fully determined.
