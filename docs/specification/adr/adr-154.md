# ADR-154: The Prelude Is a Written List, Small and Closed

**Status:** Accepted · **Built:** no — see §5
**Date:** September 19, 2026
**Target Version:** Nikaia 0.0.31
**Related:** [ADR-140](adr-140.md) D5 (`use` brings nothing in, for `std` as
for a package — which left this open), [ADR-046](adr-046.md) (a package's
prefix at every use), [ADR-030](adr-030.md) D1 (`use std::…` names the
library), [ADR-028](adr-028.md) D5 (an entry exists because a program asked),
Part I 2.2, Part I 9.1

## 1. Context

[ADR-140](adr-140.md) D5 decided how `use` works — it brings **no** name in,
for `std` as for a package — and said in passing that `Vec`, `String` and
`HashMap` need no `use` at all, *which is the prelude and is unchanged*.

Unchanged from what, is the problem. There is no written prelude. The line is
drawn by what the compiler happens to know: `crates/nikaia-std/src/lib.rs` has
a `prelude` module, it was grown one `pub use` at a time as things were needed,
and it carries `fs`, `io`, `cli`, `html`, `task` and `HashMap` — which is to
say a program can read a file without saying so.

A prelude is a promise that is very hard to take back: every name in it is a
name some program writes without importing, and removing one breaks that
program. So the size of the list matters more than its contents.

## 2. Decisions

### D1 — The prelude is written on Part I's first page, and it is this.

* the containers a program cannot do without: **`Vec`**, **`String`**,
  **`Bytes`**;
* the printing functions: **`println`**, **`print`**, **`eprintln`**;
* **`assert`** and **`panic`**;
* the numeric conversions Part I 2.2 already offers.

And nothing else.

### D2 — Nothing in it does I/O but printing, and nothing in it pauses.

That is the rule the list is built from rather than a property it happens to
have. `fs` and `io` leave: reading a file is a thing a program should say it
does, and `use std::fs` is that sentence. It is also what makes the prelude
safe for a profile with no filesystem ([ADR-119](adr-119.md)) — the list does
not have to be cut down for one.

### D3 — `HashMap` is the first thing outside it.

It is the name that makes this a decision rather than a tidy-up: a map is
common enough to argue for, and `use std::collections` is one line, and a
prelude that grows by *common enough* has no floor. `collections::HashMap` at
the use, which is [ADR-046](adr-046.md)'s shape one library over.

### D4 — A name joins the list by a record, and never by being needed once.

Additive is the easy direction and it is the one that ends with everything in
the prelude. A name in it has to be argued for in a record of its own, with
the D2 rule as the bar.

### D5 — The emitter's own prelude is not this list.

The generated Rust imports what the **lowering** needs — `rt` so the `fn main`
the emitter writes can start the runtime, `TrustedMap` so a map has a hasher.
Those are not names a `.nika` file may write, and the two lists are allowed to
differ because they answer different questions: what the program may name, and
what the generated file needs to compile.

## 3. Consequences

* A reader can find out what needs no `use` by reading one page rather than
  one Rust file.
* A program that reads a file says so.
* The list can grow, and each name costs a record.
* **What it costs:** the page's list, `use std::…` in front of `fs`, `io`,
  `cli`, `html`, `task` and `HashMap` wherever the corpus reaches them, and the
  emitter's prelude split from the program's.

## 4. What this does not decide

* **Whether `Bytes` stays in `std`** or is a language type; it is in the list
  because a program cannot do without it, wherever it lives.
* **A per-project prelude**, which is a manifest key nobody has asked for and
  which would make one program's `Vec` another program's mystery.
* **Whether the prelude differs by target.** D2's rule is what makes it not
  have to.

## 5. What is built

Nothing, and the gap between the list above and what the compiler does is the
work: `crates/nikaia-std/src/lib.rs`'s `prelude` carries `fs`, `io`, `cli`,
`html`, `task`, `ListExt`, `Full`, `digit_value` and `HashMap`, every one of
them reachable from a `.nika` file with no `use`.

**The corpus is what this costs**, and it is the number to measure before the
change rather than after: every `fs::`, `io::`, `cli::`, `html::` and
`HashMap` in `examples/` needs the `use` line it never needed, and the
specification's blocks with it.

The order of work:

1. D1's list on Part I's first page, so the promise is written before it is
   enforced;
2. the Nikaia-level prelude separated from the emitter's (D5), which is the
   piece that does not exist at all today — there is one list and it serves
   both;
3. the names outside the list refused without a `use`, which is `NK1117` with
   a help that names the line to add;
4. the corpus and the pages.

`docs/open-work.md` carries it.
