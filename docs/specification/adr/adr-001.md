# ADR-001: One Pinned Nightly, and a Scannerless Generated Parser

**Status:** Accepted, except §4 · **Built:** yes
**Narrowed in part by:** D5 below — stable is the toolchain, and D1's pin is the
Bridge-IR backend's alone
**Superseded in part by:** [ADR-003](adr-003.md) — the frontend no longer links
`rustc` internals; see §4
**Related:** [ADR-005](adr-005.md) D2 and D9 (D2 would have needed D1 to pass
`-Zpolonius=next`; D9 decides against the flag),
[ADR-004](adr-004.md) (the bridge backend, which is what D1 is paid for),
[ADR-007](adr-007.md) (builds the grammar protocol on D2),
[ADR-021](adr-021.md) D2 (hashes D1's toolchain into the cache key)

## 1. Context

Nikaia compiles through the Rust toolchain and hosts foreign syntax inside its
own (`dsl`, `grammar`). Both choices constrain the toolchain before any language
feature is designed: the first pins *which* compiler, the second rules out any
parser that starts from Rust's own lexer.

## 2. Decisions

### D1 — Every release pins one exact nightly `rustc`.

> **Narrowed by D5.** What still stands: a nightly that *is* used is pinned
> exactly, by one file that nothing repeats. What D5 takes away is the scope —
> the pin is the Bridge-IR backend's, and the toolchain a clone builds with is
> stable.

`rust-toolchain.toml` names the build; it is the single source of truth and the
channel is never repeated elsewhere.

This is what makes an otherwise reckless dependency legitimate. Nikaia may rely
on `-Z` flags and on `rustc_private` because it is tested against exactly one
snapshot and ships as a unit with it — a moving nightly would make both
unsupportable.

**Measured, and only one of those two is real.** The workspace contains exactly
two `#![feature(…)]` attributes and both are `rustc_private`
(`crates/rustc-executor`, and `crates/nikaia/src/main.rs` so the binary links the
same dylib set); **no `-Z` flag is passed anywhere in a build**. The one `-Z` that
was in the tree was `-Zls=root` in a *test helper* reading rlib metadata, and it
is gone. The Rust that Stage 0 emits uses no unstable feature at all. So the pin
is paid for by one thing: [ADR-004](adr-004.md)'s bridge backend, which links
`rustc_ast`.

**And the price, separated into the compiler's and the user's, because they are
not the same.** On a fresh `RUSTUP_HOME`, median of three: the four components
`rust-toolchain.toml` names install in **24.7 s and weigh 1 420 MiB**, against
**12.3 s and 602 MiB** for a stable toolchain with `rustfmt` and `clippy` —
+12.4 s and +818 MiB, of which `rustc-dev` is 654 MB (41 MB of it rustc's own
sources, which nothing here reads). That is what *building* the compiler costs.
What **running** a `.nika` file costs is 577 MiB of minimal stable against
579 MiB of minimal pinned nightly: two megabytes. The pin's real cost to a user
is not size but identity — a bridge-enabled `nikaia` links
`librustc_driver-<hash>.so` by **absolute runpath**, so it runs only beside that
one nightly installed where the build machine had it, while a compiler built
`--no-default-features` links libc and nothing else. A stable-only installation
is therefore possible, is built and tested in CI, and is the whole compiler minus
the bridge backend. Method, machine and variance in
[`docs/nightly-cost.md`](../../nightly-cost.md).

### D2 — The parser is generated from a grammar, over bytes, not over Rust tokens.

`winnow-grammar` compiles an EBNF-like grammar into `winnow` combinators at
compile time, and parses `&str`/`&[u8]` directly.

The alternative was `syn-grammar`, which parses a Rust `TokenStream` and so
inherits Rust's lexer. That is disqualifying three times over: syntax that is
not a valid Rust token sequence cannot be expressed at all; an embedded SQL or
assembly block would have to survive Rust tokenization before the grammar saw
it, which makes hosting a foreign DSL impossible; and trivia is discarded before
the grammar runs, which rules out a formatter or an LSP.

Parsing raw text makes the toolchain **scannerless**. [ADR-007](adr-007.md)
promotes that from an implementation detail to a language guarantee.

The features that guarantee rests on:

| Feature | What it carries |
| :--- | :--- |
| `&str`/`&[u8]` input, lexical vs. syntactic rules | scannerless parsing; whitespace control without a separate lexer |
| cut operator (`=>`) | commit points — an error instead of silent backtracking |
| span binding (`@`) over `LocatingSlice` | source positions, and so [ADR-012](adr-012.md)'s diagnostics |
| `fold(rule, init, step)` | an entry rule that reduces instead of collecting, so a large input parses in constant space ([ADR-009](adr-009.md)) |
| string interner (`Symbol`) | identifiers with cheap equality and one copy per spelling |
| its own `ParseError` with a rule stack | the diagnostics contract, Part III Appendix C |
| `recover(rule, sync)` | fault-tolerant parsing for tooling |

Not provided, and deferred in [ADR-007](adr-007.md) D7: auto-generated AST types
and regex terminals.

### D3 — `winnow-grammar` is pinned by git revision, and moves together with `winnow`.

Pinned in `Cargo.lock`, not by semver. The pin and the workspace `winnow`
version are advanced in one step: the crate tracks `winnow` closely, and its
diagnostics engine replaced `winnow::error::ContextError` with its own
`ParseError` — a breaking change for anything that matches on error text.

### D4 — The build is staged, and Stage 0 is a transpiler.

1. **Stage 0** — the bootstrap compiler, written in Rust.
2. **Stage 1** — self-hosting: Nikaia compiling Nikaia.
3. **Stage 2** — verification: Stage 1 compiling itself.

Stage 2 must handle the standard library and user code. That Stage 0 emits
source rather than machine code is relied on by [ADR-011](adr-011.md),
[ADR-012](adr-012.md) and [ADR-014](adr-014.md).

### D5 — Stable is the toolchain. The pinned nightly is the Bridge-IR backend's alone.

**Narrows D1.** D1 pinned a nightly for the whole of Nikaia and justified it with
two things — `-Z` flags and `rustc_private`. Neither premise survives. **No `-Z`
flag is passed in any build**; the last one in the tree was `-Zls=root` in a test
helper and it is gone. And `rustc_private` occurs in exactly two
`#![feature(…)]` attributes, both reachable only through `nikaia`'s
`rustc-backend` feature, so `cargo build -p nikaia --no-default-features`
produces a whole compiler on **stable**, with the corpus green through its test
suite at `dev` and at `release`. The Rust that Stage 0 emits uses no unstable
feature at all.

So `rust-toolchain.toml` names **stable**, and a clone builds, tests and lints
there; that is the leg CI requires to be green. What the nightly is now is one
optional backend's dependency — needed to *build* [ADR-004](adr-004.md)'s
bridge, and needed again to *run* a binary built with it, because such a binary
links `librustc_driver-<hash>.so` by absolute runpath and is therefore not
relocatable. A compiler without the bridge links `libc` and nothing else.

**What D1 keeps: a nightly that is used is pinned exactly, and exactly one place
says which.** That place is `bridge-toolchain/rust-toolchain.toml`. It is a
second real toolchain file in a directory of its own rather than a channel
written into a script, for the reason D1 gave in the first place: rustup's own
file is the only form that states the channel **and** the components in one
place, and a nightly without `rustc-dev` is not the thing the bridge needs.
`rustup show` run in that directory installs exactly what the file names — the
mechanism CI already used for the root file — and
`scripts/bridge-toolchain.sh` runs a cargo command on that toolchain against the
workspace at the root. Nothing else in the repository, CI included, spells a
nightly.

**The nightly leg stays in CI, and D1 is why.** `rustc_private` has no stability
promise and moves with the compiler ([ADR-003](adr-003.md) §1), so a bridge
backend that is not built against its pin is a bridge backend that rots. One
release is still one toolchain (§3): that channel and this compiler advance in
one step.

The cost and the price of the pin are measured in D1's own paragraph; method,
machine and variance in [`docs/nightly-cost.md`](../../nightly-cost.md).

## 3. Consequences

A release is a toolchain, not a crate: the compiler, the pinned nightly and the
pinned parser backend are one artifact. Advancing any of them is a release-sized
change, and [ADR-021](adr-021.md) makes that observable by hashing the toolchain
into the build-cache key.

## 4. History — what ADR-003 replaced

This record originally specified the **Rustc Driver Pattern**: the frontend
lowering Nikaia straight to a Rust `TokenStream` and injecting it into a
hijacked `rustc_driver`, with `nikaiac::driver` linking the compiler internals.

[ADR-003](adr-003.md) reversed that. The frontend emits **Bridge-IR** and an
orchestrator owns the `rustc` side; the lowering as actually built is
[ADR-011](adr-011.md). The motivation survived the mechanism — generated code
must reach the backend before macro expansion, a build switch must set backend
flags, and an error must be reported on the `.nika` line — and each is met
elsewhere now ([ADR-004](adr-004.md), [ADR-012](adr-012.md)).

D1 to D5 were never about that coupling and are unaffected.
