# ADR-014: Nikaia in Nikaia's `std` — and the Two Claims 1BRC Now Keeps

**Status:** Accepted
**Date:** September 7, 2026
**Target Version:** Nikaia 0.0.8 (bootstrap compiler)
**Closes:** [ADR-013](adr-013.md) §4, first two items (`fs::map` reads; the pieces run in
sequence)
**Opens:** the road to the roadmap's last line, "Self-Hosting: the compiler compiles itself"
**Related:** [ADR-001](adr-001.md) (Stage 0 is a transpiler), [ADR-009](adr-009.md) D3 and D7,
[ADR-013](adr-013.md) D1 (`std` is a crate)

---

## 1. Context

ADR-013 made `examples/1brc.nika` run and named two things it still did not do: `fs::map` read
the file rather than mapping it, and `Parallelism::Auto` cut the input and merged the pieces but
parsed them one after another. Both were dependency decisions, not compiler ones, and both are
closed here.

The third question this ADR answers was asked directly: *can more of Nikaia be written in
Nikaia?* The answer is yes, in a specific and bounded way, and the way matters more than the
amount.

---

## 2. Decisions

### D1 — Parts of `nikaia-std` are `.nika` files, compiled by Stage 0 when the crate is built.

`crates/nikaia-std/build.rs` runs every `src/*.nika` through the compiler library — parse, lower —
and writes the Rust to `OUT_DIR`; `lib.rs` includes it as a module of the same name. The first
such file is `src/text.nika`:

```nika
pub fn digit_value(c: char) -> i32 {
    return c as i32 - 48
}
```

Small, and the point is not its size. It is the first code the project itself runs on that the
Nikaia compiler produced — `examples/1brc.nika` calls it in every measurement it parses — and it
establishes the mechanism by which the share grows: **what a `.nika` file in `std` can contain
is exactly what Stage 0 can lower, and each construct the compiler learns is a function that can
move.** `list.rs` (a trait with a generic method) moves when traits and generics are lowered;
`cli.rs` when `std::env` is reachable. `fs.rs` does not move: it is `unsafe` around a memory
mapping, and that is the layer a self-hosted language still writes in the host — it is what
"hardware instructions as libraries" (Spec 0.0.7) means at the bottom of the stack.

**The compiler is a build dependency without its backend.** `nikaia` gained a `rustc-backend`
feature (default on) that owns the `rustc_private` half — the binary and the Bridge IR executor.
The library alone is what `nikaia-std` builds against, with `default-features = false`: a build
script that had to link `rustc_driver` would be neither quick nor portable, and nothing about
turning `digit_value` into Rust needs it. The dev-dependency cycle this creates (`nikaia`'s tests
link `nikaia-std`, whose build script links `nikaia`'s library) is one cargo permits and resolver
2 keeps the features of apart.

### D2 — `fs::map` is a memory mapping.

`memmap2`, read-only, validated as UTF-8 once when the map is made; after that a view of the text
is a view of the pages, and the `unsafe` that says so is a comment pointing at the validation. A
zero-length file cannot be mapped and is an empty input rather than an error. ADR-009 D7's
allowance — leave a large read-only mapping to the OS at process exit — is still not taken; the
mapping is released on drop, which is what `main` returning costs.

### D3 — The parallel driver runs the pieces in parallel.

`winnow-grammar`'s `rayon` feature is enabled on the **workspace** dependency rather than on
`nikaia-std` alone, for a reason that is about builds rather than semantics: cargo would otherwise
hold two differently-featured copies of the crate, and the tests that compile emitted programs
against the deps directory would have to know which one the runtime meant. One declaration, one
copy, every consumer.

The measure, 8 million lines (105 MB) of `station;temperature`, 4 cores, release, best of three:

| Profile | `Parallelism` | wall | user |
| :--- | :--- | ---: | ---: |
| `--profile lite` | `Off` | 3.99 s | 3.99 s |
| `--profile advanced` | `Auto` | 1.05 s | 3.90 s |

Identical output, byte for byte — which is ADR-009 D2's whole claim ("chunk count does not change
results") measured rather than asserted. The user time is the same in both; the wall time divides
by the cores. That is what a frame plus a monoid buys, and nothing in the program says how.

### D4 — The tests read which rlibs belong together from the crate metadata, not from timestamps.

A consequence of D1 worth recording. The build-dependency graph builds the parser backend a
second time under cargo's build-override profile, so a deps directory holds two `winnow` rlibs
that do not link together, and "the newest file" is a coin toss. `rustc -Z ls` prints an rlib's
dependencies as `name-hash`, the hash being the one in the file name; the tests anchor on
`nikaia_std`, read `winnow_grammar` from it and `winnow` from that, and hand rustc one consistent
set. `crates/nikaia/tests/common/mod.rs` is the whole of it, and it is why `nikaia-std` now
declares `winnow-grammar` as a dependency: the runtime and the parser it runs on are one
dependency, and the chain has somewhere to start.

---

## 3. What this makes of the corpus

`examples/1brc.nika` now does everything its comments claim: maps the file, parses it on every
core, and the two caveats in its header are gone. `crates/nikaia/tests/one_brc.rs` still checks it
on the real file; the timing above is not a test, because a test that asserts a speed-up is a
test that fails on a loaded CI runner — the *identical output* across profiles is asserted, the
speed-up is measured here.

---

## 4. What is still not true

* **`sync` is still unchecked.** The parallel section of 1BRC contains no pause because its author
  put none there, not because the compiler looked (ADR-011 §4).
* **The pool is rayon's global one**, sized by rayon's default (the core count). ADR-009 D3 keeps
  the cut and merge public for a pool of Nikaia's own; that is the runtime-integration line of the
  roadmap and not this.
* **One Nikaia file in `std`.** The mechanism is the point; the share is one function. It grows
  by the compiler growing, and D1 says which file moves when.
* **The compiler is not written in Nikaia.** Self-hosting is the roadmap's last line, and this is
  its first: a `.nika` file the toolchain depends on. The distance from here to "the compiler
  compiles itself" is the whole language — traits, generics, enums with data, `match` — and no
  part of it is made shorter by pretending otherwise.
