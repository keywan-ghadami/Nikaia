# ADR-083: A Field of a Borrowed Subject May Not Be Handed Out by Value

**Status:** Accepted · **Built:** yes — see §6
**Date:** September 15, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-064](adr-064.md) D2 (*a hull you can see is one you write* —
the sentence that rules out the other option), [ADR-005](adr-005.md) D7 (an
error explains itself in plain language), [ADR-081](adr-081.md) (which uncovered
this by taking a concatenation off the same line)

## 1. Context

```nika
impl User {
    fn name_of(&self) -> String {
        return self.username
    }
}
```

```text
error[E0507]: cannot move out of `self.username` which is behind a shared
              reference
```

about a file nobody wrote. That is every accessor over a field that is not a
number: `&self` is what [Part I 4.2](../10-nikaia-light.md) writes for a method
that only reads, and a `String`, a `Vec` or a struct this program declares is
moved rather than copied in the language below.

**Measured as a class**, because the instance is never the point. A field of a
borrowed subject leaks in exactly three positions, and three others work:

| | |
|---|---|
| `return self.name` | `E0507` |
| `let x = self.name` | `E0507` |
| `takes(self.name)` | `E0507` |
| `return self.count`, an `i64` | compiles |
| `return self.name.clone()` | compiles |
| `return self.name` from `fn m(self)` | compiles |

*Found by* running Part I 4.7's own `impl Summarize for User` once
[ADR-081](adr-081.md) had taken the concatenation off that line. Two defects were
standing on one sentence and the second only became visible when the first was
gone.

## 2. Decisions

### D1 — It is refused here, in this language's words. `NK1131`.

**Part I 6.8 decides this and it decides it already:**

> Ownership rules occasionally reject code — usually because the code contains a
> genuine bug. […] every such error explains itself in plain language and tells
> you what to do next. You never need Rust knowledge to read a Nikaia error; **if
> a raw internal (Rust) error ever reaches you, that is a Nikaia bug.**

So the page does not ask whether this program should be rejected — it says
ownership rules do that — and it says where the rejection has to come from. Both
halves were being broken at once.

### D2 — Not a `.clone()` the emitter writes.

That was the other option and it is against a decision already made.
[ADR-064](adr-064.md) D2 wrote *a hull you can see is one you write*, and a copy
the author cannot see is the same thing one position over: it would put an
allocation in the program's hot path that nothing in the source accounts for, in
a chapter whose whole argument is that a value's cost is visible.

**And it would buy nothing**, because the working program already exists and is
one word away. Both ways out are in the message: `.clone()`, written where it
happens, or a `self` receiver where the method is meant to consume its subject.

### D3 — Asked only where the field's type is known and does not copy.

A number, a `bool`, a `char` and any **view** are copied rather than moved, so
handing one out takes nothing away. A field this compiler cannot type says
nothing at all, which is [Part III C.4](../30-nikaia-tooling.md)'s polarity: a
refusal that fires where it should not is worse than the leak it replaces.

The rule therefore reads the **field's type** rather than counting `&self`s, and
the positions are the three that were measured rather than every place an
expression can stand. A position missed leaves today's behaviour, which is no
worse than before; a position wrongly included breaks a program that works.

## 3. Consequences

**Every accessor now gets an answer in this language.** The message names the
field, what was done with it, the type that made it a move, and both ways out.

**Part I 4.7 still cannot write its own sentence**, and that is now visible
rather than hidden: `return "User: " + self.username` type-checks since
[ADR-081](adr-081.md) and is refused by this, correctly. The page keeps the
interpolated form, which borrows.

**Reading a field is not taking it**, and that is the property the polarity
rests on: `self.name.to_uppercase()`, `self.name.len()` and `f"{self.name}"` all
borrow and all still work.

## 4. What this does not decide

* **Whether an accessor should be able to hand back a view.**
  `fn name_of(&self) -> &str { return self.username }` is the shape every other
  language in this family writes, and it is refused twice today — `NK1104` here,
  because a `String` is not a `&str`, and `E0106` below, because the lowering
  names no lifetime. So the language has views and no way to hand one out of a
  field. That is the natural third way out of `NK1131` and it is a record of its
  own.
* **The other positions a move can happen in.** A struct literal's field, an
  assignment's right-hand side and a `throw` are not read here. Each is a
  position to add when it is measured, and D3's polarity says an unmeasured one
  stays out.
* **What `.clone()` does to a value that is not text.** `String::clone` and
  `str::clone` are written down here, because §5 says why they had to be; a
  `Vec`'s and a declared struct's are not, so the help text names a method the
  ledger describes only for the type it was measured on.

## 5. What the recommended way out cost

**A message that names a way out has to be a way out**, and this one was not.
`.clone()` had no ledger entry, so `sync::infer` could not vouch for the call:
the method around it came out as one that **pauses**, and
[ADR-080](adr-080.md)'s `NK1129` then refused it for disagreeing with its trait.
Take `NK1131`'s advice and a different diagnostic fires.

Found by the trait tests' own fixture, which was the first program to take the
advice — and which had itself been writing `return self.name` out of a `&self`
method, a program that never compiled. Two things in one: the new refusal caught
a test that was measuring the wrong thing, and the fix it recommended was
incomplete. `String::clone` and `str::clone` are in `std.contracts` now.

## 6. What is built

`Checker::borrowing_self`, set per method from the receiver;
`Checker::a_field_of_a_borrowed_subject` and the `copies` predicate beside
`is_text`; the four call sites — a `return`, a `let`, a method's argument and a
free call's, the last of which needed its own because a free call walks its
arguments rather than going through `arguments_given`. Exercised by six programs
in `crates/nikaia/tests/borrowed_subject.rs`, four of them run, and most of them
about the direction that must **not** fire.
