# ADR-138: `throw`, `return`, `break` and `continue` Are Expressions of the Never Type

**Status:** Accepted · **Built:** no — see §5
**Date:** September 19, 2026
**Target Version:** Nikaia 0.0.18
**Related:** [ADR-093](adr-093.md) (a function that never returns, and the never type), [ADR-084](adr-084.md) D3 (a statement after a `break`), [ADR-025](adr-025.md) D2 (a failure leaves without a sigil), Part I 3.1, 3.4 and 7.1

## 1. Context

`=> throw NotFound` is a parse error. So is `?? throw Missing` and an `else`
branch that is one `return`. Each has to be written with braces —
`=> { throw NotFound }` — and the braces say nothing: there is no second
statement they are holding together and no value they are producing.

The four words are statements in the grammar. [ADR-093](adr-093.md) already
gives the language the type they would have as expressions — the **never**
type, which a function that never returns has — so the type side of the
question is answered and what is left is the grammar and one ruling.

## 2. Decisions

### D1 — The four are expressions, and their type is never.

```nika
let user = find(id) ?? throw NotFound(id)

let grade = match score {
    90..100 => "A",
    else => throw OutOfRange(score),
}

fn first(xs: Vec[i64]) -> i64 {
    for x in xs { return x }
    throw Empty
}
```

A `throw`, a `return`, a `break` and a `continue` may stand wherever an
expression may. Their type is never, so they fit **every** expected type
without widening anything: an arm that throws sits beside an arm that hands
back a `&str` and the `match` is a `&str`, because the arm that throws hands
back nothing at all.

### D2 — Nothing about what they *do* changes.

A `throw` still leaves the function and still makes it `throws`
([ADR-025](adr-025.md) D2); a `return` still returns; a `break` and a
`continue` still need a loop and still may not cross a function boundary
([ADR-084](adr-084.md) D4). The statement forms keep working, because a
statement whose expression is one of these is exactly what they were.

### D3 — `NK1133` is unchanged and is the reason this is safe.

A statement after a `break` or a `continue` in the same block is already
refused ([ADR-084](adr-084.md) D3), and that rule is what keeps D1 from
turning `break x` into a quiet dropped value: the shape it was written for is
still refused, one position over.

## 3. Consequences

* `=> throw NotFound` is what the specification's own error chapter writes,
  and the braces that are there to satisfy the grammar come off.
* A `??` may end in a `throw`, which is the shape *a value or a failure* is
  written in everywhere.
* **What it costs:** four alternatives in the expression grammar, a never type
  that fits everything in the checker, and the statement forms kept.

## 4. What this does not decide

* **`break` carrying a value.** Rust's `break x` hands a value out of a
  `loop`; this language has no unconditional loop ([ADR-070](adr-070.md)) and
  no value for one to carry, and `NK1133` refuses the shape.
* **A `never` a program can write** in a declaration. [ADR-093](adr-093.md)
  leaves that open and this does not reopen it.

## 5. What is built

Nothing; the four are statements. The order of work:

1. the four as expression alternatives, with the statement forms kept;
2. the never type fitting every expected type in the checker, and a
   `match` whose arms are a value and a `throw` typed by the value;
3. the specification's error chapter and `examples/` written without the
   braces, and a test per position — an arm, a `??` right side, an `else`.

`docs/open-work.md` carries it.
