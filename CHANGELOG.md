## [Unreleased]

### Added (four themes on the documentation site, and Nikaia code that is coloured like Nikaia)

- **The site offers System, Light, Dark and Sepia, and remembers which.** The control is in `_layouts/default.html` and the palettes are in `assets/css/nikaia.css` — one block of custom properties per theme, and below it the list of places a palette reaches, written once each. `jekyll-theme-primer` states its colours as literals, so a second theme could not be a variable swap inside the theme; it is a second stylesheet that names the theme's own places and reads their colour from a property. System is the *absence* of an attribute on `<html>` rather than a value of it, which is what makes a reader who has never touched the control, a reader with no JavaScript, and a reader who chooses System land in the same state. A stored choice is restored inline in the `<head>`, before the first paint, so a reader who chose Dark on a Light system does not see the white page first.

- **Sepia is there because of what this site is:** three specification parts and thirty-nine decision records, read end to end rather than searched. It is a light theme with the white taken out, and it reuses the light token colours rather than carrying a third set — which is only possible because the code block's background is taken off the block and given back from the palette.

- **The 180 ```` ```nika ```` blocks are highlighted from `editors/vscode/syntaxes/nikaia.tmLanguage.json`.** Jekyll highlights with Rouge, Rouge has no lexer for Nikaia, and the consequence was on every page of the specification: the Rust and TOML beside a Nikaia block were coloured and the Nikaia was not. What was missing was never a grammar — that one exists, and `editors/test/` has tested it against `vscode-textmate` all along — but somewhere to apply it outside an editor. `scripts/site-highlight/highlight.mjs` runs Shiki, which tokenizes with the same library, over `_site` after Jekyll and before the upload. What VS Code shows and what the site shows now come from one file and cannot drift apart.

- **Every block, not just the Nikaia ones.** 279 of them on 52 pages — 181 tokenized as Nikaia, the 180 ```` ```nika ```` fences and the one ```` ```nikaia ```` — and the `rust`, `toml`, `sh`, `bash`, `markdown` and `text` blocks too, so that one mechanism carries the reader's theme and no block is left on Rouge's fixed light colours. A fence naming a language Shiki does not know is set as plain text rather than failing. Both themes are written onto each token as custom properties with no literal `color`, because an inline colour outranks every selector in the stylesheet — that one decision is what keeps `nikaia.css` free of `!important` and lets the picker recolour code without a second copy of the page.

- **It asserts the shape it depends on instead of assuming it.** The input is generated HTML in two shapes — the wrapped form Rouge produces and the bare `<pre><code class="language-nika">` it produces for a language it cannot read — and the script fails the build if any `<pre>` reaches the end unconverted, rather than publishing a page where one block is themed and the next is not. That check earned itself immediately: it caught the block in `docs/technical_notes.md` that sits inside a list item, where Kramdown indents the wrappers and the two `</div>` are not adjacent.

- Verified by building the site the way `pages.yml` does and driving it in Chromium: all four themes, `prefers-color-scheme` in both states with no stored choice, the choice surviving a reload and a navigation, and the narrow-viewport layout where the control stops being fixed and becomes the first thing on the page.

### Assessed (what a full answer to a stored view would have to track, and what a half-built one does)

- **[`docs/stored-views.md`](docs/stored-views.md): an assessment, and it decides nothing.** What is built refuses a stored naked view or writes the subject's buffer out; the full rule is [ADR-008](docs/specification/adr/adr-008.md) D2's lattice, under which a stored view is neither an error nor a signature change but a **representation** change — the buffer takes a handle, the view becomes an offset and a length, and nothing is refused at all. The note asks what stands between the two, item by item.

- **Of the seven things it would need, two are present, one is computed and thrown away, and four are not.** Present: which fields of a type hold a view, and which parameters a result may point into — the latter from the *signature* only, so `borrows(a | b)` says nothing about which one. Computed and discarded: the checker infers a type for every `let` and `Checked` exports only findings, loops and method calls; the channel for handing one more answer to the emitter already exists. Absent: which parameter of a `std` call keeps what it is given, a buffer variable per view position, a solver over them, and any representation other than a native reference.

- **The decisive limit is that there is one buffer to name.** `crates/nikaia/src/emit/mod.rs` has a single `INPUT_LIFETIME`, and `contracts/trust.rs` already states the consequence in its own header. An analysis that proved a view came from a *different* buffer than its destination's would have nothing to emit, so it could only refuse — which is what the increment above already does for every destination it cannot name.

- **A half-built version was built and measured, which is why the note has a recommendation rather than a hunch.** The obvious next step — letting a local whose declared type holds a view be a destination — refuses `examples/k-nucleotide.nika`: 32 files lower instead of 33. That program writes views of its parameter into a map it hands back and is correct, because the container's buffer *is* the parameter's, and what says so is the `return`. No amount of following where the view goes answers that; equating two buffer variables does. So widening the reach before the solver exists converts working programs into refusals, and the order is forced. The probe was reverted and the corpus is back to 33/22.

- **Also recorded there, because it is a different defect and was left alone:** a free function taking a view-holding struct by value and handing one back fails with `E0106` whether or not the view is stored — the naked view is not what breaks it, so `NK2302` would be the wrong code to report. Nothing in the corpus writes the shape.

- No new ADR, no decision, and no change to any program: this entry is a note and a `docs/README.md` line.

### Changed (where the destination already names a buffer, the view is lowered instead of refused)

- **One step further along the same question, not a second mechanism.** `NK2302` asks where a naked view parameter's view goes. A **field** is declared, and its declaration says which buffer it points into ([ADR-008](docs/specification/adr/adr-008.md) D1) — so where the destination is a field of a subject that itself holds a view, the buffer is already named and the parameter is lowered as a view *of that buffer* rather than refused. `fn record(&mut self, name: &str, temp: i32)` on a `Summary` holding `HashMap[&str, Stats]` now emits `fn record(&mut self, name: &'a str, temp: i32)`, which compiles and runs — it is the program the `E0621` above was about. Part I 6.6's `Status` note and Appendix C.3's row say which cases are which.

- **The cost of the fail-closed direction is now a narrower signature rather than a refusal.** `self.names.contains_key(name)` was refused in the entry above, because nothing written down tells a call that keeps what it is given from one that does not. It lowers now, with `name` written as a view of the subject's buffer — the undecided case is still decided the safe way, and what the safe way costs is what a caller may pass instead of whether the program builds. `NK2302` therefore refuses no program the language below accepts.

- **Measured both ways on the corpus, which is the only reason this is here and not reasoned about.** Nothing that lowered before is refused now: 33 lower and 22 do not, the same files as before, and **the emitted Rust is byte-identical for all 33** — no program in the repository has the shape, so the change costs the corpus nothing in either direction. Nothing that was refused before lowers now either, for the same reason. The direction is shown on four programs in `crates/nikaia/tests/stored_views.rs` instead, each **compiled with the `rustc` that built the test and run**: the stored-into-a-field form, the stored-through-an-opaque-call form, the read-only call the entry above refused, and the one that reaches the field through a local. Reading the emitted text would not have caught this defect, because what the old behaviour produced was text that looked right.

- **Where the reach stops, as three tests rather than three sentences.** A function or method whose own subject holds no view still refuses, even when the destination is a field of a struct that carries one — there is no buffer in hand to write. A view handed back through the result still refuses: covering it means writing the result's buffer too, which is a second edit to the signature. A view given to a task still refuses. The caller side is unchecked: writing the subject's buffer on a parameter narrows what callers may pass, and nothing in the corpus hands such a method a shorter-lived view.

- **`cargo test --workspace` 532 passed, 0 failed** (529 before, 3 added and 2 converted from refusals to lowerings); `cargo fmt --all --check` clean; `cargo clippy --all-targets -- -D warnings` clean; `scripts/check-adr-refs.py` exit 0. `nikaia.contracts` is unchanged: the ledger records Nikaia signatures, and `&str` is still what the source says. No new ADR.

### Fixed (a view kept past its call is refused in Nikaia, not in the generated Rust)

- **A function taking a naked `&str` and storing it lowered to Rust that `rustc` refused with `E0621`, naming the generated file** — which Part III C.1 calls a bug in this compiler rather than in the program. `fn record(&mut self, name: &str, temp: i32)` on a `Summary` holding `HashMap[&str, Stats]` emitted `fn record(&mut self, name: &str, …)` inside `impl<'a> Summary<'a>`, and the reader was told `help: add explicit lifetime 'a to the type of name` — every noun of which is something [ADR-008](docs/specification/adr/adr-008.md) D1 says the author never writes. The 0.0.9 entry below recorded this as D7's open half and said closing it needs ADR-008 D2's tether lattice; what it actually needed first was for Nikaia to have an answer of its own, and `NK2302` is that answer. The struct form — `fn record(&mut self, m: Reading)`, which `examples/1brc.nika` has used all along — was never broken, and is what the message shows.

- **`NK2302` (Part III, C.3; the rule is Part I 6.6).** `crates/nikaia/src/views.rs` asks, per naked view parameter, where its view goes, and reports four destinations: a field reached from `self` whose declared type holds a view, a field of a struct the function builds, the result where the result holds a view of a buffer that is not this parameter's, and a task's body. One refusal per parameter, at the place that says the most about where the view went.

- **It is wider than the rule, and that is the polarity rather than an oversight.** Where a carrier of the view is handed to a call on the subject, nothing written down says whether the callee keeps it — `insert` does, `contains_key` does not, and `std.contracts` records `key: ?` for both — so the call is reported as keeping it. Failing open there means emitting Rust that does not compile, which is the C.1 violation this exists to remove; [ADR-010](docs/specification/adr/adr-010.md) D1's "an analysis that fails open is a vulnerability generator" is the same argument with a different cost. The consequence is named in the code, in Part I 6.6's `Status` note and in C.3's row: `self.names.contains_key(name)` is refused today. `NK2302` is therefore the one code in Appendix C not covered by C.4's property, and C.3 says so.

- **The domain is narrow on purpose, which is not the same thing.** Only destinations whose buffer is known *not* to be the parameter's own count. `examples/k-nucleotide.nika`'s `fn count(seq: &str, k: usize) -> HashMap[&str, Tally]` writes views of `seq` into a map it hands back and is correct, because the result points into `seq` and nothing else; the result case asks exactly that question — is this parameter the only buffer the signature names — before it reports anything. A local whose declared type holds a view is **not** a destination, because deciding it needs to know which buffer each local views, which this compiler does not compute.

- **Measured, not assumed.** Every `.nika` in the repository still lowers: 33 lower and 22 do not, the same 22 as before (21 deliberately broken files in `tests/errors/`, plus `examples/fortunes.nika`, whose `dsl postgres` has no lowering). `no_program_in_the_repository_keeps_a_naked_view` walks `examples/`, `benches/` and the Nikaia half of `std` and finds nothing. `cargo test --workspace` 529 passed, 0 failed (520 before, 9 added); `cargo fmt --all --check` clean; `cargo clippy --all-targets -- -D warnings` clean; `scripts/check-adr-refs.py` exit 0. No new ADR: the decision this rests on is ADR-008 D1, which already says a view in a field is a marker and a parameter gets no annotation.

- **Found on the way and *not* fixed, because it is a different defect.** A free function that takes a view-holding struct by value and hands one back — `fn record(s: Summary, name: &str) -> Summary` — emits `s: Summary<'_> … -> Summary<'_>` and fails with `E0106`, whether or not the view is stored: with a second naked view in the signature there is no single input for the result to be tied to. Nothing in the corpus writes that shape, and nothing here touches it: the naked view is not what breaks it, so `NK2302` would be the wrong code to report.

### Fixed (a trailing lambda can name its arguments)

- **The parser took `fn(user) { … }` inside a call's parentheses and only `fn { … }` outside them**, so Part I 5.3's own example, Part II 12.3's `account.access fn(to) { … }` and `access_all(a, b) fn(x, y) { … }` and Part II 12.7's `task::scope fn(s) { … }` were each read as two expressions - the call missing its last argument, and a closure passed to nobody, which in Rust type-checks often enough to be a different program rather than an error. `trailing_lambda` now shares `closure_params` with `closure_expr`, named arm first, and a trailing lambda reaches a path as well as a method call. [ADR-022](docs/specification/adr/adr-022.md) D1's "one lambda form" is unchanged and not reopened: naming the arguments is that form spelled out. The Status notes in Part I 5.3, Part II 12.3 and Part II 12.7 say so, `crates/nikaia/tests/lambdas.rs` compiles the emitted Rust for each shape, and the three re-run rows in [`docs/spec-promises.md`](docs/spec-promises.md) correct what the 0.0.9 entry below reported about them. Still not built, and now tests of their own: an effect marker on a lambda (`fn(info) sync { … }`, Part I 7.2) has no grammar at all, and `spawn fn(x) { … }` is one call to a function named `spawn` where it used to be two statements naming a value - the same `E0425`, one noun closer to the truth.

### Measured (0.0.9 — what an always-`Mutex` floor for `Locked` would cost against Part II 12.2)

- **An investigation, and it decides nothing about `Locked[T]`'s representation.** Part II 12.2 gives the lock two implementations, one per `user_parallelism`, and forbids the program pausing while something is locked — so a `Mutex` floor at *both* settings has to be cleared against that rule first. Four things were found, all in [`docs/mutex-floor.md`](docs/mutex-floor.md). **(1) Blocking is not pausing, and the specification already says so where it had to choose**: the panic hook must be `sync` and Part I 7.2 permits it to block ("briefly"), [ADR-006](docs/specification/adr/adr-006.md) D6 calls that "exceptionally permitted", and [ADR-005](docs/specification/adr/adr-005.md) D6 is titled "No *suspension point* while a lock is held" — so a floor neither violates 12.2's rule nor sidesteps it. **(2) Whether `access` stays `sync` turns on one ledger line and never on the primitive**: run against the real inference (`crates/nikaia/tests/lock_floor.rs`), `sync = "from(f)"` makes 12.2's idiom `sync = "inferred"` up every caller and a lambda that does I/O still loses it, while an entry with no `sync` line costs the idiom and, by [ADR-027](docs/specification/adr/adr-027.md) D1's greatest fixpoint, every caller above it — which would make 12.2's own idiom uncompilable in 12.6's own vehicle. **(3) At `user_parallelism = no` the floor costs 11.3 ns an `access` and no syscall**: `Mutex<i32>` against `RefCell<i32>`, uncontended, **+11.24 / +11.40 ns and ×6.18 / ×6.06** over two runs, falling to ×1.05 with 400 multiply-adds inside the guard (a fixed cost, not a proportional one), **zero `futex` calls in 1 000 000 acquisitions** under `strace -c`, and `Mutex<i32>` is *smaller* than `RefCell<i32>` (12 bytes against 16). A lock at `no` can never be contended by user code — one user thread ([ADR-037](docs/specification/adr/adr-037.md) D2) and an I/O thread that cannot name a user value ([ADR-038](docs/specification/adr/adr-038.md) D4's `Op` enum, re-checked) — so that is the whole of the cost there; the contended row is the expensive one (multiples, and the only row whose ratio did not reproduce) and it is unreachable at `no`. **(4) What the floor really costs at `no` is a diagnostic**: 12.2's `no` implementation exists to *panic* on a logical deadlock, and a `Mutex` hangs instead — run on one thread, exit 101 with `RefCell already borrowed` against killed-at-timeout, which at `no` is the whole program and also stops [ADR-006](docs/specification/adr/adr-006.md) D5's cleanup deadline, the hazard class D5's "honest limit" already names for blocking FFI. Keeping the panic costs **+2.0 ns, ×1.15** (an owner check in front of the acquisition), so losing it is a choice rather than a consequence.

- **The representation is already decided in the specification at *both* settings, and in no ADR at all** — which narrows the open question, but not where it was expected to narrow. [ADR-037](docs/specification/adr/adr-037.md) has no panic table and does not mention `Locked`; the table naming `Locked[T]` poisoning at `yes` is **Part III Appendix A.2**, and Part II 12.2 already names a `RefCell`-with-reentrancy-check at `no` and a real OS `Mutex` at `yes` in plain words. The only ADR that names `Locked[T]` is [ADR-005](docs/specification/adr/adr-005.md) D6, which decides the *rule* and records the divergence without deciding it. So an always-`Mutex` floor is not filling a gap: it changes a normative sentence, which under [`docs/README.md`](docs/README.md) §2 is a record that names what it displaces. The poisoning claim is asserted rather than argued (`benches/lockfloor`: a panic inside the guard poisons the mutex for every later acquisition and leaves the borrow flag recording nothing), and it is the one argument *for* the floor that is about capability rather than cost — `Arc<RefCell<i32>>` is not `Send`, so a `Mutex` floor is the only shape of `Locked` under which [`docs/rc-or-arc.md`](docs/rc-or-arc.md) §7's blocked path reaches 12.2's own counter.

- **Part II 12.2 gets a `Status` note, because what it said was not true.** The section states its no-I/O-while-locked rule as compile-time behaviour and shows the `NK2201` it reports. `Locked[T]` is unbuilt in full: the type name and `access` are accepted by the front end and reach the backend, which answers "cannot find type `Locked` in this scope"; nothing raises `NK2201`, so the program 12.2 shows as refused compiles today. Found on the way, and not about the floor: **12.2's idiom is not `sync` today either** — `counter.access` is a method call no ledger can resolve, so [ADR-027](docs/specification/adr/adr-027.md) D2's polarity refuses the claim, and the same is true of a *pure* `par_iter` body. The word can still be *written* over an `access`, because the check is deliberately permissive about a method call.

- **What was built for it, and what was not.** `benches/lockfloor/` (five paired shapes, every repeat printed, the machine and load printed by the script, and four assertions on `cargo test` for the differences a program can observe) and `crates/nikaia/tests/lock_floor.rs` (four assertions putting both spellings of a hypothetical `Locked::access` entry to `contracts::sync::infer`). **No `Mutex` reached the emitter and no representation was chosen.** `cargo test --workspace` green at `dev` and at `release`, `cargo fmt --all --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `scripts/check-adr-refs.py` exit 0.

### Fixed (0.0.9 — a written call that can fail is reported, and the ledger stops publishing that it cannot)

- **`NK2605`: an explicit call to something that can fail, in a function that does not declare `throws`, was not reported at all — and the committed ledger carried the wrong fact.** `fn ruft() -> String { return liest() }` beside a `throws` `liest` lowered in silence and `nikaia.contracts` recorded `[fn."ruft"] signature = "() -> String"` with no `throws`, where an absent `throws` in that file means *it cannot fail*. That file is committed, shipped with a package and compared by `--locked` ([ADR-020](docs/specification/adr/adr-020.md)), so the defect was not a missing caret but a **false fact published about the one thing a caller cannot see**. `NK2601`–`NK2604` and `NK2701` are all about calls *nobody wrote* ([ADR-025](docs/specification/adr/adr-025.md) D1), and the written call — the case that rule was generalised from — had no code. Part I 7.1 states the rule and carries the worked example; Part III C.3 has the catalogue row.

- **The ledger stops publishing it because the program is refused, and not because `throws` became inferred.** [ADR-023](docs/specification/adr/adr-023.md) D1 derives the error **set** and leaves the declaration in the source ("in source, `throws` is bare"); ADR-025 D1 already decided the case in words — "the function **must** declare `throws`, and the compiler says which implicit call is the reason". Inferring the keyword would also need to know about `catch`, which that walk does not: `fn f() { g() catch { … } }` cannot fail, and an inference blind to that would publish the *opposite* false fact. `project::lower` checks every unit before it calls `Ledger::render`, so a refused program renders no ledger — asserted, with the ledger as the subject, by `the_ledger_is_never_published_for_a_caller_that_does_not_say_it_can_fail`.

- **The polarity, asked the way [ADR-027](docs/specification/adr/adr-027.md) D4 asks it, and the answer is the mirror image.** A *declared* `throws` whose body cannot fail keeps `["?"]` — an over-claim, the safe direction, and it still does. The **absence** of a declaration outranked a body that provably could fail, and kept "cannot fail": the same shape as the hole D4 left for `sync`, where an *assertion* outranked a contradicting body, with the sign flipped — an over-claim there, an under-claim here, both fail-open. [`docs/from-for-throws-and-touches.md`](docs/from-for-throws-and-touches.md) §7 is the table.

- **Found on the way, and fixed with it: [ADR-023](docs/specification/adr/adr-023.md) D8's propagation was not lowered at all.** A written call to a `throws` function came out as `Ok(liest())` — a `Result` inside an `Ok` — so adding the `throws` that `NK2605` asks for produced a *second* `rustc` error about a generated file, which would have moved Appendix C.1's violation one step later instead of removing it. Every program in `examples/` writes `catch` at the call, so nothing in the corpus ever asked for the `?` and no test did either. It is emitted now for a call **by name**, suppressed inside a `catch`'s guarded half, and `a_written_call_propagates_its_failure` compiles and runs the result. A **method** call still does not take one — the emitter has no receiver types ([ADR-028](docs/specification/adr/adr-028.md)) — so `NK2605` refuses a fallible method call and `catch` is the shape that lowers; Part I 7.1's `Status` note says so, and ADR-023 §6's table gains the row.

- **`contracts::throws` now uses ADR-028's method resolution, where only `contracts::sync` did.** [ADR-031](docs/specification/adr/adr-031.md)'s chain — `HashMap[&str, Stats]` → `and_modify`'s `fn(&$V)` → `a.add(v)` → `Stats::add` — gives `record` `throws = ["ZuVoll"]` where it read `["?"]`, which is what ADR-028 means by **one** answer to what `a.add(v)` goes to. It is the only change here that makes an answer *narrower*, so it is argued rather than assumed: every contribution that went came from a call the compiler **named**; an unknown receiver and a method no ledger describes still arrive as `"?"` through `MethodCalls::unresolved`; and what replaces the `"?"` is a written-down fact, because an absent `throws` in `std.contracts` means "cannot fail", reviewed like code and contrasted with an absent `touches` in that file's own header. **This corrects the 0.0.9 *Answered* entry below**, which reasoned from "`contracts::throws` answers *every* method call with `"?"`".

- **`throws` with a type is refused with the reason, and the four specification sites that wrote one are corrected.** The decision is [ADR-023](docs/specification/adr/adr-023.md) D1's own title, so nothing was decided here. `fn f() throws IoError` gave a parse error at the type name offering `->` and `sync` as alternatives; `kw_throws` now carries a `fail(…)` saying the set is derived and recorded in `nikaia.contracts`, on the precedent of ADR-022's removed `fn: …` form in the same file. Part I 6.4 wrote `throws IoError` once in code, twice in prose and once inside **`NK2601`'s own `help:`** — the compiler's suggested fix telling the user to write what the compiler refuses — and Part II 10.2 B wrote `throws ParseError`. All four now read as Part I 7.1, which was right and is left alone.

- **`E0621` is in [ADR-005](docs/specification/adr/adr-005.md) D7's enumerated classes**, where a missing explicit lifetime belongs beside the seven other lifetime and borrow codes; [`docs/nightly-cost.md`](docs/nightly-cost.md) §3.3.2 found it absent. What "translated" means for it is recorded rather than glossed: `crates/nikaia/src/diagnostics` maps the **place** for every code, so the message already landed on the `.nika` line, and the **text** is still rustc's — `help: add explicit lifetime 'a to the type of key`, whose every noun is something [ADR-008](docs/specification/adr/adr-008.md) D1 says the author never writes. That is the same open half D7 records for `E0277`, at a second code, and it is stated and not solved: closing it needs ADR-008 D2's tether lattice, which is not built.

- **Two notes said the repository "named" a nightly, and it does not since [ADR-001](docs/specification/adr/adr-001.md) D1.** `docs/foreign-runtime.md` §1 and `docs/runtime-cost.md` §1 keep `rustc 1.94.0-nightly (8d670b93d 2025-12-31)` — **the version is a measurement and rewriting it would falsify one** — and say instead that it is the compiler the block was run under and not a toolchain this repository names. [ADR-036](docs/specification/adr/adr-036.md) §2 is unchanged deliberately: it names the compiler beside its instruction counts and makes no claim about what the repository uses, so there is no tense in it to correct.

### Added (0.0.9 — [ADR-037](docs/specification/adr/adr-037.md) D7 and D8: the count a particular `Shared` gets is inferred, and only ever downwards)

- **One rule, and everything is downstream of it: *it may only ever take an atomic away*.** D6 makes the atomic count the floor; `contracts::sharing` is an **optimisation** on top of it. It may lower a particular value to a plain count where it *proves* nothing crosses a thread with it, and where it cannot prove that the answer stays atomic. It may never add an atomic and it may never make a program unsafe — the same sentence read from both ends. The prototype `docs/rc-or-arc.md` left behind is now the real thing, under that rule.

- **`contracts::send` and `contracts::sharing` have a contract with each other and it runs one way.** `send` answers `may` for a `Shared` of crossable data, and that is only true because the count is atomic — so a value `sharing` lowers must not cross. Every crossing is a **seed**, and a missed seed is unsoundness rather than a missed 9 ns.

- **Step 1 created a seed that did not exist before, and it is the one the experiment explicitly left out.** `docs/rc-or-arc.md` §4 declined to seed `task::both` — the crossing the *compiler* chooses for statement overlapping — on ADR-033 D4's polarity, and that was sound only while a `Shared` was `MayNot` and never overlapped. Since D6 an overlapped operation may run on a thread of its own and hand a `Shared` **back** across one. It is a seed now, through the fallback for a handle whose allocation this analysis did not watch being made.

- **Five more fail-open siblings of the prototype's one known bug, found by asking what else "we have already seen it" could be hiding in.** `docs/rc-or-arc.md` §8 records a `<struct>.<field>` slot guarded on "already known", which made the verdict depend on the order somebody wrote their functions in. Its siblings: a handle **read back out** of a field produced a fresh class nothing forced; a handle **captured by a lambda** handed to a call nothing describes was not forced, because only a bare `Expr::Variable` argument was; the same for a handle inside a **tuple** or any other expression; a handle handed over as an **option** after the `;` was never looked at; a handle **assigned into** a field was not joined to it; and a `Shared` behind a **public field of a public type**, or behind a public parameter that merely *holds* one, was left plain. Every one of them is a test, and the field cases run in **both** written orders for the reason the original did.

- **The sharing summary is the fifth ledger column** — `sharing = ["counts | <result>: plain", "hits: atomic"]` — beside `sync`, `throws`, `touches` and `borrows`. Two facts in one line, and the first is the one a caller could not work out for itself: which positions are **one allocation**, so they have one count whichever side of the call decides it. `docs/rc-or-arc.md` §5.1 names it as the summary that *composes*, and the union-find that decides a count computes it already — which is why this is a column and not a mechanism ([ADR-020](docs/specification/adr/adr-020.md) D1). It is also the only column in that file that **cannot make a program wrong**: the floor is safe, so an entry that says `atomic` about everything describes a correct program paying 9 ns. `inference` becomes `stage0-signatures+sync-bodies+throws-bodies+sharing-bodies`, because one more column is read off the bodies, and 13.5's paragraph about that header is also brought up to date — it still claimed `stage0-signatures+sync-bodies`, two columns ago.

- **`nikaia --sharing` is an explanation and not a switch**, in the shape [ADR-033](docs/specification/adr/adr-033.md) D9 gave `--overlaps` and [ADR-010](docs/specification/adr/adr-010.md) D7 gave `--trust`: a heading per function, one line per value with what it got, and the reason under it. Then the **closed list of six fallbacks**, with the ones this program hit marked and the remedy for each — which is the part that makes D8 fair rather than merely decided.

- **There is deliberately no way to ask for the cheaper count (D8), and the reasoning is recorded because it will be proposed again.** Every fallback is one of two things. Either a **missing contract** — a call, a method or an argument position nothing describes, a type whose `fields` are unrecorded, a value whose origin this analysis cannot follow — and then the remedy is to *write the contract*, which is [ADR-033](docs/specification/adr/adr-033.md) D4's own closing argument that `std.contracts` growing is how programs get faster. Or it is a **public signature**, where whether the value ever crosses is decided by callers who do not exist yet, so an override would be a promise about somebody else's code — which `std.contracts` already refuses to make about a higher-order method's `sync`, and which a *representation* cannot be spelled `from(…)` for at all, because `Rc<T>` and `Arc<T>` are two types and a published artifact has already chosen one. D9's conclusion carries: **the language's escapes are restrictions, not permissions**, and a request for a cheaper representation is a permission.

- **The rule that does all of it with nothing new:** *what is observable is written; what is not is inferred, with safe as the floor.* `Shared` is written, because sharing changes when a value is cleaned up (D3's own reason, unchanged). `Rc` against `Arc` is inferred, because `docs/rc-or-arc.md` §2 measured that nothing a program can observe distinguishes them. **`Locked` is not decided by any of this**: `RefCell` against `Mutex` differs in what a reentrant `access` does and in what a panic inside one leaves behind, so it is observable, so it is written and not inferred.

- **What the analysis rests on is named rather than assumed.** A call the ledger describes is treated as **accounted for**, which is exactly what ADR-005 §5.2 already does for the same question — a contract is an account, and `std`'s are reviewed like code. The residual is ADR-005 §5.3's: enforceable only as far as a foreign crate is honest. Today the exposure is **zero**, because no `std` signature mentions `Shared` at all, and `a_std_entry_that_takes_a_shared_needs_a_second_look` is what makes somebody look on the day one does.

- **The base case is still the test that makes the rest worth anything.** A `Shared` that nothing crosses with gets the plain count, a struct field with nothing crossing keeps it, a call inside the unit keeps it, and a field read with nothing crossing lowers — without those, an analysis that answered `atomic` for everything would pass every other test in the file. Thirty tests in `crates/nikaia/tests/sharing.rs`, up from fourteen.

- **Checked rather than assumed:** `cargo test --workspace` green at `dev` and at `release`, `cargo fmt --all --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `scripts/check-adr-refs.py` exit 0. **Nothing is emitted**: `Shared` still has no constructor and no `Rc::new`/`Arc::new`, so no count is ever allocated — `sharing::rust_name` says which two Rust types the two answers are and is called by nothing. `contracts/order.rs` is untouched.

### Decided (0.0.9 — [ADR-037](docs/specification/adr/adr-037.md) D6: `Shared` is one atomic count, at both settings)

- **D3's open question is closed, and the number in [`docs/rc-or-arc.md`](docs/rc-or-arc.md) is what closed it.** D3 expanded `Shared` from `user_parallelism` — `Rc` at `no`, `Arc` at `yes`, **per build** — and the new **D6** narrows exactly that row: the count is atomic at both settings. The reason is one sentence. `NK25xx`'s verdict is about a *type* and may never consult the switch ([ADR-005](docs/specification/adr/adr-005.md) §1 Group B, §5.3), so a type whose expansion moved with the switch had to be refused a crossing at **both** settings — which made Part II 12.2's `Shared[Locked[i32]]` counter, the program the switch exists to serve, unwritable. The price is the measured **+9 ns per clone-and-drop pair**: ×3.40 on a loop that is only the count, ×1.01 on a loop with ~70 ns of work in it, and ×1.00 on a handle that is read and not cloned. The expensive atomic is the contended one (an order of magnitude, ×11–×17) and no choice avoids it — a count several threads touch has to be atomic.

- **In `send.rs` it was the one line the experiment said it would be, and the line cost more around it than in it.** `Shared` moves out of the `MayNot` case and into `CONTAINERS`, where it is answered by what it holds — so `Shared[Vec[i64]]` crosses and `Shared[Locked[i32]]` is **undecided**, for the lock's sake rather than the count's. No switch reaches the file and none may, which is unchanged. What the line cost: `Shared` was the file's only `MayNot` producer, so `held_by` and the second half of `way_out` went with it, `note`'s refusal sentence no longer names a reference count, and eight tests across `contracts::send` and `tests/send.rs` changed sides.

- **No type answers `may not` any more, so `NK2501` and `NK2502` are built and reached by no program.** Stated rather than discovered: the arm stays because the reason for it has not gone away — a type whose implementation *does* follow `user_parallelism` has to take the worse of the two settings — and `Locked` is the candidate. What is lost with it is an **end-to-end rendering test** of either code, and there is no honest way to write one: a refusal can only come from a type the records name, and they name none. The refusal arm and both its sentences are instead asserted directly in `contracts::send`'s own tests, and `tests/send.rs` asserts the new silence at both settings. Part III C.5 gains a `Status` note saying so and its two examples are rewritten against a hypothetical type, because they were written against `Shared`.

- **`Shared` is still unbuilt, and D6 decides what it will expand to rather than what it does.** There is no `Rc::new` or `Arc::new` in the emitter and no constructor in the grammar, so a `Shared` reaches the compiler only as a declared type. What changed today is a verdict, which is real and tested. D3's own per-build sentence was the same kind of promise.

- **Where the rule now is:** Part I 6.2 (the machinery a second thread may touch, at every setting), Part II 12.2 (the `Shared` around the counter is not what stops it crossing; the lock is, and nothing decides the lock), Part III 13.3 (`std` may write a `Shared` now — what the one-setting pre-lowering still rules out is `Locked`) and Part III C.5. ADR-005 §5.1's three-answer table and §5.3 get the narrowing note the layering asks for; no new ADR.

- **Not decided here.** `Locked`'s representation, which is D3's second half: `RefCell` against `Mutex` differs in what a reentrant `access` does and in what a panic inside one leaves behind, so it is observable, so it is written and not inferred. Part II 12.2's lock rules are untouched.

- **Checked rather than assumed:** `cargo test --workspace` green at `dev` and at `release`, `cargo fmt --all --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `scripts/check-adr-refs.py` exit 0.

### Answered (0.0.9 — [ADR-029](docs/specification/adr/adr-029.md) D3: `from(f)` is one rule, and `touches` is not its third case)

- **The question D1 left open is answered: a function type for user code costs *one* inference rule, not three.** D3's soundness argument — "the lambda runs during the call, so its calls are already counted in the function that writes it" — carries to **`throws`** unchanged and does **not** carry to **`touches`**. D3 gains a paragraph saying so in one sentence per column, and [`docs/from-for-throws-and-touches.md`](docs/from-for-throws-and-touches.md) is the programs, the ledgers they produced and the reports they printed. No new ADR; nothing about the decision changes.

- **The argument has a second premise nobody had written down, and it is the one that decides the other two columns.** Beside D4's immediacy, "already counted" only means *counted where the contract is read* if the analysis reading it asks about a **whole function**. `sync` does, so the premise was invisible. `contracts::throws` does too — it is `contracts::sync`'s walk with the lattice turned around, over the same `visit_expr_blocks`, whose `Expr::Closure` arm is the mechanism D3 describes. `contracts::order` does not: it asks what **one statement** reaches, because the rule it serves is about two adjacent statements.

- **`throws` needs no key at all, and that is stronger than needing `from`.** `fn sortiere(xs) throws { xs.sort_by_key fn { pruefe(a) } … }` already records `throws = ["?", "LeereZeile"]`, with `LeereZeile` coming from the lambda's body and from nowhere else — the same call over a lambda that cannot fail records only `["?"]`. And `contracts::throws` answers *every* method call with `"?"`, so a higher-order call is already as pessimistic as the column can be: a `throws = "from(f)"` read as "adds nothing" could only ever make it **less** so, which is the direction [ADR-010](docs/specification/adr/adr-010.md) D1 forbids.

- **`touches` must not borrow the spelling, and the reason is a soundness one.** A `catch` handler's effects are counted *into* the statement's touch set ([ADR-033](docs/specification/adr/adr-033.md) §8.3); a lambda's are *stepped around*. Side by side, `fs::write(…) catch { println("…") }` next to a `println` is refused as "`fs::write + println / println` — both reach stdout", naming the handler's write as a callee of the first statement, where `xs.sort_by_key fn { println("…") … }` next to a `println` is refused for ignorance about `sort_by_key` and mentions `stdout` nowhere. So "adds nothing" there would buy an overlap on an **incomplete** touch set, and the two lines of output would interleave differently from run to run: ADR-033 D1 broken by an effect nobody counted — the same shape as the `stdout`/`stderr` mistake §6 caught and the `catch` hole §8.3 closed. **A hole here changes what a program prints**, not how fast it prints it.

- **What `touches` would want instead is the opposite instruction.** Not "this call adds nothing" but *add what the lambda reaches, and everything where the lambda cannot be read* — the polarity `walk_block` already gives a handler. One word meaning "skip, it is counted elsewhere" in one column and "descend, nothing else counts it" in another is two rules wearing one name, which is what `contracts::touch::KINDS`' closed list exists to prevent.

- **The refusal that keeps it shut was a `_` arm and is now a named one.** `contracts::order`'s `walk` has an `Expr::Closure` arm with the reasoning written where the next person will be standing. Same polarity, better message ("a lambda, whose body this analysis does not read"), and it matters because a trailing lambda is today refused two or three times over by limits the records call **liftable** — a missing `touches` line, the non-literal-argument rule ([ADR-033](docs/specification/adr/adr-033.md) D9's table: "an implementation limit, not a language question"), and a missing `crosses` line ([ADR-005](docs/specification/adr/adr-005.md) §1 Group B). Close all three and the lambda arm is the only thing left. The same file already descends into a closure in `names_in`, for data dependencies: the names counted and the effects did not, and nothing said why.

- **A stale claim in `crates/nikaia-std/std.contracts` is corrected.** Its header said a higher-order method carries no `sync` because "a ledger cannot say 'it depends' yet: `sync = "from(f)"` is the shape that would, and it is not decided (ADR-027 §7)" — thirty lines above four entries that say exactly `sync = "from(f)"`. The comment predated ADR-029 D3. Both halves of it now say what is true, and the `touches` note beside it says why the same shape is not available there.

- **Three tests hold the answer.** `a_throwing_lambda_is_already_in_the_enclosing_functions_error_set` (`tests/contracts.rs`) pins the error set, and `a_lambdas_own_effects_are_not_in_the_statements_touch_set` (`tests/ordering.rs`) pins the touch set against `std`'s ledger *and* against one where `Vec::sort_by_key` claims `touches = []` outright — the permissive entry a `from`-style reading would amount to. `sync`'s half was already pinned by `a_higher_order_method_hands_on_what_its_lambda_does` and is re-run rather than rewritten.

- **Checked rather than assumed:** `cargo test --workspace` green at `dev` and at `release`, `cargo fmt --all --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `scripts/check-adr-refs.py` exit 0. **No function types were added to the grammar**; `fn f(g: fn())` is still a parse error, which is D1 and is the owner's decision to make.

- **Handed to the owner, not decided here.** (1) `contracts::throws` does not use ADR-028's method resolution, where `contracts::sync` does, so the [ADR-031](docs/specification/adr/adr-031.md) chain `HashMap[&str, Stats]` → `fn(&$V)` → `a.add(v)` → `Stats::add` yields `throws = ["?"]` rather than `["ZuVoll"]` — fail-closed, and one argument away from being exact. (2) An **explicit** call that can fail inside a function that does not declare `throws` is not reported by Nikaia at all: `NK2601` and `NK2701` are both about *implicit* calls ([ADR-025](docs/specification/adr/adr-025.md) D1), the ledger records the caller as unable to fail, and the emitted Rust is what `rustc` rejects. Neither has anything to do with lambdas.
### Measured (0.0.9 — ADR-037 D3: what an atomic reference count costs, and whether `Rc` or `Arc` can be chosen per value)

- **An experiment, and it decides nothing.** [ADR-037](docs/specification/adr/adr-037.md) D3 expands `Shared` from `user_parallelism` — `no` gives `Rc`, `yes` gives `Arc`, **per build** — and says of itself that whether the choice could be made *per value* "is a real question and is not answered here". It was tried, measured and prototyped. The question is still open and the decision is the owner's; what exists now is a number, three worked cases and a list of what the analysis cannot decide, all in [`docs/rc-or-arc.md`](docs/rc-or-arc.md). D3 gains a parenthetical pointing at it and keeps its wording.

- **`Rc` and `Arc` differ in nothing a program can observe except speed and `Send`-ness**, which is the gate the experiment had to pass first: D3's reason for `Shared` being written by hand is that *sharing changes when a value is cleaned up*, and if that distinguished the two counts the language's own rule would forbid inferring between them. It does not. Six assertions in `benches/refcount/` run on every `cargo test`: the handle is the same size, the owner count is the same at every step, **the value is cleaned up at the same point** (asserted against a written log), a weak handle goes stale at the same point, and exclusive access and unwrapping succeed and fail alike. Two differences are real and named rather than hidden — the **thread a destructor runs on** (which can only differ for a value that crosses, where the choice is forced anyway) and the count-overflow abort threshold (`usize::MAX` against `isize::MAX`, needing 2⁶³ live handles).

- **The atomic costs +9 ns per clone-and-drop pair, and it is a fixed cost rather than a proportional one.** Intel Xeon @ 2.80 GHz, 4 vCPU, 15 GB, Linux 6.18.44, `rustc 1.94.1` stable, `--release`, nine repeats of 50 000 000 operations, load average printed beside every table. `clone+drop` **×3.40** (+9.028 ns, sd 0.043 on the atomic row); a read through the handle with no clone **×0.99** — the control, which ties and bounds every other difference from below; the same clone and drop with ~70 ns of other work between them **×1.01** (+0.864 ns), the atomic hiding under independent instructions. The whole table was taken twice within the hour and every row agrees to within 1 %, except the noisiest at 7 %. Per [`docs/runtime-cost.md`](docs/runtime-cost.md) §6.3 only the ratios and the signs travel: absolutes on a shared VM moved 1.4–1.9× from one day to the next.

- **The expensive atomic is the one no inference can avoid.** Four threads cloning and dropping **one** count cost **×17.19** (+56.9 ns an operation) against four threads with a handle each — the cache line moving between cores, not the instruction. That row is the least reproducible here, at ×11.33 in a third run on a busier box, so what travels is the order of magnitude and not the figure. But a count four threads touch is a value on four threads, which *must* be atomic; so the case worth 17× is the case with nothing to decide, and the case the inference can decide is worth 9 ns.

- **A prototype that reports and emits nothing: `contracts::sharing` and `nikaia --sharing`.** `Shared` is unbuilt — there is no `Rc::new` or `Arc::new` anywhere in the emitter — so nothing was wired into a build. The analysis is real: it runs over the real AST and the real ledgers, it reuses `contracts::send`'s enumeration of the crossings as its seed list and [ADR-029](docs/specification/adr/adr-029.md)'s walk through a struct's `fields` for transitivity, and `crates/nikaia/tests/sharing.rs` is 14 tests over real `.nika` sources. **The lattice turned out not to be where the difficulty is:** a count belongs to the *allocation* and not to the handle, so the relation between handles is an equivalence rather than an ordering, the analysis is union-find plus one colouring pass, and the least fixpoint of "is atomic" and the greatest fixpoint of "stays plain" compute the same set in one step — unlike `sync` ([ADR-027](docs/specification/adr/adr-027.md) D1), whose constraint is conjunctive over a graph that can cycle.

- **The polarity holds and every undecidable case is named.** In doubt, atomic: an inferred `Arc` where a plain count would do is a cost, an inferred `Rc` on a value that crosses is a data race ([ADR-010](docs/specification/adr/adr-010.md) D1). Four cases come out atomic because nothing decides them, and the report marks each as undecided rather than letting it pass for a decision: a `Shared` in a **public** signature; one handed to a **call** nothing describes; one handed to a **method** nothing describes; one in an argument position no contract covers. A fifth is a hole rather than a case — a `Shared` inside a type whose `fields` the ledger does not record is not seen at all.

- **The one `Shared` in the repository comes out atomic, where the switch gives it a plain count.** `examples/fortunes.nika` takes `db: Shared[postgres::Connection]` and hands it to `all.fetch(db)`; nothing written down describes `fetch`, so the polarity decides. The file's own comment says the opposite about the build it was written for, and both are right — which makes the inference a **regression** on the corpus's only `Shared` at `user_parallelism = no`, and a ~9 ns one against a database round trip, so a regression that does not matter either.

- **And it does not stretch far enough to reach the program it was wanted for.** Part II 12.2's counter is `Shared[Locked[i32]]`. `Arc<T>` is `Send` only where `T` is `Send + Sync`, and `RefCell` is not `Sync`, so inferring the *count* per value does not make that counter crossable — `Locked` would have to be inferred too. There the gate closes: `RefCell` and `Mutex` differ in what a reentrant `access` does (panic against block) and in what a panic inside one leaves behind (poisoning), so that is a **different** decision from the one `Rc` against `Arc` passed. Measured, the pair costs +20.8 ns and ×5.72 an increment, of which about 12 ns is the lock and about 9 ns the count — so the lock is the larger half, and it is the half a program can tell apart.

- **What it would cost `NK25xx`, which is not obvious and belongs in front of the decision.** `Shared` is the only type the records make non-crossable ([ADR-005](docs/specification/adr/adr-005.md) §5.3). A per-value inference makes a `Shared` that crosses atomic rather than refusing it, so the structural `Send` check would keep its `Undecided` arm and **lose the `MayNot` arm it was built for**. The two designs are substitutes rather than complements, and a third option the measurement makes cheap — one representation, `Shared` always `Arc` — reaches the same place in one line of `send.rs` with no analysis at all. The price of that one is the 9 ns, and the choice between the three is the owner's.

- **Nothing regressed, and it was checked rather than assumed.** `cargo test --workspace` green at `dev` and at `release`, `cargo fmt --all --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `scripts/check-adr-refs.py` exit 0.

- **Handed to the owner, not decided here:** §5.1's library boundary cannot be answered yet. A count is a *representation* and not a claim, so `Rc<T>` and `Arc<T>` make a public function two functions — which means a ledger column can record a choice but cannot serve both callers, the way `sync = "from(f)"` can. Whether a per-function sharing *summary* suffices instead depends on whether a Nikaia package ships source that this build lowers or a compiled artifact, and Part III 13.3's manifest says in as many words that how a Nikaia package is resolved is not decided ([ADR-002](docs/specification/adr/adr-002.md) D1 §5). So D3 has a question under it that another open decision owns.


### Withdrawn (0.0.9 — the nightly toolchain, the Bridge-IR backend and the `rustc_ast` path)

- **Nikaia lowers `.nika` to Rust source text, and that is the only code generator.** Three things that existed to make a second one possible are **withdrawn**: the pinned nightly toolchain, the **Bridge-IR** protocol, and the `rustc_ast` lowering that consumed it. `--backend` takes `interpreter` and `rust`; `rust` keeps its name, because it says what comes out and because the specification, the cache's backend dimension and every test already spell it. The decision is the owner's and is recorded as a **withdrawal** under `docs/README.md` §2: the specification and the ADRs are rewritten as though none of the three had been there, one sentence justifies direct lowering ([ADR-004](docs/specification/adr/adr-004.md) D1), and this entry plus [`docs/withdrawn-one-way-down.md`](docs/withdrawn-one-way-down.md) are where everything else goes.

- **What the three were, and what each was for.** **Bridge-IR** (`crates/bridge-ir`, 85 lines) was a pure-data intermediate representation — `Function`, `Struct`, `Let`, `Expr`, `Literal`, `Variable`, `Call`, spans as `Range<usize>`, no compiler state — and it was the *narrow waist*: any language frontend would target it, and a `rustc` change would reach the executor and stop there. The **`rustc_ast` path** (`crates/rustc-executor`) consumed a `BridgeModule` and built a `rustc_ast::Crate` in one pass, which `rustc_ast_pretty::pprust` printed to Rust text and a `rustc` subprocess compiled; the same crate was to be handed to `rustc_interface::run_compiler` one day, skipping rustc's parser entirely. The **pinned nightly** (`bridge-toolchain/rust-toolchain.toml`, `nightly-2026-01-01` with `rustc-dev`, reached through `scripts/bridge-toolchain.sh`) existed for exactly one reason: `rustc_ast` is `rustc_private`, and `rustc_private` needs a nightly and has no stability promise, so the backend that linked it had to be pinned to one snapshot and rebuilt against it in its own CI leg or it would rot.

- **The decision was taken without a further measurement, and that is deliberate.** Nothing was re-measured to justify it and nothing needed to be. Four numbers already existed, taken for other questions, and all four pointed the same way:
    - **Bridge-IR carried 1 of the 15 corpus programs.** It had no control flow at all — no `if`, no `while`, no `match`, no binary operators — so `hello_world.nika` reached the backend, `let_assignment.nika` was refused by name, and all eleven `examples/` lower to a `grammar! { }` invocation that Bridge-IR cannot express. The waist was narrow in the wrong dimension: not *disciplined*, just *empty*.
    - **The in-memory exit was worth 0.64 %,** and three quarters of that was starting a process rather than the round trip through text. On the largest program the corpus lowers: the print-write-re-lex-re-parse round trip is **2.77 M of 1 719 M Ir, 0.161 %**, and the process is **8.3 M, 0.48 %**. It reaches 24.5 % only on a three-line program whose whole compile is 34 M, and the share *falls* as a project grows, because every `.nika` file becomes a `mod` in one Rust crate. Worse, the crate the lowering built was **print-only** — every node `NodeId::from_u32(0)` and `DUMMY_SP`, where rustc's expansion asserts `DUMMY_NODE_ID` — so the exit was not free to keep open either.
    - **`-Zpolonius=next` changed zero verdicts at +7.11 %.** Thirty lowered programs compiled twice: 24 accepted by both, 6 rejected by both with byte-identical codes, **0 verdicts changed**, at **+7.11 %** of the instructions a full debug compile of the largest of them retires. And it was the only reason a `-Z` flag was ever wanted.
    - **A bridge-enabled binary was not a relocatable binary.** It linked `librustc_driver-<per-build hash>.so` by **absolute RUNPATH into the build machine's rustup home**, with the hash in the soname differing per build, so it ran only beside that one nightly installed where it was built. A compiler without the backend links `libc`/`libgcc` and is self-contained. That, and not disk space — two megabytes either way — is the measurement that did the most work.

- **Why it is a withdrawal and not a supersession.** A supersession leaves a live citation behind, because something still rests on the displaced part; a withdrawal leaves none (`docs/README.md` §2). After the rewrite nothing cites Bridge-IR, `rustc_ast`, `rustc_private` or a nightly, and `scripts/check-adr-refs.py` is what proves it: it fails on a citation to a `Dn` that no longer exists, and it is green.

- **What was deleted.** `crates/bridge-ir` and `crates/rustc-executor`; `nikaia`'s `rustc-backend` feature and its `rustc-executor` dependency; both `#![feature(rustc_private)]` — one in `crates/nikaia/src/main.rs`, one in a root-level `check_rustc.rs` scratch file — and `extern crate rustc_driver`; the `bridge` arm of `--backend` with both halves of its refusal; the AST-to-Bridge lowering and `parse_to_bridge` in `crates/nikaia/src/parser`; `crates/nikaia/tests/bridge_backend.rs` and `crates/nikaia/tests/backend_absent.rs`, whose whole subject was the backend and its absence; `bridge-toolchain/rust-toolchain.toml` and `scripts/bridge-toolchain.sh`; the `bridge_backend` CI leg; and `findthesource.md`, a scratch note whose entire content was a path into the pinned nightly's `rustc_ast` sources. `_config.yml` loses the two exclusions that went with them. **The workspace now contains no `#![feature(...)]` and passes no `-Z` flag**, and `rust-toolchain.toml` is the only toolchain file, so there is one CI leg.

- **What stays, renamed.** `crates/bridge-orchestrator` is `crates/orchestrator`: it is [ADR-003](docs/specification/adr/adr-003.md) D2's generic orchestrator, it owns the build cache, the lockfile and the Cargo wrapping, and none of that ever depended on Bridge-IR — only its name did. Its `LanguageFrontend` trait handed back a `BridgeModule` and now hands back **Rust source text**, which is [ADR-003](docs/specification/adr/adr-003.md) D1 as the interface it always should have been: everything the orchestrator does with a frontend's answer, it does to bytes.

- **What the records say now.** [ADR-001](docs/specification/adr/adr-001.md) is retitled and is about the generated parser and the staged bootstrap; its D1 is the toolchain decision with the pin taken out of it — stable, named in one file — and D2, D3, D4 keep their numbers because seven records and the compiler's own comments cite them. [ADR-003](docs/specification/adr/adr-003.md) is rewritten around the separation that is real and the text interface that replaces the waist. [ADR-004](docs/specification/adr/adr-004.md) is one lowering emitting Rust source text, and the text a person reads is the text that is compiled. [ADR-005](docs/specification/adr/adr-005.md) keeps Group B.2's situation and answers it with the frontend desugaring in one sentence (D2); its D9 is gone, and so is every mention of the flag in D2, §1, §3 and §5. [ADR-006](docs/specification/adr/adr-006.md) makes its `async_drop` argument without comparing against a flag nothing passes. [ADR-002](docs/specification/adr/adr-002.md) loses its history section and the pin from its price. [ADR-021](docs/specification/adr/adr-021.md) keeps **D9** and its Cranelift measurement — that is a *Cargo codegen backend* and was never the bridge — and loses **D14**, whose subject was a backend that could be compiled out and no longer exists. [ADR-011](docs/specification/adr/adr-011.md) D8, [ADR-014](docs/specification/adr/adr-014.md) D1 and [ADR-038](docs/specification/adr/adr-038.md) §4.1 lose their withdrawn halves. No ADR file ended up empty, so none was deleted.

- **The notes keep every number, and say what became of the question.** `docs/nightly-cost.md` and `docs/subprocess-cost.md` are not gutted: they carry a banner saying their subject was withdrawn without a further measurement and that the numbers below are unrevised, and their closing sections now say what happened to the questions they left open instead of leaving them open. `docs/std-sysroot.md` names its 58 packages as they were named then and notes that the 1.4 GB it weighed the decision against is now 602 MiB with the conclusion unchanged. `docs/technical_notes.md` keeps its `rustc_ast` findings under a note that nothing links them any more. `docs/withdrawn-one-way-down.md` is the long version.

- **Nothing regressed, and it was checked rather than assumed.** `cargo test --workspace` green at `dev` and at `release`, `cargo fmt --all --check` clean, `cargo clippy --all-targets -- -D warnings` clean, `scripts/check-adr-refs.py` exit 0. There is one toolchain now, so there is one of each to run.

- **Handed to the owner, not decided here:** [ADR-021](docs/specification/adr/adr-021.md) D9 keeps Cranelift "documented, tested, switchable", and its switch is `[profile.dev] codegen-backend`, which is an unstable Cargo key. With the nightly withdrawn it can no longer be switched on from this repository. D9's *refusal* and its measurement are untouched, as asked; whether the switchability claim survives is a decision no record makes.

### Decided (0.0.9 - ADR-001 D5 and ADR-005 D9: Nikaia no longer requires the Rust nightly)

- **Stable is the toolchain a clone builds with.** `rust-toolchain.toml` says `channel = "stable"`, and [ADR-001](docs/specification/adr/adr-001.md) **D5** is the new decision that narrows D1. D1's premise was two things, `-Z` flags and `rustc_private`; neither survived measurement. No `-Z` flag is passed in any build, and `rustc_private` lives in exactly two `#![feature(…)]` attributes, both reachable only through `nikaia`'s `rustc-backend` feature. So the whole compiler - the `rust` backend, the interpreter, projects, the ledger, the type checker - builds, tests and lints on stable, and that is now the leg CI requires to be green.
- **The nightly is the Bridge-IR backend's, and stays pinned exactly in one place.** That place is the new `bridge-toolchain/rust-toolchain.toml`, and it is a second real toolchain file rather than a channel written into a script for D1's original reason: rustup's own file is the only form that states the channel **and** the components together, and a nightly without `rustc-dev` is not what [ADR-004](docs/specification/adr/adr-004.md)'s bridge needs. `rustup show` run in that directory installs exactly what it names - rustup takes the nearest toolchain file, so it wins over the root's stable - and `scripts/bridge-toolchain.sh` runs a cargo command on it against the workspace at the root. Nothing else in the repository, CI or the compiler's own error messages included, spells a nightly.
- **`-Zpolonius=next` is refused, and Group B.2 goes to the frontend.** [ADR-005](docs/specification/adr/adr-005.md) **D9** narrows D2: the flag changes **zero** verdicts over the thirty programs this repository lowers, costs **+7.11 %** of a full build, and being a `-Z` flag would put *every* user back on a nightly that D5 has just taken them off. What answers Group B.2 instead is the desugaring onto entry-style APIs that D2 itself named as the fallback - affordable because the corpus writes it unprompted: `examples/1brc.nika` and `examples/access-log.nika` both want exactly D2's situation and both write `.entry(k).and_modify fn { … }.or_insert_with fn { … }`. **What stays true:** the classification (Group B, the compiler's to solve, no user-visible syntax) and the situation's reality - thirteen lines of Nikaia reach it, and nothing in the repository writes them. D9 is not built.
- **Corrections to claims made earlier in this changelog.** The 0.0.9 entry above says "D2 stands as decided" and "the ordering now explicit: build the frontend desugaring first; the flag earns its 7 % the day a program somebody wrote needs it" - that was the evidence's conclusion, and the decision has now gone further: the flag is refused outright, and reopening it is a change to ADR-001 D5 as well. The same entry says the pin is "paid for by one thing, ADR-004's bridge backend" and treats that as a correction *within* D1; it is a new decision now, D5, because the scope of the pin changed and this project records that as a `Dn`. [ADR-006](docs/specification/adr/adr-006.md)'s `async_drop` comparison is updated from the other side: a flag that only accepts more correct programs can be declined and picked up unchanged, which is the property the comparison was using.
- **CI keeps both legs and swaps which one is the project's health.** `bootstrap_compiler` now runs on stable (`-p nikaia --no-default-features`, build, clippy, test, and the driver over every sample); `bridge_backend` runs the whole workspace, `rustc-executor` included, on the pinned nightly through the script. The nightly leg is not droppable: `rustc_private` has no stability promise and moves with the compiler ([ADR-003](docs/specification/adr/adr-003.md) §1), so a bridge that is not built is a bridge that rots. Both legs run `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` and `scripts/check-adr-refs.py`; clippy on the nightly leg is new.
- **Green on both, at both profiles.** `cargo test -p nikaia --no-default-features` on stable: 363 passed, 0 failed, at `dev` and at `release`. `cargo test --workspace` on `nightly-2026-01-01`: 442 passed, 0 failed, at `dev` and at `release`. `rustc_private` is still confined to `crates/rustc-executor` ([ADR-003](docs/specification/adr/adr-003.md) D1).
- **Reader-facing text that said otherwise.** `README.md` no longer says the executor is "pinned to one exact nightly per release" as if that were the installation requirement, and says what you actually need. Part III Chapter 13 gains the rule - a stable toolchain and nothing more, with the bridge backend as the exception - which it had never stated at all; Part I and Part II turned out to say nothing about the toolchain and are untouched. Part III 13.5's illustrative ledger header also said `toolchain = "nightly-2026-01-01"`, which contradicted the paragraph two screens down that explains the field records **Nikaia's** version and never `rustc`'s; it reads `nikaia 0.1.0`, which is what the compiler writes.
- **Not decided here:** which backend is the default on a build that has no bridge. That belongs to ADR-004 and ADR-021 D9, is being settled elsewhere, and nothing in this change implies an answer.
### Decided and built (0.0.9 - [ADR-004](docs/specification/adr/adr-004.md) D4: the bridge backend is optional, and `rust` is the default)

- **`nikaia --input x.nika` with no `--backend` now lowers through the `rust` backend**, the Stage 0 transpiler. `--backend bridge` still exists, is still chosen by name, and is still in every build made with the `rustc-backend` feature. This is the question [`docs/nightly-cost.md`](docs/nightly-cost.md) §5 and [`docs/subprocess-cost.md`](docs/subprocess-cost.md) §5 handed on rather than answered, and [ADR-004](docs/specification/adr/adr-004.md) D4 is where it is answered.
- **The default had been the backend that compiles almost nothing: Bridge-IR carries 1 of the 15 corpus programs** and the `rust` backend carries all fifteen. A default is what a person gets without asking, and that one answered *I cannot* to fourteen programs in fifteen - a fact that went unnoticed for as long as it did because, while `bridge` was the default, it panicked on its first interned symbol and so failed on **every** input with `cargo check` staying green.
- **And the reason it could not simply stay the default: a bridge-enabled binary is not a relocatable binary.** It links `librustc_driver-<per-build hash>.so` with an absolute RUNPATH into the build machine's rustup home, and the hash in the soname differs per build, so a stable install has a differently named file. Built without the feature it links only `libc`/`libgcc` and is self-contained. Not disk space, which is two megabytes either way.
- **What is *not* undone, because a record that left this out would read as a retreat.** [ADR-003](docs/specification/adr/adr-003.md)'s hub and spoke stands whole - a frontend targets Bridge-IR and never `rustc_ast` - and ADR-004 D1's single lowering stands. **The bridge backend is not deprecated**: it is the route the language's own future compilation goes through, and D3's in-memory exit is the same open option it always was. What changed is which backend a person gets without asking, and whether every installation must carry one.
- **[ADR-021](docs/specification/adr/adr-021.md) D14: *compiled out* and *never implemented* are two refusals, and the message says which one you got.** D9 had one case in front of it, `cranelift`, which nothing implements; `bridge` on a build without the feature is the other, and it exists. So one refusal names the feature, the toolchain component and roughly what it weighs, because there is something to do about it, and the other says there is nothing to install - a shared wording would cost a reader the whole difference in the expensive direction. A refusal also lists what *this build* has rather than what the language names, so it cannot answer one refusal with another.
- **The cache was checked rather than assumed, and needed no change.** The backend is already a dimension of the key ([ADR-021](docs/specification/adr/adr-021.md) D5, D7, asserted by `the_backend_changes_the_key`), and only the `rust` lowering is ever stored - the bridge hands its module to `rustc-executor` and consults no cache at all. So a bare invocation shares the one entry `--backend rust` already used, which is the same lowering under two spellings, and no `bridge` entry exists to be served to a `rust` build or the reverse. `backend_default.rs` asserts that the two spellings hit one entry rather than forking the store.
- **No existing test's expectation was flipped.** Every test in the suite already passed `--backend` explicitly, so none of them rested on the default; what rested on it was *prose*, and `bridge_backend.rs`'s header is the one that mattered. It said `--backend bridge` "is the default backend", which is now history and reads as history - and the file carries more than it used to, not less: while `bridge` was the default every bare invocation drove that path, and now only these three tests do. A backend nobody exercises is how that panic happened the first time.
- **One thing this makes visible and does not decide**, recorded in D4 and handed to the owner: the backend now reached first is not the printer ADR-004 D2 describes. `--backend rust` emits Rust from the Nikaia AST in `crates/nikaia/src/emit` and never builds `rustc_ast`, so D1's "exactly one place" and D2's "never a parallel implementation" are claims about the Bridge-IR path. That was already true while `bridge` was the default; what changed is which of the two a reader meets first.
- Part I 8.1.1 writes `nikaia --input x.nika --overlaps` with no `--backend`, and that command line only now does what the sentence says: `--overlaps` and `--trust` are answered by the `rust` backend, so under the old default they were accepted and silently dropped.
### Fixed (0.0.9 - ADR-011 D2: a `return` at the end of a value was being read as that value)

- **Stage 0 deleted a `return` from the end of any block that stood in value position, and in the common case nothing complained.** `1 => { return 10 }` came out as `1 => { 10 }`, so the value became the *arm's* instead of the function's. It had been recorded ([`docs/nightly-cost.md`](docs/nightly-cost.md) §3.3) as a narrow `match` bug surfacing as `E0308`. It was neither. The failure mode depends on whether the two readings happen to agree on a type, not on what the function returns: `fn announce(n: i64) { match n { 0 => { return note(n) } … } println("checked") }` compiled, ran, and printed `checked` on the way out - a **silently different program**, with nothing for rustc to say about it because both readings of the arm are `()`.
- **The cause was one `bool` doing two jobs, and it reached four shapes.** `tail` in `crates/nikaia/src/emit/mod.rs` meant both "this statement is the block's value" - which decides the semicolon, and is Part I 3.1 - and "this block's value is the *function's* return value", which is what licenses writing `fn f() -> T { return x }` as `{ x }`. Only a function body is the second, and `expr()` handed `true` to every block-shaped expression on the way in. So the same line dropped the `return` at the end of a **`match` arm**, an **`if` branch whose value is taken**, a **`catch` handler**, and a **block or `seq` block used as a value**. A loop body and a function's own tail were never affected and are unchanged. The fix is a three-state `Tail` - `Statement`, `Value`, `Return` - in place of the `bool`, with the rewrite allowed only at `Return`.
- **The ordering analysis was counting a `return` the emitter then deleted.** [ADR-034](docs/specification/adr/adr-034.md) D1 refuses to overlap a statement whose `catch` handler can leave the function, and `contracts::order`'s `diverts` counts any `return` anywhere in that handler. The emitter dropped the one at the handler's end - so the analysis was reasoning about a control flow the emitted program did not have. It errs safe (it refuses an overlap the program did not need, never the reverse), so no schedule was wrong; but the two halves of the compiler disagreed about what the handler did and only one of them was right. They now agree, and a test says so.
- **Six programs, run rather than read, and four of them printed the wrong answer before the fix.** `crates/nikaia/tests/returns.rs` lowers each shape, compiles it as Rust, runs it and compares the output against what the source means - because a test that only compiled the lowering would have passed, and a text comparison would only have asserted that the emitter agrees with itself. One shape's *verdict* changes: `let x = { return 1 }` used to compile, because the lowering had quietly turned it into `let x = { 1 }`, and is now an honest rustc complaint about a binding with no value. Nothing in the corpus writes it - `cargo test --workspace` on the pinned nightly and `cargo test -p nikaia --no-default-features` on stable are green at dev and release, and `tests/errors/EXPECTED.txt` does not move. What does change is `examples/json.nika`'s `longest`, whose four arms each end in a `return` and now say so; it prints what it printed.
- **No ADR is corrected, and that is the finding about the records.** [ADR-011](docs/specification/adr/adr-011.md) D2 already said "the lowering is syntactic, and never guesses a meaning", and ADR-034 D1 already said a `return` anywhere in a handler leaves the function. Both were right and the compiler disagreed with them, which [`docs/README.md`](docs/README.md) §1 calls a bug in the compiler. **Part I 3.1 was silent**, though: it said what a block's last line is worth and never what a `return` written there means, so the rule now has one sentence in the specification where it belongs.
- **The second half of §3.3 is not fixed, because it is a decision.** A method taking `key: &str` that inserts into a `HashMap[&str, …]` field is refused with `E0621` before any flow analysis. Stage 0 spells a view's lifetime by position ([ADR-011](docs/specification/adr/adr-011.md) D6), and a bare `&str` parameter is two things at once: one that will be **stored** needs `&'a str`, one that will only be **inspected** must not have it - checked, not assumed, since `'a` there is refused with `E0515` for a `&mut self` method whose caller builds the probe locally, and the same program compiles with the lifetime elided. Choosing per view is [ADR-008](docs/specification/adr/adr-008.md) D2's tether lattice, which that record says is not built. §3.3.2 states the two open questions. Separately: `E0621` is **not** among the codes [ADR-005](docs/specification/adr/adr-005.md) D7 enumerates, and its text ("add explicit lifetime `'a` to the type of `key`") names something ADR-008 D1 says the author never writes - D7's own `E0277` failure at a second code.
### Added (0.0.9 - a TextMate grammar for `.nika`, and what writing it found)

- **`editors/vscode/syntaxes/nikaia.tmLanguage.json` is one file that every current highlighter reads** - VS Code, Sublime, Zed, linguist, `bat`, Shiki and anything else on `vscode-textmate` - with a minimal VS Code extension (`package.json`, `language-configuration.json`) around it and a short [`editors/README.md`](editors/README.md). It is a **tool**: no ADR, no specification change, per [`docs/README.md`](docs/README.md)'s layering rule. Maintained by hand against both authorities and deliberately **not** generated from the parser: `crates/nikaia/src/parser/mod.rs` is a PEG with commit points, actions and recursion, and TextMate is a flat list of regular expressions with no stack - half the language cannot be expressed there at all, so a generator would have had to invent the approximation anyway.
- **The constructs that are Nikaia's own are where the work was**, and each is pinned by an assertion: `f"…"` holes as real expressions against `"…"` whose braces are braces ([ADR-035](docs/specification/adr/adr-035.md)); the `;` config zone inside a call *and* inside a signature, against a statement's `;`; `...args: Self::dsl` ([ADR-007](docs/specification/adr/adr-007.md) D5); `throws` / `throw` / `catch` / `??` as the error syntax rather than a `Result`; `sync` on either side of the return type; `fn { … }` as the one lambda form, trailing and chainable; `seq { … }` as a keyword only where a block follows it, because `examples/k-nucleotide.nika` uses `seq` as a variable; `Vec[i64]` in square brackets; `@frame(boundary: "\n", unchecked)` with `unchecked` scoped as the assertion it is.
- **A `dsl` body is foreign syntax and gets no Nikaia colouring.** `html` bodies get a small HTML written into this grammar rather than delegated to `text.html.basic` - delegating loses the holes, because once an HTML grammar enters a tag its patterns are the only ones active and `<for r in :rows>` and `class="{r.shade}"` both put Nikaia *inside* one. SQL targets are marked `meta.embedded.sql.nika`; every other target gets `:name` parameters and nothing else. `{…}` holes are enabled for `html` alone: a template's holes need no `f` because the construct is the mark, but that is the template grammar's property and in SQL a brace is a brace.
- **Tested against the reference implementation, not by inspection.** `editors/test/scope-test.mjs` drives the grammar through `vscode-textmate` itself: **143 scope assertions**, plus every `.nika` file in the repository - 55 files, 10 311 non-whitespace tokens, **676 (6.6 %) with no scope beyond `source.nika`**, every one of them a plain local or field name plus three deliberate oddities in `tests/errors/` (`G1`'s two smart quotes, `G2`'s `café`). That figure is measured with the catch-all identifier rule *removed*; with it the number is 3 of 10 314 (0.03 %) and says nothing, which is why both are reported. ### Found (0.0.9 - where the specification and the parser disagree, reported and not fixed)

- Writing the grammar meant reading Part I-III against `crates/nikaia/src/parser/mod.rs` rule by rule. **Eleven entries' worth of construct that the specification defines have no rule in the parser at all** (the table is in [`editors/README.md`](editors/README.md)): `trait Name { … }` (Part I 4.7 - `impl Summarize for User` parses, the trait it implements cannot be declared); the list literal `[1, 2, 3]` (Part I 4.5, already recorded in [`docs/error-corpus.md`](docs/error-corpus.md) as the reason `tests/errors/A4.nika` reports `expected expression` at the `[`); `macro` / `quote` / `struct … with …` (Part II 10.3-10.4); `const` (Part II 10.2, which is what makes a `dsl … from …` run at compile time, so the compile-time half of dual-mode parsing has no syntax); `select` (Part II 12.4); `test` / `bench` / `assert` (Part III 14); `extern "C"` / `unsafe` (Part III 15.1); `null` and a nullable type `String?` (Part I 2.3 - while `??`, the operator for handling null, *is* implemented); `?.` (Part I 3.5); `use a::{b, c}` (Part II 10.5); and `{ line, .. }` in a `match` pattern (Part I 7.1, so a `match` over an error type cannot bind some fields and ignore the rest).
- **Three disagreements about the *shape* of a construct, where both sides wrote something.** (1) **`spawn`**: the specification writes `spawn fn { … }` in five places including `NK2101`'s own `help:` text, and the parser is `"spawn" "(" expr ")"` - and `spawn fn { … }` does not fail, it parses as a variable `spawn` followed by a lambda, so the program means something else. (2) **`throws` with a type**: Part I 7.1 states that `throws` names no types and the parser agrees, but Part I 6.4 writes `fn cleanup(&mut self) throws IoError` and so does `NK2601`'s help text - the specification contradicts itself, and the parser follows the sentence rather than the examples. (3) **A string literal spans lines**: `STR_CHAR`'s `any` matches a newline, so an unterminated literal runs to the next quote or to end of file; the specification says nothing either way, and `tests/errors/F1.nika` is that case.
- **And two silences worth writing down.** A comment is `"//" until(line_ending)` and nothing else - no block comment, no doc comment, and Part I never says. And a numeric literal is `digit1` or `digit1 "." digit1 EXPONENT?`: **no digit separators, no radix prefixes, no suffixes**, in either the specification or the parser - so `1_000`, `0xFF` and `1i64` are each something other than a number.

### Built (0.0.9 - ADR-002 D4: a project reaches `std` through a sysroot, and stops building the compiler twice)

- **58 of a hello-world's 97 resolved packages existed only to *build* `nikaia-std`**, `clap`, `anstream`, `toml`, `sha2`, `bridge-ir`, `bridge-orchestrator` and `nikaia` itself among them. The cause was [ADR-014](docs/specification/adr/adr-014.md) D1's *when*: `std` lowered its own `.nika` files in a build script, so it had the compiler as a **build-dependency**, so Cargo compiled the compiler library again *inside the project's `target/`* - while the installed compiler was running and doing that very lowering. A duplicate build, per project, for ever, and 29 s cold for a program that prints one line.
- **`std` ships as sources with its Nikaia half pre-lowered, and the measurement closes.** Re-measured where the fix was built: **103 packages to 46, the 58 to 1, 79 units compiled to 38, 25.8 s to 16.0 s.** The 58 reproduced exactly on a second machine five months of version drift later, because it is a property of a dependency edge and not of a registry. The 1 that remains is `version_check`, an honest build script of a crate `std` itself depends on; `nikaia`, `clap` and `sha2` are asserted absent by a test rather than by reading a lockfile once. `crates/nikaia-std/build.rs` and its `[build-dependencies]` are gone, and a test fails if either comes back.
- **A from-source install may re-lower, through the `nikaia` binary and never by linking the compiler as a library.** `nikaia lower-std` is that command. The linkage was the defect, not an implementation detail of it - so one artifact serves a binary install (compile the `.rs`) and a from-source one (re-lower if you want to), which is the point: the alternative is two release pipelines that can disagree.
- **Built locally into an rlib cache, and the second project on a machine does not rebuild `std`: 1.65 s and one crate compiled, against 16.0 s with the cache switched off.** The key is the one [ADR-021](docs/specification/adr/adr-021.md) already has - the compiler's own fingerprint (D3) and the toolchain - plus the `target` and the **codegen flags**, named in `Key::sysroot` beside `Key::build` for D7's reason. Codegen is in because **hardware optimisation is the one axis where `std` matters more than the compiler**: `std`'s code runs inside every user program, where the compiler's own speed only costs build time. So `-C target-cpu=native` is a *dimension* that coexists rather than a reason to rebuild the other entry. Asserted by the rlib's modification time, not by an absent "Compiling" line, which would only say Cargo was quiet.
- **Three plausible dimensions are deliberately out, and one of them looks like an omission.** `user_parallelism`, because the switch reaches `std` as a runtime value - `UserCode::Sequential` handed to `rt::start` in the generated `fn main` - and never as a `cfg` or a feature; verified, and it still holds (`nikaia-std` declares no features, and every `cfg` in it is `target_os`). `ordering` and the lowering backend, because they decide what a `.nika` file lowers to and `std`'s Rust is not lowered by a project's build at all. And the **content hash of the `std` tree**, because what the key names is a directory and Cargo's own fingerprinting already owns what is stale inside it: hashing the tree too would start a fresh directory for every edit to `src/fs.rs` and rebuild everything under it (38 units, 16 s) to guard against a staleness that cannot occur - D7's "too much" direction.
- **What was an accident is now a promise, and it is checked.** `std`'s Nikaia half was lowered at `Build::default()`, hardcoded, so always at `user_parallelism = no` whatever the consuming program was built at - and **nobody had decided that**. It is decided now, as a constraint: lowered once, at one setting, sound only while nothing switch-sensitive appears in those files. `Shared` is exactly what would break it ([ADR-037](docs/specification/adr/adr-037.md) D3 makes it `Rc` at `no` and `Arc` at `yes`, and that question is still open). Every `.nika` file in `std` is lowered at both settings and the bytes compared, so the day one arrives it is a red build rather than a `std` that cannot cross a thread inside a program that may.
- **The pre-lowered `.rs` is committed, and the tie was broken by a constraint rather than by taste.** Both ways cost something - a generated file in a reviewer's diffs, against a release step that must not be forgotten. What decides it is that `cargo test --workspace` must work from a fresh checkout with no extra steps, and at that moment the only mechanism that could produce a missing `.rs` in time is the build-dependency this removes. So committing is not the convenient option, it is the only compatible one; and the cost is paid by making the file unable to lie - a test regenerates it with the compiler, compares bytes, and names the command that fixes a drift, the same standard [ADR-005](docs/specification/adr/adr-005.md) D8 sets for the ledger.
- **`std.contracts` stays inside the compiler** (`include_str!`), and the compiler answers from that copy and never from the sysroot. ADR-005 D8 makes ledger stability across toolchain versions explicitly *not* required, so a `std` that could be paired with a different compiler would let the ledger describe a compiler that is not there. The sysroot's copy is the source it was built from, and a test requires the two to be equal.
- **`NIKAIA_SYSROOT` replaces `NIKAIA_STD_PATH`**, named for what it is: the old name said *crate directory*, and a crate directory can answer only one of the questions this mechanism has. The two runtime versions a generated program may name (`winnow-grammar`, `winnow`) are baked into the compiler by its own `build.rs` instead of read from `[workspace.dependencies]` at run time - a sysroot is not a Cargo workspace and has nothing above it, and these are the emitter's versions anyway.
- **Two prices, named.** The compiled `std` lives in the user's cache directory and not under `target/`, because shared-between-projects is the whole of what it is for - so `rm -rf target` no longer gives a cold build, and ADR-021 §3's owed eviction policy now has a second store to cover. And two builds sharing an entry serialise on Cargo's lock on that directory, where two projects with their own `target/` did not.
- **Not built:** the packaging step that produces a sysroot outside a checkout. The layout is decided - a directory with `nikaia-std/` in it, which is why `crates/` *is* a sysroot and the in-tree flow needs no special case - but `nikaia-std/Cargo.toml` still spells its shared dependencies `{ workspace = true }`, so a copy of it outside this workspace does not resolve. Method, machine and the full list of 58 in [`docs/std-sysroot.md`](docs/std-sysroot.md).

### Decided (0.0.9 - four things that had been left to a later reader)

- **`seq` is the keyword, settled.** ADR-033 D7 wrote it down as a placeholder for "a word chosen later", and Part I 8.1.1 warned that a program written today might have to be renamed. It is kept: a second round of naming a block almost nobody writes buys nothing, and it already reads as *"in this order, whatever you think"*. The warning is gone from the specification.
- **The runtime configuration file is `nikaia-runtime.toml` in the working directory**, with `NIKAIA_RUNTIME_CONFIG` naming one outright for a binary serving several machines. ADR-038 D5 named the four settings and said "read at startup" and nothing else, so the implementation had chosen a name under protest; it is decided now, with the keys spelled as `nikaia.toml`'s are because a person who has written one of the two files has already learned the convention.
- **`stdout` and `stderr` are compared as one destination**, confirmed. They are two handles and one file the moment anybody types `2>&1`, which is why `println` / `eprintln` / `println` interleaved differently on every run of a redirected program. `seq` is what a program writes where the permissive reading would have been wanted.
- **Standard input belongs to the readiness half of ADR-038 D3**, and stating it that way turns the rule the right way round: a pipe, a terminal and a socket all signal readiness honestly, and a read on one blocks only while there is nothing there. **A regular file is the exception** - always "ready", and the read blocks in the kernel anyway. So it is not "files and sockets" but "a regular file completes, everything else signals".
### Built (0.0.9 - ADR-005 §1 Group B: the structural `Send` check, `NK2501` and `NK2502`)

- **Three records relied on a check that was not in `crates/`.** [ADR-005](docs/specification/adr/adr-005.md) §1 Group B decides it, Part III C.3 reserved `NK25xx` for it, and [ADR-037](docs/specification/adr/adr-037.md) §3 and [ADR-038](docs/specification/adr/adr-038.md) D7 both rely on it. The only `Send` in the workspace was a trait bound inside `nikaia_std::task::both`. It is built now - `crates/nikaia/src/contracts/send.rs` walks a type structurally and transitively, through a container's arguments and through a `struct`'s `fields` as the ledger records them, and terminates on a type that holds itself.
- **It is built *before* `Shared`, and that ordering is the whole point.** Today's silence costs nothing only because Nikaia has no value that may not cross a thread: `Shared` is unbuilt, so every value a program can construct is crossable, and `rustc` has had nothing to refuse. `Shared` at `user_parallelism = no` creates the first one, and a program handing it to a foreign call would then be **accepted at `yes` and refused at `no`** - the exact asymmetry Group B, `NK25xx` and ADR-037 §3 were all written to prevent - with a raw `E0277` as the only signal.
- **One verdict at both settings, and the check never sees the switch.** A value may cross a thread only if it may cross **any** thread, so a type whose expansion is safe at one setting and not at the other may not cross at either. What the switch decides is the *severity*: at `no` nothing the program wrote runs concurrently, so a crossing into a task does not happen in that build and `NK2501` is a **lint** there rather than a refusal - which is what Part III C.3 asked for, and refusing would have refused a program that compiles. `NK2502` is an error at both, because a Rust dependency's own threads are not bounded by a switch about *your* code (ADR-037 D2's load-bearing "user"). A test runs one program at both settings and compares the verdict rather than the exit code.
- **Fail-closed, with three answers and not two.** A type may cross, may not, or **nothing written down says** - and the third is not the first. Reading the absence of an answer as permission is the polarity [ADR-010](docs/specification/adr/adr-010.md) D1 forbids; refusing on it would reject correct programs, which Part III C.4 says the compiler may never do. So what the two non-yes answers cost depends on who chose the crossing: a crossing the **compiler** chose (the `task::both` of statement overlapping) is simply not taken, which costs speed and never a program - ADR-033 D4's own polarity; a crossing the **program** wrote is refused where it can be decided and handed to `rustc` where it cannot, and `rustc`'s refusal now arrives against the `.nika` line.
- **Where the crossings are, and which are covered.** `task::both` (the result of each overlapped operation crosses back, and the captures are empty by construction today); `spawn` (`NK2501`, reported ahead of the emitter, which cannot lower one yet); a value handed to a call this compiler cannot see the end of (`NK2502`, ADR-038 D7's foreign runtime). **A scope's tasks are not covered**: `task::scope` has no syntax in the grammar and no AST node, so there is nothing to check.
- **`crosses = true` is a new ledger key on a type, and it had to be.** A Rust type records no `fields`, so the structural walk answers "nobody said" about `cli::Args` - and that is not permission, so the ten overlapping pairs ADR-033 §8.1 bought with a `touches` line would have gone again. The key is a promise about a body this compiler does not read, written in `std.contracts` and reviewed like code, exactly as `sync = true` on a Rust function is. Its absence stays "nobody said" and never "it may not". Measured: that one line is the difference between the corpus's overlapping surviving and not.
- **The rule reaches only as far as a foreign crate is honest, and ADR-038 D7's first rule now says so** rather than leaving it to be discovered. `examples/foreign-runtime/smuggled` puts a plain reference count on a foreign worker thread through an `unsafe impl Send` that lies, and no frontend check can catch it: where Nikaia can see the value it is crossable *by declaration*.
- **Not decided here, because no record decides it:** if the choice between the two reference counts stays per build (ADR-037 D3 leaves it open, in as many words), then a `Shared` may not cross a thread **at all** - because the verdict may not depend on the build - and Part II 12.2's shared counter is the program that wants to. That has to be answered before or with `Shared`. It is recorded in ADR-005 §5.3 and ADR-037 §3 and nothing was invented for it.

### Fixed (0.0.9 - ADR-005 D7: the project build handed Cargo's stderr to the terminal)

- **`nikaia build` had no diagnostic interception at all**, so every backend error reached the user as Rust about `target/nikaia/gen/….rs` - a file the build wrote and the author has never read. Part III C.1's Iron Rule calls that a bug in this compiler, and the mapping that fixes it had worked since [ADR-012](docs/specification/adr/adr-012.md): it was only reachable through `--explain`, which reads `rustc --error-format=json` on standard input. The channel was what was missing. `cargo --message-format=json` is it - every `rustc` diagnostic arrives on stdout as one JSON object per line, and `diagnostics::translate` now reads them there.
- **`E0277` joins the classes ADR-005 D7 enumerates as translated.** All seven it named - E0382, E0499, E0502, E0505, E0506, E0597, E0716 - are borrow, ownership or lifetime errors, and a trait bound is how `Send`, `sync` and every future marker rule surfaces from the backend. The list was short by one class, and the ADR-038 D7 experiment is what found it.
- **The position is translated and the text is not, and the split is recorded rather than glossed.** ADR-012 deliberately does not rewrite a message, because the lowering is name for name and "`xs` does not live long enough" is already a sentence about the Nikaia source with only its place wrong. That argument **fails for a trait bound**, whose every noun is a Rust type the author did not write. So the caret lands in the `.nika` file and the sentence is still Rust's; the gap is closed from the other end, by the frontend refusing in Nikaia words what it can decide. Rewriting a trait-bound message is a second question and is named as open in ADR-005 D7.
- **`nikaia run` is now a build and then a run**, because `--message-format=json` can only be read where stdout is not the program's. The build's diagnostics are read; the run inherits stdio as before and is a no-op rebuild - the same shape the lowering already had, where the work happens once and the decision is made where it can be reported. Cargo's stderr is still inherited, so its progress and anything it says that is *not* a `rustc` diagnostic - a manifest it cannot parse, a dependency it cannot resolve - still reaches the user; a build that failed in silence is the one outcome worse than an untranslated error.
- **The source map already knew which file**, and nothing had asked. A program is however many `.nika` files its entry reaches, joined into one Rust file; the map has carried the unit index since that was true, and until the project build started reading these messages a diagnostic about the third module would have been printed against the first module's text.
### Built (0.0.9 - ADR-033 D10: two operations in flight is not two pieces of your code running)

- **`ordering = "effects"` means something at `user_parallelism = no` now.** A pair of adjacent `std` file reads lowers onto `nikaia_std::task::read_pair` - two operations the **kernel** performs while the program is suspended at both of them, with `std` doing the waiting. [ADR-033](docs/specification/adr/adr-033.md) §8.2b made `effects` degrade to `strict` there, on a reason that was correct at the time: overlapping meant two user closures on two threads, and at `no` nothing you wrote may run concurrently ([ADR-037](docs/specification/adr/adr-037.md) D2). [ADR-038](docs/specification/adr/adr-038.md) D3 and D4 built a vehicle that carries no code of yours at all, so what degrades at `no` is `task::both` and not the ordering. §8.2b's *category distinction* - whether two operations may overlap is a question about the program, whether a vehicle exists is a question about the build - is what the new decision rests on; only its conclusion is narrowed, and it is narrowed by a **new numbered decision** rather than by an edit.
- **One question became two, because it always was two.** `Build::overlaps_user_code()` answered *may two pieces of the program's own code run at once* (`yes` only, and it still gates `task::both`) and *may two operations be in flight at once* (**both** settings) with one boolean. They are two methods with two names now, and `contracts::order` gained the half that is about the program - which vehicle a pair would need - while still seeing no build switch. The word `user` in `user_parallelism` is what the whole change turns on, and this is the first place it pays for itself.
- **Measured end to end, not just at the `std` surface:** a `.nika` program lowered twice from one source, 200 000 pairs a run, nine repeats, both of ADR-038 D3's mechanisms. **−0.87 µs a pair** (sd 0.14) on the completion path against **+112 µs** for `task::both` on the same box the same hour - which is why a pair of reads gets this vehicle at `user_parallelism = yes` as well. Method, machine and load average in [`docs/runtime-cost.md`](docs/runtime-cost.md) §6; `benches/overlap/lowered.sh` is the script.
- **And the re-run is the finding, which outranks the feature.** The same binary that produced ADR-038 §4.3's table measures `join - seq` at **+112 µs where §4.3 records +59 µs**, and `both - seq` at −0.98 µs where it records −0.25 µs - every figure 1.4 to 1.9 times larger, the baseline included, on a shared virtual machine a day later. The end-to-end number agrees with that same-day control, so there is no cost hiding in the emitter; what there is instead is a bound on how far an absolute microsecond from these notes travels. Every *conclusion* §4.3 drew reproduced exactly, because each one is a sign, a flatness or a ratio rather than an absolute.
- **Where the machine has no `io_uring`, the pair is performed in the order it was written**, and that is a decision rather than a fallback. The blocking path *can* overlap a pair and charges ~38 µs to do it (~54 µs on the box above) - the fixed per-pair tax ADR-033 §8.2 measured and called a pessimisation, which cannot be predicted from the source because the payload is not in the source. So an overlap the compiler chose is taken only where it is free: measured at −0.05 µs a pair, against +54 µs for `fs::read_both` through the same mechanism. `fs::read_both` is left exactly as it was - it is what a *program* asks for, and a program may know the payload. The cost is named: at `user_parallelism = yes` on a machine with no completion queue, two reads of a quarter megabyte or more lose an overlap they had.
- **`--overlaps` answers per pair.** One note at the top saying which setting made the report hypothetical was true while the answer was the same for every pair; at `no` it is not, and a report that cannot say *why not* is the trap D9's refusals exist to keep open to a question. A pair the program allows and the build cannot carry now prints `would` with the switch that decided it, beside the `together` of one it can.
- **The corpus does not move, and the table is worth printing for that.** The same 127 adjacent pairs in `examples/`, the same seven refusal reasons, the same counts - and now the same counts at *both* settings, because no pair in those eleven files is a program-level overlap at all. The zero was never the build's doing, which is precisely what §8.2b's degradation made impossible to see from the report. The one pair in the repository that moves is the control of `examples/foreign-runtime/overlaps.nika`, which ADR-038 D7's experiment put there for this purpose and which now overlaps at `no` with no `task::both` anywhere in the program.
- **Not built with it:** two *writes* in flight (no pair vehicle, and ADR-038 §4.3 measured reads); an n-ary completion run, so three disjoint reads at `no` overlap their first pair and leave the third where it stands; and a pair where either half is a method call, for §8.1's standing reason. One thing found while measuring and left for the owner: a Nikaia project has exactly one profile, so a lowered program always runs with `debug_assertions` on, where every number in these benches is `--release`.

### Fixed (0.0.9 - ADR-027: an asserted `sync` survived a call nothing could resolve)

- **A `sync` a source asserted was kept even where the body called something no ledger knows**, and the ledger that ships recorded `sync = true` for it. ADR-027 D2 makes the *inference* conservative in the restrictive direction and D4 says an **assertion** is never overwritten by the inference - so the two together left the assertion standing, and a consumer's `par_iter` body would have believed it. `sync` gates `access`, `access_all`, `par_iter`, a scope's tasks and the panic hook, so this is the gate on every safe concurrency primitive Chapter 12 has.
- **The permissiveness was bought with a diagnostic and was buying nothing.** The check returned no violation for an unresolvable call because `NK2202` wants a caret on the call and the type checker answers per function. But Part III C.2 reports this checker at *statement* granularity already, which is a position - so the caret was available all along, and the polarity ADR-010 D1 exists to protect was being paid for it.
- **A method call stays permissive there, and that is a different case**, not the same hole: the type checker resolves one (ADR-028) and the inference merges its answer in per function, so the claim is still taken away where it has to be. A test pins that too, so the fix cannot later be read as making every unresolved thing an error.
- **Found by the ADR-038 D7 experiment.** A `sync` function calling into a foreign crate is exactly this shape, and a foreign crate has no contract by definition.

### Built (0.0.9 - ADR-021 D2: the lockfile records what Cargo resolved, and the bridge compiles at 2021)

Until it did, the one file whose job is to answer *does this build the same thing for you as for me?* answered it **only about the Nikaia half** - source hashes, toolchain and compiler fingerprint, and not a word about which `regex` was linked.

Nothing absolute goes in. Nothing is written when the versions are unchanged, so a committed file does not turn up modified after a build that changed nothing about it, and a failure to write it warns and leaves a finished build alone (D12).
- **The bridge backend compiled its printed crate at Rust edition 2015.** `rustc-executor` passed `rustc` no `--edition`, while the crate had been interned and printed for 2021 - the edition the emitter writes and the edition every test of the `rust` backend compiles at. It is a mismatch and not a choice: D2 makes the printed text a *view* of what is compiled, and this was two statements of one fact with one of them missing. Both now read a single constant.
- **The edition change was verified inert rather than assumed inert.** The printed crate and the compiled binary are byte-identical before and after (`sha256` `01455af3…` and `a474e629…` on `hello_world`), and `crates/nikaia/tests/bridge_backend.rs` compiles the same printed text at 2015 *and* at 2021 and compares what the two binaries print. D10 fixes what it would have to mean - *do not re-resolve* - and nothing passes it to Cargo; today the flag is the ledger's regenerate-and-compare. Recording the resolved versions needed no answer to that, and none was invented.

### Built (0.0.9 - ADR-033 §6: the rest of the "not built" list)

- **A run of statements of any length overlaps, not a pair.** Three independent reads used to be a pair and a leftover, which is one thread wake-up more than the work needs - ~46 µs each, and that is the whole of what the overlap has to spend (§8.4). A group of *k* lowers to *k-1* nested `task::both`, so the vehicle is unchanged and the next change of vehicle is still a `std` change.
- **The safety argument is that disjointness is not transitive**, and this is the one place where believing it would be a soundness hole rather than a missed chance. `read("a") / read("b") / write("a")` has two disjoint *adjacent* pairs and is not a disjoint run; in a group all three run at once, so a chain of adjacent answers would have overlapped a read of a file with the write of it. Every pair `(i, j)` with `i < j` is asked about, and a group is the longest **prefix** that passes - leaving a statement out of the middle would reorder the ones after it past the one left behind.
- **D6 needs nothing extra from a group.** Members that meet on nothing cannot observe one another; an accountable operation either cannot fail or catches its failure into a value (ADR-034 D2 refuses the rest); and `rayon::join` propagates the *first* closure's panic when both panic, so nesting to the right surfaces panics in written program order by construction rather than by luck.
- **`seq { … }` is built** (D7): the statements inside keep the order they were written in whatever their touch sets say, and that reaches *inward* through every block, `if` and loop written inside it. The block keeps its own place too - the fail-closed answer and the only one D7 decides. It is an `Expr` variant and not a flag on a block, for the reason `LitInterpolated` is a variant: a flag is what an analysis walks past, and stopping a reordering is the one thing this construct is for. **The keyword is provisional**, as D7 says of itself; Part I 8.1.1 now says so where a reader sees it, and the word is still the owner's to pick.
- **The touch vocabulary grew by what the corpus asked for, and by nothing else.** `cli::args` reaches `args read` - it was the most-refused callee in `examples/` at ten adjacent pairs - and `String::new`, `Vec::new` and `html::escape` reach nothing and now say so. The kinds are a closed list now and a word outside it is answered the way D4 answers everything it cannot read: the function reaches everything and keeps its place. A test asserts every kind in `std.contracts` is one the compiler knows, because that refusal is silent by design.

They are compared as one destination now; it costs nothing measurable (console writes are microsecond work, which §8.4 says the overlap cannot pay for whatever carries it) and it buys back the guarantee. The refusal names `seq` as the way out.

### Built (0.0.9 - ADR-038 D3, D4 and D5: the runtime foundation)

- **The runtime starts before `main`, and `fn main` is now the runtime's.** The emitter renames the program's own entry point to `__nikaia_main` and writes the `fn main` Rust runs: `rt::start`, the program, `finish`. [ADR-038](docs/specification/adr/adr-038.md) D4's reason is that an I/O thread already running costs nothing per operation where one started per pair costs a wake-up per pair - the whole of [ADR-033](docs/specification/adr/adr-033.md) §8.4's finding. A generated wrapper rather than a link-time constructor, because ADR-006 D5's drain has an outcome to report and an `.init_array` entry has nowhere to put one. Only the plain shapes - `fn main()` and `fn main() throws` - are wrapped; a `main` the wrapper cannot type keeps its own name rather than being guessed at.
- **What starts is what `user_parallelism` allows, and the compiler is what says so.** At `no`: the I/O workers, and everything the user wrote on the main thread. At `yes`: a pool for user code as well. It is written into the generated call because it is a *build* switch - ADR-038 D5 has four operating settings and this is deliberately not one of them (ADR-037 D2).
- **Files complete, sockets signal readiness, both behind one `std` surface.** `nikaia_std::rt` is D3: `io_uring` for `fs::read`, `fs::read_to_string`, `fs::write` and the new `fs::read_both`; a poller over `epoll` for a socket's readiness; and the blocking path on an I/O worker as the fallback. `fs::map` is untouched - it hands back pages the OS owns and there is no transfer for a completion queue to report. Nothing about any of it reaches a `.nika` file, which a test now asserts over the whole corpus rather than promising in a comment.
- **Feature-detected at run time and never at compile time.** A binary built on a machine with `io_uring` runs on one without it: the probe is `IoUring::new` answering `ENOSYS` on an older kernel or `EPERM` in a sandbox. The only compile-time gate is on the bindings, which do not exist off Linux at all. `crates/nikaia/tests/runtime.rs` forces **one compiled binary** down every route - detected, `blocking` pinned, one worker, two workers, `uring` pinned - and asserts it prints the same thing and writes the same file each time.
- **The I/O thread is the compiler's, and the *types* say so rather than a comment.** A worker's inbox is a channel of `Op`, a closed enum private to `nikaia_std::rt`, and no variant carries a closure or a `Box<dyn FnOnce>`. Outside that module there is no way to name a value the channel accepts, so ADR-037 D2's promise that nothing the user wrote runs concurrently at `no` is a property of the code and not a convention review has to keep. A `debug_assert` closes the other direction: no `std` I/O entry point is ever *on* a worker.
- **The io_uring buffer rule, met by one sentence: a slot and its buffer are freed only by the code that has reaped its completion.** The buffers live in the runtime's ring, not on any caller's stack, so an unwind cannot drop one the kernel holds; a slot is released on an outstanding-submission *count* rather than on a return; and the next operation reconciles the ring before it submits. What the language contributes is that there is never a borrowed buffer to hand over - `fs::read` returns owned bytes, so `std` allocates, moves in, and moves out (ADR-005, ADR-008's tether lattice).
- **`nikaia-runtime.toml`, read at startup: four settings and no fifth** (D5). `io-workers` (default 1), `user-pool` (default 0 = as many as the machine has), `io-method` (default `auto`, pinnable) and `cleanup-deadline` (default 30s, `0` disables draining). A key outside the four is a typo and fails, the same rule `[build]` follows. Pinning `uring` where there is none is a **failure to start**, not a silent fallback - the point of pinning is to find out. `NIKAIA_RUNTIME_CONFIG` names the file for one binary in several deployments. Hand-written reader rather than a TOML crate: `nikaia-std` is linked into every program this compiler produces, and four `key = value` lines are not worth a parser in every one of them.
- **`cleanup-deadline` has moved out of `nikaia.toml`.** How long a program waits at exit is an operating property, and a build-time key cannot be tuned by the operator - who is not the person who compiled it (D5). The manifest **still accepts it** and prints where it went, because refusing it would fail a manifest somebody wrote to the specification that documented it. Part III gains 13.3b for the new file and 13.3 loses the key.

### Measured (0.0.9 - ADR-038 §4.3: a pair of operations costs nothing, and only on one of the two mechanisms)

- **ADR-033 §8.5's prediction is confirmed: `fs::read_both` on the pre-started runtime adds nothing per pair.** −0.25 µs at 5 bytes a file, −0.48 at 4 KiB, −0.61 at 64 KiB, −0.86 at 256 KiB, each with a spread that straddles zero. The same two reads through `task::both` add **+59.2 µs** (sd 1.4), which reproduces §8.4's 46 µs and is higher for a stated reason: `fixed` timed a pair with nothing in it, and here the stolen closure's wake-up sits on the critical path of real work. §8.5's "none in principle" is "none, measured".
- **And the finding nobody predicted: the fallback does not inherit that zero. It pays ~38 µs a pair**, flat - 37.87, 37.72, 37.32 µs at 5 bytes, 4 KiB and 64 KiB, sd under 2.5 throughout. A fixed cost that does not move with the payload is a wake-up. So **"the runtime starts before `main`" is necessary and not sufficient**: D4 removes the thread *start*, and only D3's completion path removes the thread. ADR-038 §1's "that pool *is* the 46 µs" was an argument from the literature and is now a measurement of this repository's own fallback.
- **The crossover is where ADR-033 §8.2 put it.** On the fallback the pair turns profitable between 64 KiB (+37 µs) and 256 KiB (−78 µs) - the same quarter megabyte, found again by a different vehicle on a different mechanism. The completion path has no crossover, because a fixed cost of zero has nothing to amortise.
- Nine repeats of 20 000 pairs, 4 vCPU, load average 1.5-2.1 and printed beside every table, both of D3's mechanisms measured rather than one measured and one assumed. **One confound is named rather than hidden:** the two mechanisms' sequential baselines are not comparable to each other (894 µs against 401 at 1 MiB), partly because `std::fs::read` reallocates a megabyte to find end-of-file where the ring path does not - and nothing in the conclusion compares them, since every number it rests on is a difference *within* one mechanism. Method, machine, every repeat and the confound: [`docs/runtime-cost.md`](docs/runtime-cost.md), produced by `benches/overlap/runtime.sh`.
- **Left undone on purpose, because it is another record's decision.** `fs::read_both` exists, is measured, and no lowering uses it: at `user_parallelism = no`, `ordering = "effects"` still degrades to `strict` (ADR-033 §8.2b). §8.5 gave that degradation three reasons - no event loop, no sidecar, no async lowering - and two of them are now gone. Whether a statement pair may be lowered onto a completion-based pair is **ADR-033's** question, and answering it inside ADR-038's delivery would be deciding another record's business.
- **Two focused dependencies, named so the decision is reviewable:** `io-uring` 0.7 (Linux-only bindings, no runtime, no executor) and `polling` 3.11 (`epoll`/`kqueue`/IOCP, no task model). Neither brings an opinion about what a program does when I/O is ready, which is what would have re-decided D1 and D3 by the back door - and `tokio` and `hyper` are still absent.

### Decided (0.0.9 - ADR-038: the runtime and the HTTP server are ours)

- **`tokio` was never decided, only repeated.** It appears in a parenthesis in ADR-018 §3 and as a roadmap checkbox, and three records wait on "the runtime binding" without one of them saying what it is. [ADR-038](docs/specification/adr/adr-038.md) decides it, with the argument against written down so the question does not come back.
- **The HTTP server is Nikaia's own, and `hyper` is not adopted.** A finished server has to be handed I/O it can *ask* data from; `io_uring` reports data instead, and bridging the two costs a copy through an intermediate buffer that spends most of what `io_uring` was for. Adopting one does not postpone the I/O decision - it makes it, for sockets. The positive reason is bigger: an HTTP request is a byte grammar with a frame boundary, which is what ADR-009 exists for, and it is the one real program that exercises ADR-010's untrusted input and ADR-017's escaping contract.
- **I/O is split by kind, because the two halves have different answers.** `epoll` cannot read a file at all - a regular file is always "ready" and the read blocks in the kernel anyway, which is why every readiness-based runtime serves files from a thread pool, and that pool *is* ADR-033 §8.4's 46 µs. So: `io_uring` for files where the machine has it, readiness for sockets, both behind one `std` surface so the next change of mechanism is a `std` change.
- **The runtime starts before `main`.** An I/O thread already running costs nothing per operation; one started per pair costs a wake-up per pair. At `user_parallelism = no` that is all that starts - the I/O thread is one of the compiler's threads and was never bounded by that switch (ADR-037 D2).
- **Tuning is a runtime configuration file read at startup, not a manifest key.** A build-time value cannot be tuned by the operator, who is not the person who compiled it. Four settings and no fifth, with the I/O method defaulting to `auto` and pinnable - the shape `--ordering strict` already has. `cleanup-deadline` moves there from `nikaia.toml`, where Part III 13.3 had put it: how long a program waits at exit is an operating property.
- **`std::http` promised "production-ready HTTP/1.1 and HTTP/2" with no status note**, which is the kind of promise `docs/README.md` calls a defect. It carries one now.
- **A Rust crate may bring its own runtime, under two rules.** A value crosses into a foreign thread only if it may cross any thread (at `user_parallelism = no`, `Shared` is `Rc`), and a `Cleanup` may not be owned by a foreign task (ADR-006 D3 parks it with *our* runtime, and a foreign shutdown will not drain that queue). What needs no rule: a foreign crate has no `touches`, so it reaches everything and orders against everything - fail-closed polarity means interop cannot silently break ADR-033, only make programs slower.

### Fixed (0.0.9 - ADR-033: a `catch` handler's effects were not counted)

- **A handler that wrote a file the next statement read overlapped with it, and raced.** The analysis looked *past* a `catch` at the call it guards, so the handler's own effects never reached the statement's touch set - D1's guarantee broken by an effect nobody counted. A handler is code that runs, so what it reaches counts; where it cannot be read, D4 answers as it answers everywhere else.
- **Closing it found the real gap, and it was in the ledger.** Refusing every handler whose effects cannot be read would have retired the increment, because `catch { "".to_string() }` is a method call and *which* ledger entry a method call is needs the type checker (ADR-028). A weaker question does not: **if every `::to_string` in the ledger reaches nothing, then `"".to_string()` reaches nothing whatever its receiver is.** An over-approximation over the candidates, in D4's direction, and it needs no type checker.
- **`println` had no ledger entry at all.** ADR-033 D2's own table names it (`println(x) touches stdout write`) and D6 rests on it - two `println`s stay ordered *because* both touch `stdout`, not by a special case. Unentered, they were ordered by ignorance: the right answer for the wrong reason, and not the right answer any more as soon as something else is in the pair. `print`, `println`, `eprint`, `eprintln` and `str::to_string` are entered now.
- Two regression tests, one per half: a handler that writes stdout next to a `println`, and a handler the walk cannot read.

### Built (0.0.9 - ADR-033 §8.3 item 1: the ordering analysis sees more than one shape)

- **`--overlaps` weighed 127 pairs across `examples/` and refused all 127, and 101 of those refusals were the analysis's own narrowness** - "one of them is not a `let` of a single call", decided before any `touches` set was consulted. ADR-033 §8.3 says widening the shapes comes before any conclusion about whether `ordering = "effects"` earns being the default, because a zero produced that way measures the analysis and not the corpus. It is widened.
- **A bare expression statement is now an operation.** `println(x)`, `fs::write(p, d)`, `out.push(y)` - an operation the ledger can account for that binds nothing. A pair where neither half binds lowers to a `task::both` statement rather than to `let (_, _) = …`, which would be a pattern that says nothing.
- **A `let` whose initialiser is not a bare call is now weighed**, and its touch set is the **union** of every call in it: `f("a") + g("b")` performs two operations and is compared against the statement next to it on both. Values are taken apart where they are built out of literals and calls - arithmetic, a cast, a tuple - and refused everywhere else, each refusal naming what it was.
- **An assignment stays out, and that is a rule rather than a gap.** `x = 1` changes a name without binding one, so the data-dependency test - does the later statement mention what the earlier one bound - would find nothing to compare. A shape whose dependencies the analysis cannot see is a shape it may not read.
- **A correctness fix the widening exposed: an uncaught failure keeps the order** (ADR-034 D2). If `fs::write(p, d)` fails, the failure leaves the function and the sequential program never performs the statement after it - so starting that statement early performs work the program as written might never have performed. The narrow analysis reached this case and did not refuse it; a bare expression statement is what makes it ordinary.
- **The report no longer promises an overlap the emitter will not make.** A value-returning body ends in its value (Kap 3.1) and a pair hands back a tuple, so the last statement is never half of one. Reading only `let`s hid this, because a `let` cannot be a block's value.
- **Measured again: the same 127 pairs, the same zero, and eight named reasons instead of one.** 30 a method call (whose ledger entry depends on its receiver's type - ADR-028's mechanism, not this one's gap), 29 no operation at all, **28 nothing says what the callee reaches**, 13 ADR-034's conditional handler, 10 a `??`, 9 something with its own control flow, 6 the function's own value, 2 a written type. The load-bearing row is the third: **D4's fail-closed polarity doubled, from 14 pairs to 28**, because the shapes were hiding it. The zero is now a statement about the programs - microsecond work written in method calls - and §8.4 already says the overlap could not have paid for it either way.
- **Corrected: a data dependency through a `catch` handler was invisible.** `f("a") catch { … }` is one expression, but `mentions` was collected only from the call's arguments - so `let b = fs::read(…) catch { a }` after `let a = …` saw no dependency on `a` and overlapped, and the closure would have read a name the same `let` had not finished binding. The handler's names count now, including the words inside an `f"…"` whose holes are unparsed, and `names_in` is total - no `_` arm - because a variant walked past silently is a dependency the analysis cannot see, the one direction it may never fail in.
- **Not done, and deliberately not guessed: an argument that is not a literal.** A `touches` set computed from a variable holding a path is already sound (an unnameable resource conflicts with its whole kind), but *sending* the variable to another thread is a decision about what may cross one, and ADR-033 does not make it. The refusal stays, and it now names the value rather than the call.
- **Every reason the analysis must say no keeps a test**, including the two the widening could have lost: `println`/`println` still keeps its order (D6, through D4 rather than through a special case), and `user_parallelism = no` still never spawns a thread. The expression-statement overlap is compiled and run, and the program prints what the sequential one printed and leaves the same two files behind.
### Measured (0.0.9 - ADR-004 D3: what the `rustc` subprocess actually costs)

- **The subprocess is 0.64 % of a real build, and D3 is not worth building.** [ADR-004](docs/specification/adr/adr-004.md) D3 has said since it was written that the in-memory exit "can be added when the subprocess cost is worth removing", and nobody had ever put a number on that cost. Instructions retired under callgrind, on the largest program the bootstrap compiler lowers: the printed-Rust round trip - print, write, re-lex, re-parse - is **2.77 M of 1 719 M, 0.161 %**, and starting the process is **8.3 M, 0.48 %**. On a three-line program the same fixed cost is 24.5 %, because its whole compile is 34 M. Nothing consuming `rustc_interface::run_compiler` was written; the measurement is the deliverable, and it is in [`docs/subprocess-cost.md`](docs/subprocess-cost.md) with its machine, its method and its variance.
- **A project of many files makes it *smaller*, not larger.** Every `.nika` file becomes a `mod` at the crate root of **one** Rust crate (Part I 9.1), so a program of any size is still one `rustc` invocation: the fixed cost is paid once per program, not once per file, and its share falls as the program grows. The one thing that would invert that is named so it can be watched - if [ADR-003](docs/specification/adr/adr-003.md) D2's build graph ever splits a program into several Rust crates, each crate is an invocation and the fixed cost multiplies. That, and not a bigger program, is when D3 deserves re-measuring.
- **The reason nobody had measured it is that the path had never run.** `--backend bridge` is the **default** backend, and it panicked on every input, at the first symbol the lowering interned: `Ident::from_str` reads the interner out of `rustc_span`'s `SESSION_GLOBALS` and `execute` never installed one, so `scoped-tls` aborted before a line of Rust was printed. It compiled, which is why it survived - `cargo check` cannot tell a lowering that works from one that dies on its first interned symbol. Five lines (`create_session_if_not_set_then`) and `crates/nikaia/tests/bridge_backend.rs` now asserts the whole path end to end: `.nika` in, a binary out, and the binary prints what the program says. A second test holds the refusal: `let_assignment.nika` is turned down by name rather than by panic, because that is what the narrow waist ([ADR-003](docs/specification/adr/adr-003.md) D3) is for.
- **D3's own claim - "costs nothing to keep open" - is false, and that outranks the timing.** The `rustc_ast::Crate` D1 builds is **print-only**: every node carries `NodeId::from_u32(0)` (which is `CRATE_NODE_ID`) and `DUMMY_SP`, where rustc's own parser writes `DUMMY_NODE_ID` and `rustc_expand`'s `assign_id!` asserts exactly that before handing out a real id. Handing this crate to `run_compiler` trips that assertion on a debug compiler and, without it, leaves every node holding the crate root's id. The spans say the same from the other end: [ADR-012](docs/specification/adr/adr-012.md)'s diagnostics are translated from `rustc --error-format=json` *about a generated file*, which an in-memory compile does not write. So the exit costs a node-id discipline, a `SourceMap` and a second diagnostics route - not nothing, and nowhere written down until now.
- **Two thirds of what the subprocess costs is `rustup`, not the process.** `rustc-executor` calls `Command::new("rustc")`, and on `PATH` that is the shim: it starts a 40 MB binary, reads `rust-toolchain.toml`, and only then `exec`s the compiler. Measured as wall-clock minus rustc's own `-Ztime-passes` `total` in the same process: the real binary's process cost is **7.0 ms** (`hello_world`) to **9.8 ms** (`1brc`); through the shim it is **27.6** and **32.0**. End to end on the one corpus program Bridge-IR can carry, `nikaia --backend bridge` takes 69.0 ms, of which the subprocess is 63.5 (92 %) and the shim alone 15.5 (22 %). **Left undone on purpose**: which `rustc` the executor invokes is a toolchain-identity decision, not a performance one - the shim re-reading `rust-toolchain.toml` per invocation is what makes [ADR-001](docs/specification/adr/adr-001.md) D1 true at run time - and no record decides it, so it is reported rather than chosen.
- **Bridge-IR can carry one of the fifteen corpus programs**, which is the context every number above sits in. `bridge-ir` is 85 lines with no control flow at all - no `if`, no `while`, no `match`, no binary operators - so of `examples/` and `tests/samples/` only `hello_world.nika` reaches the subprocess. The eleven examples lower through `--backend rust`, whose output opens with a `grammar! { }` proc-macro invocation that nothing in Bridge-IR can express. The timings were therefore taken on `rustc` compiling the *emitted* Rust of the whole corpus, which is the same work the subprocess wraps and does not depend on which frontend printed it.
- **Three false starts are written down**, because each would have changed the answer: `rustc` on `PATH` is a symlink to `rustup`, so the first process floor credited 21 ms of rustup to rustc; `-Ztime-passes` rounds to milliseconds in its text format, so the parse read as either `0.000` or `1.000`; and "wall minus internal" taken from two different run sets put five of fourteen programs at *negative* process cost until both numbers came from the same run (median absolute deviation 0.2-0.8 ms after).
### Built (0.0.9 - ADR-007 D5: a DSL with deferred parameters generates a shadow type)

- **A `dsl … { … } eod` body's `:name` holes are now a type, and a call site is checked against it.** [ADR-007](docs/specification/adr/adr-007.md) D5 has said since it was written that this is the entire safety argument for embedding SQL rather than concatenating strings - a compiler that cannot say "this call forgot `:active`" has not checked anything - and nothing implemented it. The statement is written once, the parameters arrive at the call site as named arguments after the `;`, and forgetting one is a compile error against the `.nika` line.
- **The parameters are configuration, and the `;` is the whole protocol.** `db.prepare(query; id: 501, active: true)`: subject before it, configuration after it, which is Part I 5.1 applied to metaprogramming with no exception and no second calling convention. The statement may equally be the *receiver* (`query.execute(; …)`, as Part II 10.5 writes it) - both spellings are the same rule and the check does not distinguish them.
- **The struct is generic in every field, because nothing in the source says what a parameter is.** D5's sketch writes `{id: i32, active: bool}`; the body writes `… WHERE id = :id …`, which says nothing about `i32`. Where the type comes from is `meta::parameter(name, type)` (D4), and no `grammar` can declare one yet - so the emitter carries the names and takes the types from the arguments at the call site, monomorphised there. Writing `i32` would have been the guess [ADR-011](docs/specification/adr/adr-011.md) D2 forbids an emitter to make, and it would have been wrong for every statement whose first argument is a `String`.
- **One struct per parameter list, not per DSL string**, which is the one place the lowering is narrower than D5's words. Two statements taking `:id` and `:active` share the type. Nothing observable turns on it - a struct literal names its fields, so a call site needs only the names it passes - and per-string identity would mean the emitter tracking which statement a receiver came from, state it has nowhere to keep.
- **`...args: Self::dsl` parses and lowers.** The typed spread stands where the options stand, and it is exclusive with them: an option has a default and a DSL parameter does not, so a declaration that mixed them would have to say which rule applies to which name. It becomes a generic parameter in the emitted Rust, which is what "monomorphised per DSL string" *is* in the language below. `Self::dsl` in the result position names the same type, so a driver can hand the bound parameters back - an extension of D5's spelling rather than something it decided, and the only thing a driver written in Nikaia today can do with the value.
- **Two diagnostics, `NK1112` and `NK1113`**, each with the statement's parameter list as its note - the note is the contract the call was working from - and a paste-ready way out, including the near-miss where there is one (`did you mean \`active\`?`). A call that forgets one parameter and invents another says both things once, rather than one per build.
- **A method call keeps what stands after its `;`.** It was parsed and dropped on the floor, which is why a `dsl` statement could not be given a parameter at all: `Postfix::Method` discarded the config zone. That was the load-bearing gap, and it was invisible - the call compiled and the arguments simply vanished.
- **Not taken on trust**: `crates/nikaia/tests/dsl_parameters.rs` lowers `tests/fixtures/sql_statement.nika`, compiles the emitted Rust with the `rustc` that built the test, runs it, and compares what it printed. The statement reaches the driver **with its holes as written** - `SELECT name FROM people WHERE id = :id AND active = :active` - because a deferred parameter is not string interpolation and the value may not be spliced into the source text (Part III, 15.3). The values arrive beside it.
- **`dsl html` is untouched.** Its `:rows` is an *immediate* capture from the enclosing scope ([ADR-017](docs/specification/adr/adr-017.md), ADR-007 D4), and a test would fail if D5 had quietly turned it into a parameter. `html` is the one target this compiler is itself the grammar for; for every other, a body with holes is a deferred-parameter statement and a body **without** them is still refused - its meaning is the target grammar's, and the refusal now says that instead of saying that deferred parameters are unbuilt.
- **Not built: the driver's own half.** `args.values()` (Part II, 10.5) needs the parameters to have a type, which is `meta::parameter` again; `SqlAst[Signature = {…}]` is a spelling the parser has no rule for; and `dsl <target>` still does not resolve to a `grammar`. So the type that carries the names exists and a library that reads the values out of it by anything but their names does not. `examples/fortunes.nika` is unmoved: its `postgres` block has no holes.
### Built (0.0.9 - ADR-002 D1: one CLI wraps and instruments Cargo)

- **`nikaia build` and `nikaia run` build a project, and the binary they produce runs.** The CLI compiled one file. It now takes a directory, walks to the nearest `nikaia.toml`, translates it into a `Cargo.toml` under `target/nikaia/build/`, and drives `cargo` over it - so dependency resolution, fetching and linking are Cargo's, which is the whole argument of D1: a language that cannot reach crates.io starts with no ecosystem, and those three are solved problems. A project with no runtime dependency goes from nothing to a running binary in **0.24 s**; a project with `regex` from crates.io and a grammar in it takes 24 s the first time and 0.12 s after.
- **The single-file path is untouched.** `nikaia --input x.nika --backend rust|interpreter` behaves exactly as it did, and a test next to the new path asserts both backends still work without a subcommand - adding a subcommand to a CLI that had none is precisely the change that would have broken them.
- **`type = "rust"` passes through and nothing else is invented.** Part III 13.3 shows two dependency shapes. `regex = { type = "rust", version = "1.5" }` reaches Cargo with only the marker removed, because the marker is Nikaia's word and Cargo would refuse it as an unknown key. `http-server = "1.2"` is **refused with its reason**: no ADR names a registry, a name space or a distribution format for a Nikaia package, and handing it to Cargo would make it fail on crates.io somewhere that explains nothing.
- **`[build.<target>]` becomes a Cargo profile, and the panic strategy is not in it.** `opt-level` and `lto` for the machine this build chose become `[profile.dev]`; `panic` is written there too and comes from `target` rather than from the author - `unwind` where the machine unwinds, `abort` where it traps (ADR-037 D1). A key `[build.<target>]` does not know, and a `[build.<machine>]` that names no machine, both fail the build and name themselves - the same rule `[build]` already had, for the same reason.
- **`RUSTC_WORKSPACE_WRAPPER`, verified rather than asserted.** Cargo applies it to workspace members only, which is why D1 names that variable and not `RUSTC_WRAPPER`: a crate from crates.io is compiled by the real `rustc` with nothing in between. The claim is **invisible in the output** - a dependency passed *through* a pass-through wrapper and one that never reached it produce the same rlib - so the wrapper writes down what Cargo handed it (`NIKAIA_WRAPPER_TRACE`), and the test over a project depending on `regex` asserts exactly one crate in the build was lowered, that it was the project's own, and that nothing in the trace mentions `regex`, while Cargo's own lockfile shows `regex` was resolved and linked.
- **Cargo does not require a `.rs` crate root, which is what makes the interception possible at all.** The generated manifest names `src/main.nika` as the binary's path; Cargo hands the wrapper a `rustc` command line with a `.nika` file in it; the wrapper lowers, substitutes the emitted Rust, and runs the real `rustc`. Cargo's own `rustc -vV` probes go through the wrapper too and are passed on untouched.
- **Two things building it settled, and neither was predicted.** Both are about Cargo's freshness. A generated file rewritten with *identical bytes* is newer than the fingerprint Cargo wrote, so the package is dirty on every build, for ever - measured by building twice, then fixed by writing only when the bytes change. And the dependency file `rustc` emits names the **generated** Rust, which Cargo believes: an edited `.nika` source left the package fresh and the binary stale until every source that took part was put back into that file after `rustc` succeeds. Both now have a test - build twice, edit once.
- **A program declares only the runtime it names.** The emitted Rust reaches for `nikaia_std`, `winnow_grammar` and `winnow` conditionally, so the generated manifest declares each only when the lowering actually writes it, and their versions are read out of the compiler's own `[workspace.dependencies]` rather than written down a second time - a program that linked a different `winnow` from the one `winnow-grammar` was built against is a type error at every `Stream` bound.
- **The generic half lives in the orchestrator** (ADR-003 D2): rendering a manifest, running `cargo`, splitting a `rustc` command line and repairing a dependency file are in `bridge-orchestrator::project` and know nothing about `.nika`. `crates/nikaia/src/manifest.rs` grew to read `[package]`, `[dependencies]` and the codegen tables, and `Manifest::find` now walks up through `Layout::resolve` - the cache's root-finder - so a build and the cache entries it writes cannot disagree about which project a file belongs to.
- **Not built, and said rather than skipped:** D2's compile-time evaluation, which waits on ADR-026 being open; `nikaia test`, `bench` and `fmt`; and the D2 lockfile field for *resolved dependency versions*. That last is a real gap: Cargo's `Cargo.lock` for the generated package records them and `nikaia.lock` does not, so the file that exists to answer "does this build the same thing for you as for me?" answers it today only about the Nikaia half. `opt-level`, `lto` and a dependency version deliberately stay **out** of the build-cache key - they change machine code and not the lowering, and the envelope the cache holds is the emitted Rust and the ledger, which Cargo's own fingerprinting then covers (ADR-021 D1). A key that moved with them would be D7's first failure direction.

- **`nikaia.contracts` is now compared across two processes**, for every example the bootstrap compiler can lower (10 of 11), at one thread and at four. D8 has said since it was written that the ledger is a pure function of (source tree, toolchain) byte for byte, and that the enforcement is "build twice and compare" - and nothing did.

### Built (0.0.9 - ADR-037 D5 and ADR-033 D8: the switches live in the manifest)

- **`nikaia.toml` carries the build switches, and a flag overrides them for one build.** `[build] target`, `[build] user-parallelism` and `[build] ordering` were specified and unread - the choice lived only on the command line, which makes a project's setting something every invocation has to remember. They are properties of a project, and a committed value is one a reviewer sees. `--target`, `--user-parallelism` and `--ordering` override for a single build, which is what a benchmark and a bug hunt need.
- **A key `[build]` does not know fails the build and names itself.** The manifest spells it `user-parallelism` and the flag `--user-parallelism`, so an underscore is the mistake a person actually makes - and a silently ignored key leaves the build at a default its author believed they had changed. `cleanup-deadline` is accepted without being honoured, because a manifest that follows the specification must not be refused by a compiler that has not caught up with it. `[build.x86_64-linux]` and `[build.wasm32-unknown]` are codegen tables rather than switches and are skipped, not rejected.

### Measured (0.0.9 - ADR-033 §8: what the overlap actually bought)

- **Nothing in this repository overlaps, and the reason is the analysis, not the code.** `--overlaps` weighs **127 adjacent statement pairs across `examples/` and refuses all 127**; the emitted Rust is byte-identical under `--ordering effects` and `--ordering strict` for all ten files the bootstrap compiler can lower, and not one `std::thread::scope` is produced. But **101 of the 127 fall out before any `touches` set is consulted**, on "one of them is not a `let` of a single call" - the analysis only looks at a shape almost nothing is written in. 12 are ADR-034's conditional handler. Only 14 are the ledger's fail-closed polarity doing its job. A zero produced that way measures the analysis, not the corpus.
- **The lowering is a pessimisation below ~256 KB per operation**, and this is now measured rather than suspected. `benches/overlap/` builds the two shapes the emitter produces for the same two reads and times them: **0.04×** at 5 bytes per file, **0.13×** at 64 KiB, crossover near 256 KiB, then **2.5×** at 1 MiB and **6.75×** at 8 MiB. Two spawns and two joins cost about **100 µs per pair, paid unconditionally**. A fixed 100 µs tax on two operations that may each take a microsecond is the opposite of the goal these decisions serve.
- **Nothing changes yet, deliberately.** ADR-033 §7 owed a measurement on *real programs* and this corpus still is not one. The debt is now two debts instead: widen the analysis past `let x = f(…)` so its silence means something, and find a vehicle that beats 100 µs - a cost estimate in the ledger, the pool a `user_parallelism = yes` build already has instead of raw spawns, or `strict` as the default with overlap as the opt-in. In that order; the second must not be decided before the first is done.
- **The overlap was running user code on two threads at `user_parallelism = no`, which promises the opposite.** `--user-parallelism no --ordering effects` emitted `std::thread::scope` ten lines above the `Parallelism::Off` the same file hands the parser - and neither `thread::scope` nor `rayon::join` links on `wasm32-unknown`. The cause is a category error worth naming: **whether two operations *may* overlap is a question about the program, whether a vehicle exists to overlap them with is a question about the build**, and `overlap_at` consulted `ordering` and never the build. At `no`, `effects` now degrades to `strict` - the same degradation `par_fold` already makes to a sequential `fold` (ADR-009). `--overlaps` says which setting made its report hypothetical instead of reading as a promise. The predicate is `user_parallelism` and deliberately not "does this build have threads": it has a second one at `no` too and always did, since Part I 8.4's **Runtime Sidecar** offloads blocking I/O to a background thread on native (a Web Worker on WASM), safe precisely because *user code never runs there* - the exchange is ownership-transferring message passing.
- **The overlap now lowers to `nikaia_std::task::both`, which is `rayon::join` on the pool the program already has.** Not mainly for speed: `std::thread::scope` asks the OS for two fresh threads *per pair*, so a handler overlapping two reads across a thousand concurrent requests asks for two thousand threads, and nothing in the lowering bounded that. The pool's ceiling is the pool's. It also means the emitter names one `std` function instead of spelling a scope, two spawns and two joins into every program - the next change of vehicle is a `std` change.
- **Changing the vehicle was not the fix, and that is the finding.** The fixed cost of an empty pair falls from **90 µs** (`thread::scope`) to **46 µs** (`rayon::join`), but the table over real reads does not move at all: with blocking I/O the second closure has to be *stolen*, which wakes a sleeping worker, which is the same futex wake `spawn` pays. **The floor is thread wake-up latency, not thread creation** - an OS number no user-space vehicle removes. So the overlap can only ever pay for operations in the **millisecond** range, and every program in this repository does microsecond work.
- **Which inverts the conclusion (ADR-033 §8.5).** ADR-033 never asked for two threads; it asked that two operations which meet on nothing not wait for each other. Two reads handed to the sidecar, both in flight, results collected on the main thread in written order, is exactly that - and carries **no per-pair wake-up at all**, because the sidecar thread is already running. The 46 µs floor is an artefact of the vehicle `user_parallelism = yes` uses, not of the decision. **ADR-033 may be worth more at `no` than at `yes`.** A prediction and not a measurement - there is no event loop to time - but it redirects what to build next: not a faster thread vehicle (§8.4 ruled that out), the runtime `no` deserves.
- **`benches/overlap/run.sh` is the number to beat**, kept as plain `rustc`-buildable std so it can be read next to the generated Rust.

### Decided and built (0.0.9 - ADR-033 D9: no `allow_parallel`, and the compiler says why instead)

- **The obvious companion to `seq` is refused, and the reasoning is written down because it will be proposed again.** `try_join { }` is out twice over: it names what the compiler already does, so writing it would make the fast path the thing you ask for - the design ADR-033 exists to invert - and `tokio::try_join!` means *cancel the others on the first error*, the opposite of D6. Borrowing the name would borrow the wrong expectation.
- **`allow_parallel { }` serves exactly one refusal**, and that one has a clearer spelling already. Of everything the analysis turns down - a data dependency, the same resource, a resource it cannot name, a non-literal argument - only a `catch` that can `return` is a case where the programmer knows something the compiler does not and the program is right either way. And `catch { return }` conflates two things: what to do about the failure, and whether to carry on. Separating them (`catch { Kunde::unbekannt() }` then `if k.ist_unbekannt() { return … }`) is not merely equivalent but **better**, and it overlaps. A keyword whose only purpose is to rescue a phrasing that has a clearer form is a second way to say one thing - which is what [ADR-022](docs/specification/adr/adr-022.md) removed a lambda form for.
- **What is owed instead, and is now built**: `nikaia --input x.nika --overlaps`. Every adjacent pair, which of them run together, and for the rest the reason - naming the file two statements collide on, the call nothing describes, or the handler that can leave the function *together with what to write instead*. A refusal nobody can ask about **is** the trap the keyword would have been an escape from; this is the asking. Asked for and never volunteered, because a paragraph per pair would be noise in exactly the programs that are fine. It explains a decision rather than changing one, which is what `--trust` already does for provenance.
- **The analysis knew all of this and threw it away.** `may_overlap` returned a boolean; it now answers with a `Verdict` (and an `Accounted` for a statement it cannot reduce at all), which is why the report can say `both reach file \`log.txt\`, and one writes it` rather than "not accounted for".
- **A test asserts the advice is true**: the rewrite the refusal recommends really does overlap. If it did not, the argument against the keyword would be wrong and the keyword would be needed.
- **Revisited if** somebody writes a real program with a place where they want both to run, cannot restructure it, and can measure the difference. Until then the language has two escapes and both are *restrictions* - `seq` and `ordering = "strict"` - rather than permissions. A narrower and more honest surface than three block forms.

### Changed (0.0.8 - ADR-035: `f"…"` interpolates, `"…"` is text)

- **Every string literal was a template**, so `"{ margin: 0 }"`, `"\d{3}"` and every line of JSON a program printed were all format strings. `examples/json.nika` - a program whose entire job is to emit braces - was written `print("{{}}")` to print `{}`, and `examples/1brc.nika` ended on `println("{{{body}}}")`, three braces of which two were tax.
- **Measured over the corpus**: 212 string literals in 45 `.nika` files; **56** hold a hole, **154** are plain text. Three quarters of them were templates that interpolated nothing, and every string that wanted a brace paid for it.
- **The root cause is not the brace.** The distinction already existed in three places - the emitter branches (`"x"` vs `format!`), the *type* branches ([ADR-024](docs/specification/adr/adr-024.md) D5 made `"a {b}"` a `String` and `"a b"` a view), and since [ADR-032](docs/specification/adr/adr-032.md) every analysis has to open every literal to find out. The only party who could not see the answer was the person writing the string.
- **The mark belongs on the construct, and Nikaia already knew that**: `dsl html { … }` is marked, a grammar is marked, a `spawn` is marked. The bare string literal was the one place the rule was forgotten - which is how ADR-017's templates inherited ADR-032's blindness without anyone noticing.
- **`f"…"` has code in it; `"…"` is text** ([ADR-035](docs/specification/adr/adr-035.md) D1). `{{`/`}}` stay the escapes *inside* an `f"…"`, where there is something to escape from. `print("{}")` prints `{}`.
- **The type is read off the first character** (D3): `"…"` is a view, `f"…"` is a `String` whether or not anyone put a hole in it. That retires ADR-032 D5, under which adding a brace to a message silently changed its type.
- **The `f` and the quote are one token** (D4), so `f "x"` is a variable beside a string and whitespace never decides what a program means. A template keeps its bare braces - the construct is the mark. And `f"…"` is unreachable where a constant is required (a Kap 5.1 default, a `match` pattern, a grammar literal): the grammar says so rather than a later pass discovering it.
- **The break is a warning, on purpose and not forever** (D5). `println("hallo {name}")` still compiles and now prints `{name}`, and Part III C.1 calls a silent change of meaning a compiler bug - so **`NK1111`**, the first thing this checker warns about rather than refuses. It cannot be an error: `"{ margin: 0 }"` is correct CSS, and refusing it would break the property the checker rests on. So the test is narrow - the braces must hold something that parses **and resolves to something that is here**, a variable in scope or a function a ledger knows. It is removed one release from now.
- **56 literals migrated mechanically, and the corpus raises no warning.** The transformation is meaning-preserving by construction; comments, grammar patterns and template bodies are excluded, and the three places an automated pass got that wrong were caught by the test suite rather than by review.
- **A diagnostic got better on the way.** Folding `f"…"` into `str_lit` as a second alternative silently dropped `` ` " ` `` from the parser's "also possible here" list - a rule whose body is one sequence reports what it can start with, one built from alternatives did not. `f_str_lit` is its own rule, and the list now carries both `` ` " ` `` and `` ` f" ` ``.

### Built (0.0.9 - ADR-033's first increment: two reads that meet on nothing)

- **Two adjacent `let`s whose calls reach different files now run at the same time.** [ADR-033](docs/specification/adr/adr-033.md) §6's first increment, end to end: the ledger gained a `touches` column, `contracts/order.rs` decides whether two statements may overlap, and the emitter lowers a pair to `std::thread::scope`. `std::thread::scope` and nothing else - `std`'s I/O is blocking Rust behind `fs::read`, so overlapping it means threads, and a scoped join needs no runtime and no dependency.
- **Not taken on trust**: `tests/ordering.rs` compiles the emitted Rust and runs it, and the program prints what the sequential one printed. A lowering that produces plausible-looking Rust which does not build is worth nothing.
- **Eight reasons two statements must *not* overlap**, each its own test, because the decision is only safe if every "no" is reliable: a data dependency; a write to the same file; a file the compiler cannot name (it is then every file of its kind); a function nobody described (`println` has no `touches`, which is also what keeps two `println`s in order without a special rule for it); a handler that can `return`; an argument that is not a literal; and a block's tail.
- **A panic is resumed, not unwrapped.** A program that would have panicked still panics with its own message and its own payload; turning it into `called Result::unwrap on an Err` would be the lowering putting its own words in the program's mouth.
- **`--ordering strict` turns it off** (D8), and the switch is real rather than decorative: the same source lowers to exactly the program this compiler emitted before any of this. The `nikaia.toml` key of Part III 13.3 is still specified and unimplemented, so the choice lives on the CLI today.

### Decided (0.0.9 - ADR-034: a handler that can return makes the next statement conditional)

- **The first thing building ADR-033 corrected in it.** D5 forbids running an operation early that might not have run at all, and named a branch as the way to be uncertain. `let a = fs::read_to_string(p) catch { return }` is a second way, and it is the shape real Nikaia code is written in: both statements are unconditional, neither is inside an `if`, the touch sets are disjoint - and if the first read fails, the sequential program **never performs the second one at all**.
- **[ADR-034](docs/specification/adr/adr-034.md) D2 states the rule generally** so a third case does not need a third ADR: *an operation may be started early only if the program as written would certainly have performed it.* A branch is one way to be uncertain; a diverting handler, a `break` and an early `return` are three more, and the sentence covers all of them where a list would not have.
- **Why it got its own record rather than four quiet lines of code**: ADR-033 is marked provisional because a decision of that size is expected to need corrections, and a provisional decision that quietly acquires patches is not provisional but vague. It is also the first evidence about ADR-033 that came from building rather than from thinking, which §7 said was owed.

### Also found by building it

- **`ordering` had to become a build-cache dimension.** It changes the emitted Rust, so a key without it would let `--ordering strict` be served the overlapped artifact a previous run recorded - a cache handing back a program nobody asked for. ADR-021 D5's own rule ("build-time choices reach the key"), met from a new direction.
- **A `throws` function body has a statement loop of its own**, separate from a block's, because its last statement may need wrapping in `Ok(…)`. Two loops deciding independently what may be reordered is two rules waiting to disagree, so the pairing lives in one helper both call.
- **Not one example in the repository overlaps.** Every one of them either chains its reads or names its paths with a variable. A test asserts it, so the day one does is a day somebody is told. That is the measurement ADR-033 §7 could not take, taken as far as this corpus allows - and the answer is that the corpus is not evidence either way.
- **A pre-existing bug, ruled out rather than fixed**: `fs::read_to_string(p) catch { "" }` emits Rust that does not compile, because the handler is a `&str` and the call hands back a `String` (ADR-024 D5's divergence). It fails identically with and without this change, and the tests here write `catch { "".to_string() }` to step around it rather than to hide it.

### Decided, not built (0.0.9 - ADR-033: program order is a guarantee where it is observable)

- **The decision, in one rule**: every operation is known by **what it touches** - which file, which socket, which lock - and *two operations whose touch sets are disjoint have no order between them*. Everything else keeps the order it was written in. `let a = fs::read("x")` beside `let b = fs::read("y")` costs 40 ms rather than 80, and nothing is written to get it. [ADR-033](docs/specification/adr/adr-033.md), Part I 8.1.1.
- **The reframe that made it possible.** The first answer to "let the compiler overlap what is independent" was no: a CPU may reorder because it knows the whole dependency graph, its operations are mutually effect-free, and it can roll back - and for I/O none of the three holds. That is right about **today's effect vocabulary** and that is its weakness. Nikaia knows exactly one thing about `fs::write`: *it is I/O and may pause*. Two writes to different files are indistinguishable, not because I/O is unknowable but because nobody wrote down what each call reaches. **The ordering problem is a resolution problem of the effect system, not a safety property of parallelism.**
- **It is the borrow checker, extended past memory to the world** (D3), and that is the argument for it over any other spelling. Nikaia already answers *who may touch this, and may they change it* completely and invisibly, with no lifetime annotations ever (ADR-005). `&` and `&mut` are *read* and *write*; what is missing is only that a file, a socket, `stdout` and a `Locked` value are not yet things that can be pointed at. Not a new mechanism bolted on - the one the language already rests on, over a larger set.
- **Unknown touches mean touches everything, so unknown means ordered** (D4), and this is what makes it adoptable at all: a program built against libraries that describe nothing behaves **exactly as it does today**, parallelism appears only where somebody wrote enough down for it to be provable, and no program is ever made wrong by a missing contract. ADR-010 D1's fail-closed polarity, applied to a third question.
- **One concept replaces four rules.** Data dependency, the order of output (`println`/`println` stays ordered because both touch `stdout` - no special case), the no-pausing-while-locked rule of 12.2, and race freedom. The last is the interesting one: Nikaia's freedom from races rests today on Lite being single-threaded, which is why it is a property of a *profile* rather than of the language. Under a touch model it is a property of the language, and the profile divergence loses its worst instance.
- **The exception costs, deliberately** (D7): `seq { … }` says an order the compiler cannot see - two calls to different addresses of one service. A line, visible, rare. And the whole thing is switchable: `ordering = "strict"` in `nikaia.toml` (D8) restores the written order everywhere, not as a temporary aid but as the escape for a project that does not want this.
- **Also decided: no speculation and a bounded degree** (D5). `if x { lies(a) } else { lies(b) }` starts one of them - burning a request that was never wanted is the opposite of what this is for. And a loop over ten thousand files must not open ten thousand descriptors; unbounded parallelism is not generosity toward a machine.
- **Nothing of this is built**, and the ADR says so in its own §6: no `touches` column, no `ordering` key, no `seq`, and an emitter with no notion of a dependency graph. The first increment that would do anything end to end is named there - two unconditional `fs::read` calls with disjoint literal paths, lowered to a concurrent join.
- **Accepted without a measurement, on purpose and on the record** (§7). This repository's rule is that a staging decision enters the compiler only with a measured crossover, and it has twice overturned an obvious intuition. That rule is about **optimisations** - two implementations of one meaning, where measurement is the only honest arbiter. This is a **semantic** decision: what a program means when two lines stand next to each other. No benchmark decides that, and the programs that would exercise it cannot yet be written. The debt is recorded instead: measure how much unconditional independent I/O real programs contain once an application exists to measure, and if the answer is "almost none", `strict` becomes the default rather than the escape.

### Fixed (0.0.8 - ADR-032: a hole is code, and every analysis has to see it)

- **A call inside `"{…}"` was invisible to the entire compiler.** `let n = add(1)` is `NK1101`; the identical `println("{add(1)}")` lowered without a word. The same held for a `dsl html` template's holes ([ADR-017](docs/specification/adr/adr-017.md)). The cause is one line of history: a hole's expression is parsed **in the emitter**, on the way to Rust, so "parsed" and "analysed" had come apart for one construct and everything upstream was blind to it by default.
- **The half that was more than a missed diagnostic**: `sync` is *inferred* from what a body calls ([ADR-027](docs/specification/adr/adr-027.md)), and the walk did not descend into holes. So `pub fn greet() -> String { return "hello {io::read_to_string()}" }` was recorded **`sync = "inferred"`** - a false claim, in a file a library ships, that a pausing function cannot pause. A consumer reads that and puts the call inside `access` or `par_iter`. ADR-027 D2 and [ADR-010](docs/specification/adr/adr-010.md) D1 both name this direction the dangerous one: *an analysis that fails open is a vulnerability generator*, and this one did not merely fail open - it affirmatively claimed the safe answer for an unsafe body.
- **One function, not two fixes** ([ADR-032](docs/specification/adr/adr-032.md) D1): `emit::literal_expressions` answers "what code is inside this expression?" for interpolated strings and for templates - including the holes inside a template's `for` body and the collection it iterates - and every analysis calls it. Re-parsing holes at each call site is how the blindness happened the first time, and ADR-017 inherited it two ADRs later without anyone noticing, because there was no place where the question could be asked.
- **A hole is checked exactly as a statement is** (D3), and the test asserts the two diagnostics are `==` rather than merely both errors - equality is the property, not "an error appears". The `sync` **check** holds an asserted `sync` to its holes too, so `NK2202` names a pausing call inside a literal (D4).
- **A hole that does not parse is nobody's business but the emitter's** (D2), which already has the span and the message. An analysis inventing a second error for the same text is two errors for one mistake - the same reasoning as `Ty::Unknown` in [ADR-024](docs/specification/adr/adr-024.md): the absence of a claim, not a claim of absence.
- **`"a {b}"` is a `String` and `"a b"` is a view** (D5), which falls out of the checker looking at the literal at all.
- **230 tests pass with no ledger drift** - not one recorded contract in `std.contracts` or any example's ledger moved. Nothing in the corpus was depending on the blindness, so the gap closes without any existing claim changing.
- **Parsing holes into the AST properly is the honest fix and is deliberately not this change** (§3): it reshapes `Expr::LitStr`, and with it the emitter's measured string fast paths, the golden fixtures and the error corpus. It can be done later without any decision here changing meaning.

### Decided and built (0.0.8 - ADR-031: a signature may name its receiver's type arguments)

- **Three ADRs in a row ended at the same wall, and this is it coming down.** ADR-027 inferred `sync` from bodies and could not vouch for a method call; [ADR-028](docs/specification/adr/adr-028.md) resolved method calls and could not type a lambda's parameter; [ADR-029](docs/specification/adr/adr-029.md) gave the ledger function types and still could not say what `and_modify` hands its lambda. In `.and_modify fn { a.add(m.temp) }`, `a` should be a `&Stats` - and `Stats` comes from the map, `HashMap[&str, Stats]`, which the signature language had no way to refer to.
- **A spike found the exact break**, before any code was written: `.entry` is called on `HashMap[&str, Stats]` and `.and_modify` on a bare `Entry`. The information existed at the receiver and was dropped at the result. Nothing had to be inferred that was not already known - it had to be *carried*.
- **`$V`** ([ADR-031](docs/specification/adr/adr-031.md) D1): `HashMap::entry` is `(&HashMap[$K, $V], key: ?) -> Entry[$V]`, and at a call site the receiver binds the variables and they are substituted away. `HashMap[&str, Stats]` → `Entry[Stats]` → `fn(&$V)` is `fn(&Stats)` → `a` is a `&Stats` → `a.add(v)` resolves to `Stats::add`, which is pure. The sigil is not decoration: `T`, `K` and `V` are perfectly good type names, and a rule that guessed from capitalisation would silently turn somebody's type into a hole.
- **An unbound variable becomes `?`, never a name** (D2), which is the whole safety argument and why this does **not** contradict ADR-024 D4. D4 erases a Nikaia generic because a `T` that survives into a comparison makes the checker report that `i32` is not `T`. A variable here cannot survive: it is bound and replaced, or it is `Unknown`. `HashMap::new()` says nothing about what it holds, binds nothing, and the chain stops helping rather than guessing.
- **A variable says what flows *out*; `?` stays for what flows *in*** (D3), and this is a distinction rather than caution. What flows out is a promise the ledger makes, wrong on its own account. What flows in is a constraint on somebody's program - and Rust's `HashMap<String, V>::get` takes anything the key borrows as, so `counts.get(fragment)` in `k-nucleotide.nika` is correct and `key: $K` would have **rejected it**. That is the one thing the checker may not do, and there is now a test named after exactly that program.
- **Binding is narrow on purpose** (D4): from the receiver, by position, one pattern. No binding from arguments, no nested matching, no constraints. This is the first *inference* in the ledger's type language - everything before it was vocabulary - and inference engines grow. Drawing the line here means the next widening has to be argued for rather than arriving as a refactor.
- **Measured: 18 of 18.** Strip every `sync` declaration from the examples and count what comes back: 9/18 after ADR-027, 14/18 after ADR-028 and ADR-029, **18/18 now**. `1brc` 5→7, `access-log` 4→6. **Every `sync` written by hand in this repository is now something the compiler works out for itself** - the keyword is an assertion you write where you want a property held, and no longer something a program has to carry to be usable.

### Added (0.0.8 - ADR-030: a program is more than one file)

- **Multi-file programs.** Part I 9.1 has said since 0.0.5 that every file is a module, and `use` parsed and lowered to a comment. `use utils` now brings in `utils.nika` beside the entry, every module becomes a `mod` at the crate root, and `stock::total(…)` in Nikaia is `stock::total(…)` in Rust - so **[ADR-011](docs/specification/adr/adr-011.md) D2 is untouched**: nothing resolved it. What changed is that the compiler knows which files take part, which is a question about the file system rather than about names.
- **The argument this rests on is one observation**: `std.contracts` has had module-qualified keys since the day it existed (`fs::map`, `io::lines`, `text::digit_value`), and everything built on the ledger resolves a call by asking for `a::b` - the `sync` check, the type checker, provenance, Kap 5.1's options, ADR-025's fallible loops, ADR-027's inferred `sync`, ADR-028's method resolution. A program's own ledger takes the same shape, so **none of them learns a new trick**. The file they ask simply has more in it.
- **`pub` becomes `pub`**, so Part I 9.2's privacy is enforced by the language below rather than re-implemented - the same move [ADR-017](docs/specification/adr/adr-017.md) D2 made with `html::Render`. And **`NK1110`** says it in Nikaia's words first, because Part III C.1 calls an untranslated backend error a bug in this compiler. It knows a call crosses a boundary without knowing where it is: only a call written `module::item` can be from another file.
- **Two bugs that one file could not show.** The emitter wrote `pub` on **every struct field**, whatever the source said - invisible in a single file, and across a boundary it silently granted access 9.2 denies. And `pub` on a field did not parse at all, though 9.2 specifies it, so the one thing that would have made the first bug visible was missing too. Both fixed; the golden fixture that had frozen the old behaviour is regenerated.
- **A third bug, found by writing the example**: `"{utils::double(21)}"` was read as the expression `utils` written with the format specifier `:double(21)`. A hole in an interpolated string is Nikaia source, and Nikaia source names things across modules. `::` is a path now.
- **One ledger for the project** (Part III, 13.5), and the contracts are inferred over all of it **at once** - because `sync` is a fixpoint over the call graph (ADR-027 D1), and a call graph that stopped at a file boundary would answer differently depending on which file was read first. Modules are recorded in name order, not in the order their imports were discovered.
- **[ADR-021](docs/specification/adr/adr-021.md) D13 is narrowed honestly.** 13.1 asks the cache key to cover each source that took part, and knowing what took part means parsing the entry - so *on a hit nothing is parsed* becomes **nothing is parsed twice**. A hit still saves the lowering, the checks and the inference, which is the larger part. A single file is unchanged down to the key's bytes.
- **The source map records which file**, so [ADR-012](docs/specification/adr/adr-012.md) survives the join: a `rustc` message about the third module lands in the third module.
- **`examples/inventory/`** is the first program here made of more than one file - the same program `examples/report.nika` is, in three. Both are kept on purpose: a reader can see what a boundary buys and what it costs on a program small enough to hold in the head. The example harness reads a *program* rather than a file, so an example may be one file or several and the tests do not care which.
- **What it does not do, and why each is where it is** (ADR-030 §7): a grammar is not visible across modules (the emitter reads grammars out of the file it is emitting, and the fix points the right way - the file about reading a stock list is where reading one belongs); field privacy is enforced by the language below and not reported as `NK1110`, because the ledger records a field's type and not yet its visibility; and a hole in an interpolated string is not type-checked at all, because it is parsed in the emitter - pre-existing, and now worth naming.

### Decided and built (0.0.8 - ADR-029: a higher-order function does what its lambda does)

- **A ledger entry has to hold for every caller, so a function that runs somebody else's code had to commit to the pessimistic answer.** [ADR-028](docs/specification/adr/adr-028.md) D6 gave `and_modify`, `or_insert_with` and `map` signatures and deliberately no `sync`, because a ledger could not say "it depends". That was honest and it rejected correct programs: `fn ordne(xs) { xs.sort_by_key fn { a } … }` sorts a list by a key and cannot pause by any reading of it, and calling it from a `sync` function was `error[NK2202]: ordne can pause`. Since `access`, `access_all`, `par_iter` and a scope's tasks all gate on a `sync` lambda, the commitment read, where it bit, as **no `map`, `filter`, `fold` or `sort_by_key` inside a lock, over any lambda at all**.
- **`sync = "from(f)"`** ([ADR-029](docs/specification/adr/adr-029.md) D3) names the parameter that decides - the same shape `returns = "borrows(a | b)"` already uses for "depends on a parameter", which is why it needed no new grammar in the file. A caller reads it as **"this call adds no pausing of its own"**, and that is sound for one reason worth writing down: the lambda runs *during* the call, so its body is part of the function that writes it and that function has already counted its calls. `from` adds nothing because there is nothing left to add.
- **That reason is also its limit** (D4). A parameter the callee **stores or spawns** - Part I 5.4's `@detached` - breaks it, because then the lambda's calls belong to nobody the caller is counting, and a pausing body would slip into a lock with the ledger saying it could not. The ledger cannot spell `@detached`, so the rule is enforced rather than assumed: a test walks every `from` entry `std` ships and requires it to name a parameter that is a lambda. The day `std` gains a detached one, that test is where it is noticed.
- **The ledger's type language gains `fn(…)`** (D1) - `fn(&Stats)`, `fn()`, `fn(&str, i64)` - saying what a lambda is *handed*. What it hands back is deliberately absent: nothing needs it, and a spelling is easier to add than to change. **Only a ledger writes one**: Nikaia's grammar has no function-type syntax, so no source program can declare a parameter of that shape - which closes the hole where a function passes its own lambda parameter on, rather than leaving it open.
- **A lambda's parameters now get types from the callee's signature** (D2). The checker walked a call's arguments *before* resolving the callee and so knew nothing about them; it now resolves first and walks after. The implicit form is the one that needed this and could not have it: `fn { a.add(t) }` records **no parameters at all** in the AST, because Part I 5.3 settles how many arguments a lambda takes from which of `a`, `b`, `c` its body mentions.
- **Measured, and the honest answer is "nothing yet".** On ADR-027's measure - strip every `sync` from the examples, count what comes back - this changes nothing: **14 of 18, before and after**; 20 of 43 functions corpus-wide, likewise unchanged. **No program in this repository is unblocked by it.** What it removes is a false rejection, and the smallest program that shows it is now a test: `ordne` above compiles and is `sync = "inferred"` where it used to be `NK2202`. The case is that the corpus is eleven mostly parser-driven programs and the rule this lifts applies to a category rather than to a program - and a reader who wants a measured crossover before believing a change is right to want one, and should know this one does not have it yet.
- **What is still in the way, named exactly**: the four functions ADR-028 left open are all `.and_modify fn { a.add(m.temp) }`, and D2 types `a` from a signature that says `fn(?)`. It cannot say `fn(&Stats)`, because `Stats` is the **type argument of the map** and the signature language has no type variables. So the next question is one question: may a `std.contracts` signature refer to its receiver's type arguments? It would be the first thing to add *inference* to the ledger's type language rather than vocabulary, which is why it gets its own decision rather than being smuggled in here.
### Fixed (0.0.8 - `while` exists)

- **`while` was in the specification and not in the compiler**, and it failed in the way that costs most: silently. Part I 3.3 documents it with a worked example; the parser had no rule for it, so `while n < 5 { n += 1 }` read as **three** statements - a variable called `while`, a comparison thrown away, and a bare block - and lowered "successfully" to `while; n < 5; { n += 1; }`. What a reader got was `rustc` complaining about a file nobody wrote, which Part III C.1 calls a bug in this compiler. It is one statement now, it lowers name for name (ADR-011 D2), and its condition is type-checked like an `if`'s (`NK1108`, with a note that says which loop it is about).
- **The regression test is about the shape**, not the output: a `while` must be *one* statement and not three. That is the bug that was there, and a test that only checked the emitted Rust would not have caught it.
- **Two rows of the error corpus changed**, and both are improvements: `while` now appears in the list of what may begin a statement, because it may.
- **`loop` is not added.** It has been on the roadmap since that file was written and it is **not in the specification** - Part I 3.3 has `while` and `for` and nothing else. Whether the language wants an unconditional loop is a question to answer before implementing one, and the roadmap now says so rather than listing it as work.
- **The roadmap's Phase 1 said things that stopped being true months ago**: that enum variants do not parse (they have since G12) and that `while` does not (it does now). Both boxes are checked, with what is actually still open under them - the Bridge path, which carries `let` and an expression statement and refuses every other kind.

### Decided and built (0.0.8 - ADR-028: the type checker already knew)

- **The answer was one module away, being computed and thrown away.** [ADR-027](docs/specification/adr/adr-027.md) inferred `sync` from bodies and refused to vouch for a method call, because `stats.add(5)` names `add` and says nothing about what `stats` is. It recorded that as future work: "a method becomes resolvable the day its receiver has a signature written down". The type checker had been resolving method calls on every build the whole time - receiver type, ledger lookup, contract - and nobody was reading the result. [ADR-028](docs/specification/adr/adr-028.md) reads it.
- **The pattern is not new**, which is the argument for it. [ADR-025](docs/specification/adr/adr-025.md) D7 had the emitter ask the type checker which `for` iterates a fallible stream, because answering it means inferring a type and the checker is the module with types. This is the second instance: the alternative was giving `sync.rs` a second type checker, obliged to agree with the first.
- **The ordering is what makes it sound, and it is tested rather than asserted.** `Ledger::infer` now reads the declarations, runs the checker against *that* ledger, then infers `sync` using its answers. That is only valid because the checker reads `signature`, `fields` and `iterates` and **never `sync`** - so resolving a method against the half-finished ledger gives what resolving it against the finished one would. `the_checker_does_not_depend_on_the_sync_it_helps_infer` runs the checker twice, once against each, and compares all three of its outputs. Teach the checker to read `sync` one day and that test fails and says why, instead of the ledger quietly ceasing to be a pure function of its source.
- **Indexing a container has a type** (D4), and this was worth more than it sounds. `Expr::Index` claimed nothing at all, so in `n-body.nika` `let b = &self.bodies[i]` made `b` unknown, so `b.x` was unknown, so `(dx * dx + dy * dy + dz * dz)` was unknown, so `.sqrt()` could not be resolved and `energy` could not be shown to be the pure arithmetic it visibly is. One `Unknown` at the bottom of an expression erases everything built on it. `Vec[T]` and `List[T]` yield `T`, `HashMap[K, V]` yields `V`, and anything else still claims nothing - indexing text is a slice in some languages and a byte in others, and Nikaia has not said.
- **`std.contracts` describes the collections and text the language below provides** (D5) - `Vec`, `HashMap`, `str`, `String`, `f64`. ADR-020 D5's mechanism (a library whose implementation is in another language writes its contracts down and reviews them like code) used for a second purpose. **Every entry was observed being asked for by a program in this repository**, and the discipline matters more than usual here: a missing entry only fails to help, while a wrong one makes the checker reject a correct program - the one promise it cannot break. Types are `?` wherever there is no one type; the **arity** is claimed and checked, and the corpus is what holds that risk down.
- **A higher-order method carries no `sync`, deliberately** (D6). `Entry::and_modify` runs the lambda it is given, so whether it pauses depends on what is in it, and a ledger cannot say "it depends" yet. It gets a signature - the checker resolves through it - and no `sync`, so a caller still loses its inferred promise. That is the correct answer rather than a limitation: `sync = true` there would be a promise about somebody else's code. `sync = "from(f)"` is the shape that would say it properly, and it stays ADR-027 §7's open question.
- **Measured, the same way ADR-027 measured**: strip every `sync` declaration from each example that has one, rebuild, count how many of those exact entries come back on their own. **9 of 18 → 14 of 18.** `n-body` went 0/3 → 3/3 on D4 alone. And the four that remain are **one shape rather than four problems**: every one is a method called on a *lambda parameter* (`.and_modify fn { a.add(…) }` - what is `a`?). Typing that needs the ledger to say what a function-typed parameter receives, which is the same missing vocabulary D6 met from the other side.

### Measured (0.0.8 - the compiler parses 20 % faster, and the survey was pointing the wrong way)

- **`Cargo.lock` moves to `c7dd91a`** ([winnow-grammar#14](https://github.com/keywan-ghadami/winnow-grammar/pull/14)): a rule with several alternatives now skips its leading whitespace **once**, not once per alternative. On `nikaia --backend rust` over 2000 functions (300 KB), under callgrind: **1,025.5 M -> 822.2 M instructions, −19.8 %**, with branches −19.8 %, mispredicts −9.5 % and both cache columns flat. Every column that should move moves, which is what removing *work* looks like rather than buying a mispredict with instructions.
- **The mechanism.** A syntactic rule skips whitespace where it starts, and that skip was emitted inside each alternative - so a sixteen-way rule ran sixteen skips at one position to consume one blank and threw away all but the winner. A rule with a `# "…"` label already hoisted it, for the unrelated reason that the label's offsets have to line up, and that is where the effect showed: adding a label to one Nikaia rule was worth 8.8 % on its own.
- **Nothing observable changed.** The 26-row error corpus exists to catch a message that moved, and it is byte-identical.
- **How it was found, which is the part worth keeping.** `docs/staging-candidates.md` named dispatch over literal alternations as "the actual prize". One callgrind profile of the compiler, taken *before* writing any code, said otherwise: `parse_WS_inner` was **32.5 %** of the parse and the class scan inside it **24.1 %**, against **1.8 %** for the sixteen-way alternation and **1.0 %** for the six-way one. Whitespace was 56 % and the literal dispatch under 3 %. The alternation was the problem - through the whitespace it re-ran, not through the compares it made.
- **Two things measured beside it lost**, and are recorded upstream so they are not re-proposed. Guarding `rt::expected` on `E::RECORDING` - skipping, on the pass that discards messages, work only a message needs - costs **+1.4 %**. And respelling `WS` as `multispace0 (COMMENT multispace0)*` trades **+0.7 % instructions for −7.7 % mispredicts**, which the arithmetic favours by about 2.6× and which was refused anyway: it changes what a parse error says, and an uncertain performance trade bought with a certain regression in messages is not a trade.
- **The step missing from the survey's own list**: profile first. Every candidate in it was derived from reading code; the one measurement taken before writing any overturned the ranking and was cheaper than anything on it.
### Decided and built (0.0.8 - ADR-027: `sync` is earned, not entered)

- **`sync` was opt-in, and that was backwards.** Part II 12.1's rule - a `sync` function may only call `sync` functions - is right, and the *default* under it was not. A function got `sync` in the ledger only if someone typed the word, so `fn bonus(score: i32) -> i32 { score * 2 + 1 }` was recorded as "not `sync`": a claim about a body the compiler had already read and knew better about. [ADR-027](docs/specification/adr/adr-027.md) infers it instead - **a function is `sync` when every call it makes resolves and every callee is `sync`** - and the keyword becomes what `@borrowed` is in Part I 6.6: an assertion you write where you want a property held, not a mode you have to enter.
- **Why it mattered more than an annotation usually does.** `access`, `access_all`, `par_iter`, a scope's tasks under Advanced and the panic hook *all* gate on a `sync` lambda. `sync` is not a niche marker for hot loops; it is the gate on every safe concurrency primitive Chapter 12 has. While it was opt-in, what such a lambda could call was "whatever somebody remembered to annotate", the annotation chain ran as deep as the call graph, and nothing from another library could be annotated at all. The safe path was the narrow one, which is the wrong way round for the thing the language is *for*.
- **The two analyses run in opposite directions, and that is the design** (D2). The **check** on an assertion stays conservative in the *permissive* direction: it reports only calls it can prove will pause, so it never rejects a correct program, and a method call it cannot resolve is not an error. The **inference** runs the other way and claims `sync` only where it can prove it - the same unresolvable method costs the function its claim. The entry is *shipped* (13.5), a consumer reads it and admits the body into `access`, and a wrong `sync` there is a pausing body inside somebody else's lock. [ADR-010](docs/specification/adr/adr-010.md) D1 settled this polarity once already: an analysis that fails open is a vulnerability generator. Both live in one file and share one resolution rule; they disagree only about what an unresolvable call *means*.
- **The ledger says which kind of promise it is** (D3): `sync = true` where the source asserted it, `sync = "inferred"` where the body implies it. A *caller* must not tell them apart and does not - both mean "cannot pause". A *diff* must: withdrawing an assertion is a decision someone made, losing an inference is a consequence of an edit further down the call graph, and two events that print the same line cannot be narrated apart. Absent still means not `sync`, so nothing about how the file is read changes.
- **Measured, on a program that was already written.** `examples/1brc.nika` carries seven `sync` declarations. Strip all seven and rebuild: **four come back on their own** - `Stats::{new, add, merge, mean}`, arithmetic on fields with no calls to resolve - and three do not, because `Summary::{new, record, merge}` reach `HashMap::new()` and `.entry(…)`, a path and a method no ledger names. The boundary is exactly D2's, and the remaining three are [ADR-024](docs/specification/adr/adr-024.md)'s open work rather than this decision's limit: a method becomes resolvable the day its receiver has a signature written down, and neither analysis has to change for that to help.
- **A test reversed, and it is the one worth reading.** `a_constructor_makes_the_same_promise_or_does_not` was written when the check first reported `1brc.nika` and `access-log.nika` - a `sync` method building a value through a constructor that never said `sync` either. That constructor builds a struct literal and calls nothing; it could never pause. The test had frozen a missing annotation as if it were a caught bug. It now asserts the accept, and keeps its other half: a constructor that really *can* pause still takes its caller's promise down with it. The rule did not move; the ledger's answer to "can this pause" got better.
- **Mutual recursion between pure functions keeps the promise**, because the fixpoint is a greatest one - start from "everything is `sync`", take the claim away - rather than a least one, which would deny both functions the promise on the grounds that each is waiting for the other. Pinned by a test, together with the reverse case and with one proving the answer does not depend on declaration order (13.5 makes the file a pure function of source and toolchain; `--locked` compares bytes).
- **`inference` becomes `stage0-signatures+sync-bodies`** (D5). A ledger whose `sync` was read off a declaration is not one whose `sync` was read off a body, and 13.5 built that header for exactly this event.
- **`--locked` now names the entry a changed line belongs to** (D6). `sync` is the commonest line in a ledger now, and the diff was printing bare `sync = true` three times over with no owner - which says something moved and leaves you to find out what. It says whose contract moved.

### Measured and changed (0.0.8 - the first two Tier-1 candidates, and both intuitions were wrong)

- **The measurement harness exists**: `crates/nikaia/tests/measure.rs`, ignored by default, lowers a `.nika` file with the real emitter, compiles it with `-O` and counts instructions retired under callgrind. Two workloads in `benches/`, because a template has two shapes that answer differently - `template.nika` is one growing table, `page.nika` is a static page rendered many times. `docs/staging-candidates.md` §5 said the programs existed and the harness did not; it does now, and a workload lives in `benches/` rather than `examples/` because an example is a program someone reads to learn the language.
- **`html::escape` is 65 % cheaper**, and *two of the three things tried made it worse*. On 40 000 holes: the original (a five-element linear scan per character, twice) cost 466 M instructions; the **table-driven** version this repository's own survey recommended - a 256-entry `[&str; 256]` - cost **541 M, 16 % worse**; a one-word bitmask cost 181 M; and the bitmask *without* the run-copying that looked obviously better cost **161 M**. All five characters are below 64, so "is this one of the five" fits in a `u64` and touches no memory, where a table of fat pointers is 4 KB to walk. This is [ADR-026](docs/specification/adr/adr-026.md) §3.1's pre-registered failure - *"table-free is not automatically faster"* - met from the other side, on the first candidate that tried it.
- **A `dsl html` template reserves what the compiler knows**, and what that is worth depends on the template's shape rather than its size: **−3.4 %** for a static page rendered many times, and **−0.0 %** for one growing table, the same constant 585 instructions at 200 rows and at 20 000. The reservation is a **floor** - every hole and every turn of a `<for>` adds to the result and none subtracts - so it needs no threshold and can never be too large. For a loop-dominated template that floor is a few dozen bytes of a megabyte, which is why the zero is structural rather than disappointing.
- **What this says about the survey.** `docs/staging-candidates.md` §6 ends on *"a staging decision enters the compiler only together with a measured crossover"*. Applied to the first two candidates it named, the rule overturned one recommendation outright and split the other into two answers. Both are now recorded there with their numbers, and the remaining candidate - dispatch over literal alternations, which lives in `winnow-grammar-macros` - has a harness to be measured with.

### Added (0.0.8 - Kap 5.1: the Subject ; Config protocol, G18)

- **A function may take named options with defaults**, which Part I 5.1 has specified since 0.0.5 and nothing parsed. A `;` divides a signature: positional data before it, named options after it, and an option always has a default - which is what makes it an option rather than an argument that has to be passed at every call.

  ```nika
  fn request(url: &str; timeout: i32 = 30, method: &str = "GET") { … }

  request("https://api.com")
  request("https://api.com"; timeout: 60)
  request("https://api.com"; method: "POST", timeout: 5)
  ```
- **The lowering is the interesting part.** The language below has neither named arguments nor defaults, so an option becomes an **ordinary parameter in declaration order** and a call fills in whatever it left out. That means the expansion needs the *callee's* declaration rather than the call - `method` written first above is still passed second - which is exactly what the ledger records. `signature` gained the options with their defaults, so `fs::write(path, data; append: true)` is checked and expanded from the file `std` ships.
- **`fs::write` has the two options its specification names**, `append` and `create`, and they do what Part III 17.1 says: `append` keeps what is there, `create: false` refuses to make a file that is not there, which is how a program says it means to overwrite something in particular.
- **A default is a literal.** An arbitrary expression would raise a question with no obvious answer - whether it is evaluated where the function is declared or where it is called - and that is worth deciding when something needs it. Writing a configuration parameter *without* a default is a parse error that says why.
- **`NK1109`**: a call names an option the callee does not have, with the one that was probably meant. Also reported where the callee has no `;` at all, which is a different mistake and says so.
- **The checker found one of its own bugs on the first program that used the feature.** An interpolated string was typed `&str`; it lowers to `format!`, and a `format!` is a `String`. Two spellings in Nikaia, two types below - and the checker follows the lowering rather than the syntax. Pinned by a test.
- **`examples/tally.nika` uses both halves**: it declares an option and passes one to `fs::write`, appending its summary to a run log.

### Decided and built (0.0.8 - ADR-025: a loop can fail, and the rule was already written)

- **G17 is closed, and it turned out to be two problems.** Trying to build `fs::lines` and `io::lines` produced [ADR-025](docs/specification/adr/adr-025.md): one half is about failure, the other about ownership, and only the first was a question about the language.
- **The failure half, and where the answer came from.** `for line in io::lines()` performs a call per turn that nobody wrote and no signature declares - so there was nowhere for `throws` to attach, and pressing three answers (a line, the end, *I could not find out*) into an iterator's two makes a failed read indistinguishable from the end of the stream. A ten-million-line file reports two lines, successfully. **Part I 6.4 already refuses exactly that** at the *closing* brace of a block, where a resource's cleanup can fail, and calls it "a decades-old bug class in other languages". So the rule was written and had simply never been stated generally: **D1 - an implicit call that can fail fails the enclosing function, and the compiler makes you declare it.** Cleanup is its first case, iteration its second, and a third (an operator, a conversion) is covered in advance.
- **Nothing marks the loop** (D2). [ADR-023](docs/specification/adr/adr-023.md) D8 tabulates the language's invisible control-flow events and refuses to mark one of three, because a mark on one line implies the lines without one are safe. This is a fourth row in that table. Swift writes `for try await` and Zig writes `while (try …)`; Nikaia takes their answer and leaves their marker.
- **`NK2701`, and a range of its own** (D5) - `NK27xx`, *implicit calls*, in the shape `NK2601` set: *this function can fail because a turn of this loop can fail · help: declare the error: add `throws` to this function*.
- **`fs::lines` and `fs::bytes` are removed from Part III 17.1** (D3), not deferred - the way [ADR-009](docs/specification/adr/adr-009.md) closed G4. `lines(path)` was to open the file *and* yield tethered `&str`, so the value would own the buffer and hand out views into itself: the one thing an iterator may not do, and the reason the language below allocates a string per line for the same function. The shape that works is two calls - `fs::map(path)` owns the pages, `.lines()` borrows views of them - and that separation **is** the model Part I 6.6 and ADR-008 rest on. For a record-per-line file the language already has something better than a sequence of lines: `@frame(boundary: "\n")`, which is what `1brc.nika`, `access-log.nika` and `config.nika` all use. None of them iterates lines.
- **`io::lines()` exists**, because a pipe is genuinely different: its bytes do not exist until they are read (ADR-019 D1), so the failure cannot be moved to the call. Its lines are **owned**, which 17.1 already specified for its own reason and which is also what keeps it expressible - an iterator may hand out views into a buffer it does not own, and never into one it does.
- **`examples/tally.nika`**, the tenth running example and the first whose **memory does not grow with its input**: one line alive at a time, however long the pipe. `k-nucleotide.nika` reads all of standard input, which is right for FASTA and wrong for a log that never ends; this is the other half.
- **The ledger has a third kind of fact in it** (D6): `iterates = "throws"` on a type contract, carried by `std.contracts` for `io::Lines`. Second extension, second time it was one key.
- **The emitter reads the type checker's answers for the first time** (D7). It asks [ADR-024](docs/specification/adr/adr-024.md)'s checker which `for` iterates a fallible stream, so `for line in io::lines()` and `let s = io::lines()` followed by `for line in s` are the same thing - matching on the name would have caught the first and quietly missed the second. The checker was built to report; it turns out to be what tells the emitter what to emit.

### Added (0.0.8 - `std` can write a file)

- **`fs::write(path, data)` and `fs::read(path)`** (Part III, 17.1). Every example in this repository ended at `println`, and a program that cannot produce a file is not a tool. `write` creates the file or truncates it, which is what `write` means everywhere; `read` is the bytes half of `read_to_string`, for input that is not text and where nothing downstream is going to cut a `&str` out of it.
- **`examples/report.nika`**, the ninth running example and the first whose result is a **file**: a stock list in, an HTML page out. It is also `escaping.nika`'s claim tested against data that was not written to make the point - the `&`, the `"` and the `<` come out of the *input file*, which is where they come from in every program that has ever had an escaping bug.
- **The example harness checks the file, not the line about it.** `crates/nikaia/tests/examples.rs` gained `wrote:` beside `input:` and `stdin:`, and `{output}` beside `{input}`, so an example whose deliverable is a file is checked by reading it back - under both profiles, which must agree on it as they must agree on what is printed.
- **A rule for the hand-written half of `std.contracts`, and the bug it fixes.** A parameter whose Rust type is a *bound* rather than a type is recorded `?`. `fs::write(path: impl AsRef<Path>, data: impl AsRef<[u8]>)` accepts a `String` and a `&str` and a buffer, so writing `&str` there would make the type checker refuse `fs::write(path, text)` for a `String` - a correct program, rejected, which is the one thing [ADR-024](docs/specification/adr/adr-024.md) promises cannot happen. `fs::map` and `fs::read_to_string` carried exactly that mistake and now do not. The arity is still checked; the type is not claimed, because there is no one type. Pinned by a test.

### Found (0.0.8 - two gaps, from trying to build the rest of `std::fs`)

- **G17 - a stream of lines that can fail while it is being read.** Part III 17.1 specifies `fs::lines` and `io::lines` as `-> Lines throws`, as if the failure happened when the stream was opened. It does not: a read fails *mid-iteration*, and Nikaia had no form that said so. Neither function shipped here. **Closed by ADR-025, above** - and the first write-up of this gap got two things wrong that the ADR corrects: `fs::lines` and `io::lines` are not one problem but two (one about ownership, one about failure), and `1brc.nika` is not built on `.lines()` at all - it declares `@frame(boundary: "\n")` and folds over the mapped pages, which is the language's real answer to line-oriented input.
- **G18 - named arguments with defaults do not parse.** Part I 5.1 specifies `fn request(url: String; timeout: i32 = 30, method: String = "GET")` and nothing parses it. Found by `fs::write`, whose specified surface has `append` and `create` in exactly that position: they are not in `std` because there is no way to write a call that passes one, and inventing a spelling for one function is a spelling to keep or to break later.

### Added (0.0.8 - ADR-024: the type checker)

- **Nikaia checks its own types**, in its own vocabulary, before it emits a line of Rust. Eight codes, and the `NK1xxx` family - *Syntax & types* - had been empty since the catalogue was written: `NK1101` a call passing the wrong number of arguments, `NK1102` an argument that is not what the parameter takes, `NK1103` a `let` that says one type and is given another, `NK1104` a `return` (or a body's last expression) that is not what was declared, `NK1105` an assignment, `NK1106` a struct literal's field, `NK1107` a field that is not there, `NK1108` a condition that is not a `bool`.
- **The whole design is one value: `?`, the absence of a claim.** Half of `std` is still Rust ([ADR-014](docs/specification/adr/adr-014.md)) and a Nikaia program calls `push_str`, `entry`, `chars` and `nth` freely. A checker that had to answer for those would need a second frontend that reads Rust, or a guess - and a type checker that guesses reports errors that are not there, which is worse than one that says less. So every rule has the same shape: infer both sides, and report only where **both are known and they disagree**. The promise that buys is the one worth having: **it never rejects a program that is correct**, and what it catches grows as the ledger grows, without the checker changing.
- **The ledger is its database, and there is no second one.** `signature` on a function and `fields` on a type join `sync`, `throws` and `returns` in the file Part III 13.5 already specified - inferred from the source for Nikaia modules, written by hand and reviewed for the Rust half of `std`, which is the same two-origin shape [ADR-020](docs/specification/adr/adr-020.md) gave it. One mechanism, three sources, in the order a call resolves: this unit, `std`, and a package's own ledger on the day one arrives. A generic parameter is recorded as `?`, because `T` is a name that stands for a type rather than being one.
- **Its first find was real.** `examples/fortunes.nika` put a `&str` literal in a `String` field. Nothing had caught it because that example does not run yet - it waits on the `postgres` DSL - so no `rustc` had ever seen it. That is the case the checker exists for: a program the backend has not compiled, checked in the language it was written in.
- **A string literal is a `&str`, and Part I is corrected to say so** (D5). 2.4 said in passing that `let name = "Nikaia"` makes a `String`, and 2.3 wrote `let strictly_string: String = "Hello"`; 6.6 says an allocation happens **only** where you wrote that you wanted one, which is the language's central claim about large inputs and is incompatible with a literal that allocates at every mention. The literal is a view; `.to_string()` is how you ask for the other thing. This is [ADR-013](docs/specification/adr/adr-013.md) D7's rule - a conversion is written, never quiet - applied to the most common conversion there is.
- **A bare number still makes no claim** (D6). Committing `3` to `i32` would make `add(3)` an error wherever `add` takes anything else, which is more lines than it would be right about.
- **Every finding names a way out**, as Part III C.2 requires: `&str` against `String` suggests `.to_string()`, two numbers suggest `as`, and a field that is not there is matched against the ones that are - with a distance that counts a swapped pair as **one** edit, because `nmae` for `name` is the typo this is for and plain Levenshtein charges two for it.
- **A grammar's action answers to its rule's return type**, and the struct literal in one is checked like any other. That is where a mistyped field name most often is: a rule is the place a struct is typed out in full. What a *pattern* binds is `?` - that belongs to the parser backend and Stage 0 does not read it - and the rule's declared type is enough for both checks that matter there.
- **Where a type does travel, it travels**: a method on a receiver whose type is known resolves under `Type::method` in this unit's ledger or a library's (`fs::Mapped::deref` matched by suffix, name-for-name as everywhere else), a `for` over a `Vec[Row]` binds a `Row`, and a constructor hands back the type it is on.
- **The guard is the corpus**: the checker runs over every `.nika` file in the repository - eight runnable examples, `fortunes.nika`, and `std`'s own modules - and the build fails if any of them produces a finding. Beside it are the deliberately-wrong programs, one per code, which are what makes a clean corpus evidence rather than a tautology.

### Removed (0.0.8 - ADR-022: one lambda form, `fn:` is gone)

- **`fn: expression` is removed** ([ADR-022](docs/specification/adr/adr-022.md)). It was four characters shorter than `fn { … }` and cost three things. **It did not grow**: a body that gained a second line had to change *form* rather than gain a line - not hypothetical, since ADR-013 D7 lists three lines of `1brc.nika` rewritten from it, and the file still carries the comment saying so. **It was a second way to write the same thing**, differing from the block only in a delimiter, so ADR-013 D5 had already spent a paragraph on which to reach for. And **its body swallowed the chain**.
- That last one is the reason this is a removal rather than a deprecation. `.route fn: handler(db)` followed by `.listen(":8080")` lowered to `route(|| { handler(db).listen(":8080") })` - the `.listen` landed **inside** the lambda, with no error and a different program. Both readings are valid expressions and nothing in the grammar can tell them apart, because there is no token between the body and the rest of the chain - which is exactly what a block's `}` is. The specification's own examples were written in the form that misparses: Part II 12.6 chained `.map fn: …` into `.filter fn: …` into `.collect()`, and Part III 17.1 chained `.route("/") fn: …` into `.listen(":8080")`.
- **A method may now take arguments *and* a trailing lambda**: `.route("/x") fn { handler(db) }`. That form had no grammar at all - there was a rule for a method with arguments and one for a method with a trailing lambda, and none for both - and it is unambiguous *because* the short form is gone.
- **The trailing lambda stays**, and it is not the redundancy this removes: `fn:` and `fn { … }` differed only in a delimiter, while inside and outside the parentheses differ in *where the argument goes*, and the outside form is what lets a chain read down the page.
- **Writing `fn:` is an error that says what happened**, because the form was in the specification and somebody will have it in their fingers: *the `fn: …` form was removed (ADR-022): write `fn { … }`. Its body ran to the end of the expression, so a `.method()` after it landed inside the lambda - silently.*
- **`examples/fortunes.nika` parses in full.** Its `main` was the last thing in the repository that needed the added form. What that file waits on now is the `postgres` block - a deferred-parameter DSL (ADR-007 D4) - and G6's runtime binding; the syntax is no longer in the way.
- Part I 5.2 was *Expression Lambdas (The `fn:` Shorthand)* and now records the removal; 5.3 gains the trailing rule. Part II's `par_iter` chain, Part III's server example, ADRs 009, 013, 017 and 018, four example sites and `std`'s own doc comment are written in the one form.
### Added (0.0.8 - ADR-017: the template escapes, and the compiler enforces it)

- **`dsl html { … } eod` is compiled where it is written.** The body is known when the program is compiled, so it is split into literal markup and holes there, and what comes out is the string building a hand-written renderer would do. That is what makes the escaping a **compile-time property** rather than a call somebody has to remember. This is the half of G7 that was decided and not built.
- **D1, every hole escaped, unconditionally.** There is no flag at a hole and no way to ask for the other behaviour: the emitted code always goes through `html::Render`, and the compiler has no branch that emits anything else.
- **D3, a hole is only legal where escaping is enough.** "Escaped" is not one operation, so a hole in a `<script>` body, a `<style>` block, an HTML comment, an unquoted attribute or a **URL attribute** is refused with the position named and the reason given - `a URL needs percent-encoding and a scheme check, not HTML escaping: `javascript:` survives every one of the five characters`. Every illegal hole is named at once, because a template with three of them should say so three times rather than once per build. That check is what lets D1 be unconditional.
- **D2, "already markup" is a type - and the type system enforces it.** `html::Raw` is the promise and `Raw::new` its one constructor; `html::Render` is that decision put where **`rustc`** can act on it: a `Raw` renders itself, text renders escaped, a number writes itself, and a type with no impl cannot be placed in a template at all. The Nikaia compiler emits the same call for every hole and does not need to know which case it is - which is just as well, since it has no type checker.
- **The scan reads the position off the *literal* text**, and that is sound rather than approximate: a hole's value is escaped, so it cannot open a tag, close a string or start a comment. `{{` is a literal brace, the same rule an interpolated string follows, and the framing whitespace of the block - the newline after `{` and the indentation before `} eod` - is not markup and is removed.
- **`examples/escaping.nika`**: an eighth running example, and the smallest program that shows all three decisions. Four rows: three whose text is escaped (`<` and `&` in a name, quotes around a note, an apostrophe, a `</td>` that is not a tag) and one the program built as markup and said so with a type.
- **Control flow is there too**: `<for row in :rows> … </for>`, written as an *element* because the file is markup and an editor that highlights it keeps working - a second syntax in a file that already has one is a second thing to know. `:rows` carries the colon because it is captured from the enclosing scope (ADR-007 D4): that is where the template's names end and the program's begin. It becomes the loop of the language below, over the captured collection, so it borrows rather than copies; the position check runs through the body, because a hole in a `<script>` does not become safe by being repeated. **`fortunes.nika`'s `render` lowers and runs today** - that file now waits only on G6 and on `fn:` in a method chain (ADR-013 D5).
- **A type may be named by a path** (G16): `Shared[postgres::Connection]` did not parse, and `fortunes.nika` found it the moment its template stopped being the first thing that failed. The whole path is interned as one name, because that is what the name *is* to a compiler that lowers name for name (ADR-011 D2) - nothing here resolves a module, and a path can therefore never collide with a struct the file declares.
- **A hole in an interpolated string may hold a string literal.** `"{f(\"a\")}"` handed the parser `f(\"a\")`, which is not an expression. A hole is Nikaia source written *inside* a string literal, so the escaping it carries is that literal's: the two characters the enclosing string had to escape are undone before the hole is parsed, and every other escape keeps its meaning.
- The inline `dsl` block also **parses** now: `Expr::Dsl` had been in the AST since an early draft with nothing producing it. A target other than `html` is refused with what it would need instead - a `dsl sql { … }` is a deferred-parameter DSL (ADR-007 D4), and saying so beats lowering it to something that reads like a template and is not one.
### Added (0.0.8 - ADR-010: provenance chooses the hasher, and it is 26% of the flagship)

- **A map keyed by the input gets the hash that the provenance of that input picks.** `std`'s ledger says which of its calls are **sources** and who chose their bytes (ADR-020: a file the operator named, a pipe they connected, the arguments they typed), `contracts::trust` joins them over the program, and the emitter names the map accordingly. Nothing else about the map changes - same table, same API, same full-content equality (ADR-010 D5).
- **Measured, on the same tree, twice.** Callgrind over 200 000 rows with byte-identical output, once with the hash chosen and once forced back to the hardened one: **120.0 M instructions against 89.1 M - 26 %**, or 600 per row against 446. `docs/handoff.md` and `ADR-011` §4 called this the largest single item left and predicted 22 %; it is more, because the prediction was taken against a slower baseline.
- **What Stage 0's analysis is, exactly**, so that a later one is not mistaken for it: **one buffer**, because ADR-008 gives a compilation unit one input lifetime. The join over a program's sources is not a coarsening of a per-buffer analysis - it *is* the per-buffer analysis, for the one buffer this representation can express. A barrier widens to untrusted, never the other way (D1): what Stage 0 can reach is `std`, which states all of its sources, so today there is no unresolvable one.
- **`nikaia --trust`** prints where the bytes came from, which source said so, and which hash the maps got - the choice is visible, never a mystery (D7).
- **The build cache already covers it**, and this is worth knowing rather than guessing at: provenance is a function of the source and of what `std`'s ledger says about the sources that source calls, and the compiler's fingerprint (ADR-021 D3) hashes `std.contracts` by name alongside the compiler's own sources. So the key moves when the answer can move, without provenance being a key field of its own.
- **`std::hash`**: `FxHasher` and the `TrustedMap` / `TrustedSet` it backs. It is the hash `rustc` uses on its own tables, and it is in `std` rather than behind a dependency for two reasons: it is twenty lines that sit on the hot path of every Nikaia program that aggregates anything, and a program whose *hash function* comes from a crate it did not choose is a program whose iteration order and worst case can change under it. One thing the tests pin because it is real and easily mistaken for a bug: the empty key and the single zero byte hash the same, which costs a bucket comparison and nothing else - a map compares keys in full - where a length mixed into every hash would cost a multiply on every lookup to fix it.
- **`std` has no untrusted source yet**: `http`, `net` and `db` arrive with the modules that have them. The lattice is tested against a ledger that *does* have one, so the join is checked rather than assumed on the day one appears.

### Measured (0.0.8 - the intern cache does not want sizing for 1BRC)

- **`docs/handoff.md` §4's second open item closes without a change.** The question was whether the measurement that rejected keying 1BRC's station table by `Symbol` - 617 instructions per row against 514 for a plain fast-hashed map - had been an artefact of an *unsized* interning cache, since `ParseContext::expect_distinct_keys(n)` exists upstream and Nikaia does not call it. It was not. Callgrind over `intern(until(";"))` on 100 000 rows, sized against unsized: at **413** distinct keys, 1BRC's station count, sizing saves **one** instruction per row; at 5 000 it saves 60. The default 512 slots already holds 413 keys without thrashing.
- **So there is nothing to add to the language for it.** A `.nika` file would need a way to say a key count - an attribute on the grammar, the count being the author's knowledge and not the emitter's to invent (ADR-011 D2) - and that is worth designing when a program wants thousands of distinct keys, not before. Upstream winnow-grammar#13 puts the numbers where the method is documented, so the next person reads them before calling it.
- With this and the item above, **both performance items in the handoff are closed, and both closed by measuring rather than by building**: one was a real cost in a place nobody had looked, the other was not a cost at all.

### Added (0.0.8 - `sync` is checked)

- **Part II 12.1 is enforced**: a `sync` function may only call `sync` functions, reported as `NK2202` on the `.nika` line, with the source line and a caret under it - the shape `--explain` has shown rustc's diagnostics in since ADR-012, because a rule the compiler checks itself should not look different from one it relays. The keyword has parsed since ADR-013 and the emitter wrote `// … Not checked yet.` above every one of them; it does not say that any more.
- **The ledger is what made it possible.** A call to `io::read_to_string` from a `sync` function is only a violation if something says that function can pause, and `std.contracts` is where it says so - which is [ADR-019](docs/specification/adr/adr-019.md) D2 becoming a check instead of a paragraph.
- **What it resolves, and what it does not.** A call by *name*: a function in this unit, a constructor under the name the lowering gives it, or a path like `io::read_to_string` into a library's ledger. A **method call it cannot**, because that needs the receiver's type. So the check is conservative in the permissive direction - it never rejects a program the rule allows, and does not yet catch every program the rule forbids. Worth having and worth saying: an unchecked promise catches nothing at all, and what it does resolve is what the rule exists for, since `fs::` and `io::` are named rather than called on a receiver.
- **A lambda is part of the function that writes it.** `.and_modify fn { … }` runs *during* the call it is given to, so what it calls, the function around it calls. `spawn` is the one that is not walked - its body runs later and elsewhere, which is what a detached context is (Part I, 5.4).
- **It found two on its first run.** `1brc.nika` and `access-log.nika` each had a `sync` method building a value through a constructor that never said it was `sync` either. Both were pure computation all along and both now say so - which is the check doing exactly what it is for, on the two examples that have been in the repository longest.

### Added (0.0.8 - ADR-020: the ledger, and a library brings its own)

- **The Borrow Contract Ledger exists** ([ADR-020](docs/specification/adr/adr-020.md); Part III, 13.5). `nikaia --backend rust` now writes `nikaia.contracts` beside its output, and `--locked` verifies it instead of writing it - the CI line the specification names, exact because the file is a pure function of source and toolchain.
- **It records what a caller must know about a body it cannot see**, which is more than borrows: `sync` (Part II 12.1), `throws` (Kap 7.1), what a result may point into (`returns = "borrows(a | b)"`), and for a type whether it is `@borrowed` and which of its fields tie it to the input - including through another type that does, which is the transitive half of Part II 10.6. Recording only borrows would have meant a second file for the second question, with the same determinism rules and the same distribution story.
- **Only what is true is written**, so an absent `sync` means *not* `sync` while an absent **entry** means nothing is known and a caller may not assume. That distinction is the whole reason the file is worth shipping rather than deriving.
- **The header says which inference produced it.** ADR-005 D3 describes whole-program inference over bodies; Stage 0 reads signatures, and writes `inference = "stage0-signatures"` so the two are never mistaken for each other and `--locked` fails on the difference rather than accepting the weaker answer as the stronger one. The `toolchain` recorded is **Nikaia's** version, not `rustc`'s: these contracts are decided here and never by the compiler this one emits code for.

### Added (0.0.8 - `std` ships its contracts)

- **`crates/nikaia-std/std.contracts`**, the ledger a program's compiler reads when the program calls `io::…` or `fs::…`. Part III 13.5 has always said a published package ships its ledger; this is `std` doing it.
- **Two origins, and the difference is not hidden.** The modules written in Nikaia have their entries *inferred* from their sources, and `crates/nikaia/tests/contracts.rs` regenerates them and fails if the file has drifted. The modules still written in Rust cannot be inferred by a compiler that does not read Rust, so their entries are **written by hand and reviewed like code** - the honest shape of a library whose implementation is half in another language, and a share that shrinks as ADR-014 proceeds. A second test fails if a module reaches the prelude with no contract at all.
- **`text.nika` gained a `sync`.** Writing the ledger showed that `std`'s one Nikaia function did not declare what it plainly is: pure computation that cannot pause. That is the file doing its job on its first day.
- **What this unblocks, and why it is shaped this way.** Part II 12.1's rule - a `sync` function may only call `sync` functions - is unenforced, and [ADR-019](docs/specification/adr/adr-019.md) D2 leans on it in specification while the compiler says nothing: a call to `io::read_to_string` from a `sync` function is exactly what it forbids, and the compiler could not know what `io::read_to_string` is. Now it can look it up. ADR-010's provenance sources are contracts of the same kind, and a type checker's signature store is this file with types added rather than a new one.

### Added (0.0.8 - ADR-019: a program can read standard input)

- **[ADR-019](docs/specification/adr/adr-019.md) and `std::io`.** Part III 17.1 specified `std::fs` down to `seek` and `Cleanup` and said nothing about the input a program in a pipeline has - so Nikaia could open a file by name and could not read what was piped into it. The Computer Language Benchmarks Game feeds every one of its text programs that way.
- **A stream is not a file, and the surface says so**: no `map`, no `seek`, no length, and no second read of the same bytes. `fs::map` hands back pages that existed before the program asked for them; standard input's bytes do not exist until they are read, so a program that wants views into its input owns the buffer first. The omissions are the specification - a `seek` that worked while the input fit in a buffer and failed when it did not would be worse than none.
- **Looks blocking, is not, and is not `sync`.** No `async` on the signature, no `await` at the call, the same as `std::fs`; under Lite the event loop runs another task while the pipe is empty, under Advanced the read may resume on a different thread, and neither is visible in the source. What *is* visible is the rule that matters: **a `sync` function cannot call it** (Part II, 12.1) - which is not a restriction invented here but the existing rule doing the job it exists for, since a `par_iter` body is `sync` precisely so that no core ends up waiting on a pipe.
- **`lines()` yields owned text where `fs::lines` yields views**, because a file's line can be a view and a stream's cannot; **there is one standard input**, so the module is functions rather than a handle two tasks could hold; and **provenance follows the file rule** - Trusted, with `trusted: false` at the entry for the request-body-on-stdin case, so ADR-010 keeps one rule about where bytes came from rather than two.
- `read_to_string` and `read` are implemented; `lines` and `bytes` are specified and are not, exactly as `fs::open` and `fs::seek` are.

### Added (0.0.8 - a seventh running example, on a pipe)

- **`examples/k-nucleotide.nika`**: the CLBG benchmark, reading FASTA from **standard input** and reporting how often each short fragment occurs. `crates/nikaia/tests/examples.rs` grew the ability to feed an example on a pipe rather than a path, because a pipe is what the example is about.
- **What a pipe costs, shown rather than described.** `1brc.nika` maps its file and copies nothing at all; here there are no pages to point at, so the program owns its buffer - and everything after that first copy is the same, which is the part worth seeing. The fragments counted are thousands of **views into that buffer** (`&seq[i..i + k]`), not strings, so a sequence counted at k = 12 builds a table of pointers and lengths.
- It is also a grammar for a format that is nearly not one: FASTA is a header line beginning with `>` and the lines under it, and `not(">")` is what ends a section's body without the repetition needing a terminator. The two stable sorts of Part I 4.5 state the benchmark's compound order - by fragment ascending, then by count descending.

### Fixed (0.0.8 - a `return` inside an `if` stopped returning)

- **An `if` in *statement* position had its branches emitted as tails.** That is right for `let x = if c { a } else { b }`, where the branches *are* the value, and wrong for a guard: the last statement of a branch was written as the branch's value, so `if n < k { return counts }` came out as `if n < k { counts }` and the function carried on. Found by `examples/k-nucleotide.nika`, where the types happened to disagree so `rustc` caught it - **in a function returning nothing it would have compiled and quietly done the wrong thing.** Pinned in `crates/nikaia/tests/expressions.rs`, in both the plain and the `throws` shape.

### Changed (0.0.8 - the compiler parses 17% fewer instructions)

- **Dependency**: `winnow-grammar` `9180b3d` -> `d431ed1` (upstream #12). A class scan is a run of nothing more often than it is a run of anything: the implicit whitespace skip runs between every pair of elements of every syntactic rule, and in a language written without gratuitous blanks most of those find nothing. The scan paid its whole eight-bytes-at-a-time setup to report that the first byte was not in the class; it tests that byte first now.

The cost was in the row of the table nobody had measured.

### Added (0.0.8 - a sixth running example, with no grammar in it at all)

- **`examples/n-body.nika`**: the Computer Language Benchmarks Game's five-body integration, and the first example here that parses nothing. Five programs in a row that all begin with a DSL would say Nikaia is a parser generator; this one is arithmetic in a loop - `sync` methods, `&mut self`, indices and floats - which is the other half of what a systems language is judged on. It is also the only example whose numbers are not ours to choose: the CLBG publishes the same program in some thirty languages with an exact expected output, and **ours matches it to the digit** (`-0.169075164` / `-0.169087605` at n = 1000), which `crates/nikaia/tests/examples.rs` checks under both profiles.

### Added (0.0.8 - arithmetic that reads like arithmetic)

- **A range is an expression** (Part I, 3.3). Part I has shown `for i in 0..5` since the first draft and the bootstrap compiler could not parse it, so an index loop had no way to be written at all. `a..b` excludes its end, `a..=b` includes it, and a range **binds looser than every operator in it** - `0..n - 1` ends at `n - 1`, which is the reading a loop head wants and the only one that is ever useful.
- **A float literal may carry an exponent** (Part I, 2.2): `1.5e-4`, `2e3`, `9.54791938424326609e-04`. That is how a program about physical quantities is written, and the same number spelled out in zeroes is how a digit gets lost in a diff. The rule is lexical, so `1 . 5` is still not a number.

### Fixed (0.0.8 - two that were silently wrong)

- **A postfix applied to something that binds looser lost its parentheses.** A group is not a node - the parser drops it, because that is how the tree was written rather than part of it - so `(a as f64).sqrt()` came out as `a as f64.sqrt()`, a cast to a type nobody named, and `(a + b).to_string()` as `a + b.to_string()`. Both often still compiled, which is what made this worth a test of its own. The receiver of a `.`, the base of a `[`, and the operand of a `?` are now parenthesised where they bind looser.
- **The compiler's identifier accepted a leading digit**, so `1.5` parsed as the field `5` of a variable called `1`. The backend's `ident` accepts one by design and a grammar that wants otherwise says so, which the compiler's own grammar had never done. It printed back identically - which is exactly why it survived, and why the corpus never caught it: the emitted text read the same right up until there was more after it, and `1.5e-4` came out as `1.5e - 4`. `not(digit)` in front of the name costs a character comparison and closes it.

### Added (0.0.8 - a fifth running example, and the three things it found)

- **`examples/json.nika`**: a JSON document, parsed into a tree and printed back. The first input whose shape the *grammar* does not fix - `config.nika`'s tree is two levels deep because its rules say so, and a JSON value contains values to whatever depth the document goes. Three things follow that no other example shows. **An `enum` is the tree**: six variants, and every walk over it is a `match` with six arms that the compiler checks for completeness - the check a `kind: &str` field cannot have. **Two cycles, neither declared**: `value` reaches `value` through `[` and `{`, and `Json` holds a `Vec[Json]` and a `Vec[Member]` that holds a `Json`; the view analysis of Part II 10.6 walks the type cycle to a fixed point rather than into it. And **where zero-copy stops**: a JSON string is not a slice of the input (`"a\nb"` is five characters in the file and three in the value), so `Text` holds the **raw** body - still a view - and `unescape` runs only on the strings a program asks about. That pays twice: printing the document back needs the raw text, so the common case never decodes at all. It is deferred decoding, the argument `dec[T]` already makes for numbers.

### Added (0.0.8 - `char`, which the language could not say)

- **A character literal is an expression and a pattern** (Part I, 2.2 and 3.4). `'n'` was not something the language had, and `char` was not in the table of primitive types either - the type was reachable only because a type is a name. Decoding an escape is exactly the shape a `match` over characters has, so both halves are needed and both are here. The body is kept **as written**: the language below spells `'\n'` the same way, so the lowering is a transcription (ADR-011 D2) and nothing decides twice what it means.
- **`print` and `eprint`**, which are what `println` and `eprintln` always were minus the newline (Part III, 17.1). Output composed piece by piece had no way to be written: a pretty-printer that indents a tree cannot end a line after every fragment. `json.nika` is the first program here that needs it.
- **Part I gains 2.5, string interpolation**, which was in every example and in no chapter: what a hole may hold, what a `:` inside one separates, that `{{` is a literal brace, and that an escape is not a hole.

### Fixed (0.0.8 - a string could not hold a `\u{…}` escape)

- **`"\u{0041}"` was read as a hole named `0041`** and emitted a `format!` with an argument nobody wrote. A string's body reaches the emitter as it was typed - the parser keeps the escapes rather than decoding them - and the interpolation scanner did not know an escape when it saw one. It now copies an escape whole, and the `{` of a `\u{…}` with it. Found by writing `examples/json.nika`, which is what the examples are for.

### Changed (0.0.8 - every error message shows the line it is about)

- **Dependency**: `winnow-grammar` `e222ae8` -> `9180b3d` (upstream #11), and `tests/errors/EXPECTED.txt` regenerated. This is `docs/error-corpus.md`'s **closing finding**, and the only one that applied to all twenty-six rows at once: every message was a headline plus `in <rule>` lines, so a reader of `at line 3, column 5` never saw line 3 - while a rustc diagnostic routed through `nikaia --explain` had carried a snippet and a caret since ADR-012. A position a reader still has to go and look up is half a diagnostic.

```text

   3 |     temp: i32
           ^^^^
note: also possible here: `,`, `//`
in struct_item
```

- **It reaches two places at once**, because both go through the same `render`: the compiler's own messages for `.nika` source, which is every corpus row, and the errors a **generated program** prints about *its* input. `examples/access-log.nika`'s `catch` now shows the rejected log line and points at the character the parse stopped at, and `crates/nikaia/tests/examples.rs` checks that end to end - a Nikaia program compiled, run on a broken file, and its message read.
- **The caret is as wide as the token that was found**, and a line too long to print is windowed around the position rather than scrolled off the terminal. What is still missing against a rustc diagnostic is a file name in front of the message - the driver knows the input and not where it came from - and `= help:` lines.

### Surveyed (0.0.8 - where Tier-1 staging actually stands, and whether the compiler can choose)

- **[`docs/staging-candidates.md`](docs/staging-candidates.md)** follows ADR-022 §3's claim that Tier 1 waits on nothing, and checks it against today's code. The first finding corrects this project's own suggestion: **route hashing has no target** - there is no HTTP server, `route` appears only in `examples/fortunes.nika` at specification level, and ADR-018 parked it. Also not candidates, each for a reason worth recording: `match` over strings (rustc already length-buckets and `memcmp`s it), and character classes and terminator sets (solved upstream and measured - `AsciiClass` runs eight bytes at a time, `until(a | b)` already picks memchr/2/3 below four needles, and every Nikaia grammar uses at most two).
- **The real opportunity is one level down.** A rule with N literal alternatives becomes N sequential prefix compares; the emitter *has* the whole set at compile time (`emit/mod.rs:735`, `:732`) and hands it on unchanged, because every parser decision is made in `winnow-grammar-macros`, an external git dependency. `examples/json.nika:69` pays 8 failed compares for a `Json::Object`; the compiler's own grammar has 35 literal-led alternatives. The obstacle is location, not difficulty - and Cargo fingerprints a git dependency on its commit, so testing needs a `[patch]`.
- **Benchmark programs exist; a harness does not; and the harness is not a prerequisite** - a distinction worth stating precisely, because "we have no benchmarks" is wrong and "we can't measure" is wronger. ADR-010's hasher was measured ad hoc under callgrind at 120.0 M → 89.1 M instructions with byte-identical output. What the survey adds is which benchmark fits which change: **1BRC does not exercise literal dispatch** - it has one alternation, already staged to memchr2 - while `json.nika` and the compiler's own grammar do.
- **And the question underneath all of it: can the compiler even decide?** Byte-determinism answers the largest part. [ADR-005](docs/specification/adr/adr-005.md) D8 with its CI double-builds means the emitter may decide only from source and toolchain, so **autotuning is out** - timing two variants at build time would produce two different programs on two machines. What remains splits four ways: do not decide where LLVM's switch lowering and PGO already do (free, because we emit Rust); a **measured** threshold on a structural property the compiler knows (in house: the three-needle rule - and, in house, the counter-example where that kind of threshold sat at three rather than the assumed six to eight); the input distribution, which the author already declares through alternative order; and the actual CPU, which belongs to runtime dispatch inside `std`. The rule the survey lands on: **a staging decision enters the compiler only together with a measured crossover**, because otherwise the complexity is certain and the gain is not - and it is paid twice, in the language surface and in the generated code.

### Open (0.0.8 - ADR-026: what a build may read, and what may run while it reads)

- **[ADR-026](docs/specification/adr/adr-026.md)** stakes out compile-time I/O, and its status is `Open` - a value no other ADR here uses. Every one of the twenty-one before it is `Accepted` or `Superseded`; this one is a design space with two decisions in it and six questions, written as questions because they are not answered. An open ADR that quietly decides something is worse than none, since the next reader takes a sketch for a commitment.
- **The gap it names.** ADR-007 D3 says one `dsl` syntax serves compile time and runtime and the context decides - but `const` does not exist at item level, in the parser or in `ast::Item`, so the discriminator that decision rests on has no representation. Meanwhile ADR-021 D2 puts every compile-time-read file's hash in `nikaia.lock` and D7 makes it a key dimension: that dimension is implemented, tested, and **has no producer**. And the fact that shapes every option: `GrammarAlt.action` is an arbitrary Nikaia block, so running a grammar at build time is running user code at build time.
- **Decided: I/O belongs to the compiler, evaluation belongs to the sandbox.** The compiler opens the file and hands over *bytes*; the evaluator never gets a path or a handle. A sandbox that has filesystem access and is configured not to use it is a policy that can be misconfigured; one handed a byte slice cannot reach a file because there is nothing to reach with. It also puts "what did this build read?" in one place instead of distributing it across whatever ran.
- **Decided: paths stay in the project, and `..` is refused rather than resolved.** Relative to the source file, inside the `nikaia.toml` root, and a path *containing* `..` is malformed rather than normalised-then-checked - because a check that normalises first is a check that argues with a normaliser, which is where confinement bugs live. Left open inside that decision: a symlink pointing out of the root satisfies the rule as written and defeats its purpose, and resolving links reintroduces the argument the rule avoids.
- **The observation the space organises around**: a grammar is a closed world. It maps bytes to a value of its *own* type and needs neither the surrounding program's AST nor its types, so an external grammar can be translated in complete isolation with a serialisation format as its only boundary. That dissolves the problem every other route hangs on - getting a build-time value of an arbitrary user type back out as source - because the value crosses as bytes either way. It also means DSL-`const` is a *different mechanism* from general `const`, which lets the closed case ship without waiting for the open one.
- **Sharpened after two rounds of outside input**, and the sharpening is mostly a split: **compiler-side staging and user-visible comptime are two features, not one** (§3). Every application usually cited as the reason for the expensive one — perfect hashing over a route table, a regex lowered to a DFA, a flattened state machine — is work the *compiler* does because it knows something, with no sandbox, no fuel budget and no `wasm32` target. The precedent is in this repository and it is measured: ADR-010 picks a map's hasher from the provenance of its keys, nothing in the `.nika` mentions hashing, and it took 22 % of 1BRC's instructions. Tier 1 waits on nothing in §4.
- **Tier 1 must be *able* to emit specialised code, and already is** (§3.1) - recorded so nobody concludes otherwise later. Two routes, both in use: the compiler chooses and `std` provides (ADR-010's pattern; SIMD lives as hand-written Rust in `nikaia-std`, and the emitter carries no `target_feature`, no `std::arch`, no intrinsics), or the emitter generates the specialised code outright (the `grammar` pattern - a DFA as code rather than a runtime table is what it already does). With the caveats attached rather than left for a benchmark: a table-free DFA trades a data-dependent load for an indirect jump and I-cache pressure and does not win universally, and "no branch mispredictions" is backwards for a state machine - the win is where analysis *removes* states.
- **Tier 2 pulls against the thing ADR-021 was built for** (§3.2). Compile-time execution makes builds slow. The complaint about Zig's comptime performance is therefore not a competitor's weakness to exploit but a warning about the feature, on the same terms for us; the cache is the mitigation, turning a per-build cost into a per-change one.
- **Q3 reverses.** The earlier lean toward `wasmi` was badly reasoned: as an interpreter it is roughly an order of magnitude off a JIT, which removes the very speed advantage that would justify Tier 2 over a plain bytecode VM - and the grammar has to be translated to Wasm before anything runs, which for one evaluation dominates what it was meant to accelerate. The honest claim is conditional: the advantage exists for large workloads with a cached module and is negative otherwise. The workload half is unmeasured, and this session already watched an equally plausible assumption (Cranelift as the dev backend) come back 25 s against 26 s.
- **New Q6: trust changes the default, not the mechanism.** Treating all comptime code as hostile was wrong - but "local runs native and unrestricted, foreign is sandboxed" puts the line in the wrong place. *Local* is not the boundary: the dangerous case is your own repo after a `git pull`, where a pull request's DSL executes natively on every reviewer's machine and in CI, which is the `build.rs` attack surface exactly. And two of the three supposed sandbox costs do not track trust at all - **determinism** is ADR-005 D8's hard guarantee and your own code is as able to break it as anyone's, and the **fuel budget** is a tool for the local developer, since a build that hangs silently is worse than one that stops with a call path. That leaves memory and filesystem isolation as the single cost that genuinely tracks trust, and a direction to consider: declare the capability in the manifest instead of inferring it from a directory, so it is a line a reviewer sees in a diff.
- **Prior art and a rejected list**, so the same ideas are not reopened as fresh ones: Zig restricts (`comptime` cannot do I/O; `@embedFile` is the separate declarative capability - D1 plus Q2's restrict branch, shipped), Jai permits, Rust keeps a separate mechanism whose Tier 1 application is served by a *library* (`phf`). Rejected with reasons: a raw-pointer host/guest ABI (voids D1 and isolation, and leaks allocation addresses under ASLR - the layout in guest memory meets its legitimate core), 1BRC as evidence for comptime (our own CHANGELOG attributes those gains elsewhere), "faster than ripgrep" as a claim (the architecture permits it; the sentence invites a benchmark ripgrep wins, because its speed is literal prefilters), and "typed AST nodes at compile time" as a present-day advantage (ADR-013: there is no type checker).
- **The open questions**, with the blocking one named: what a program may do in `const` - purity, allocation, and a fuel budget, because a compiler a dependency can hang is a supply-chain problem in a performance costume. Then: restrict actions to a pure subset (and need no sandbox) or permit and sandbox them; if sandboxed, wasmi vs wasmtime vs an own VM, weighing a `wasm32` target requirement for every contributor and Wasm's determinism asterisk on NaN bit patterns against ADR-005 D8's hard byte-determinism guarantee; and whether confinement needs an explicit grant in D's `-J` style. On that last one the ADR credits what ADR-021 already built - every read is recorded in the committed lockfile, so a dependency that starts reading your `secrets.toml` shows up as a diff in review - while saying plainly that this makes the capability *visible*, not absent, and that the two are not the same claim.

### Added (0.0.8 - the build cache exists now, and two backends stopped lying)

- **`bridge_orchestrator::cache` implements ADR-021.** The crate that every document named as the home of build caching had been fifty lines ending at a `TODO`; it now holds the thing: SHA256 input hashing, `nikaia.lock` as the committed record, a cache key per translation unit, and a content-addressed artifact store with no index of its own. An unchanged unit is served from the store instead of being lowered again.
- **It is on by default, and `--no-cache` is the way out** (D11). Reusing an unchanged lowering is the difference in feel between a Nikaia build and a Rust one, and a default nobody types is not that difference. Being the default is also what turns *where the files go* into a requirement rather than a detail: `nikaia.toml` is found by walking up from the input, as Cargo finds `Cargo.toml`, and decides the shape. In a project the lock is committed at the root and the store sits in `target/nikaia/cache/`, with the unit named by its path below the root (`src/main.nika`) so the key does not move with the checkout. Outside one, a committed lockfile would have nothing to be committed to, so the record joins the store in the user's cache directory and **nothing whatsoever is written into the source tree** - asserted by a test that lists the directory afterwards.
- **A hit serves the whole build, checks included** (D13). Nothing is parsed, `sync`-checked, lowered or inferred on a hit - sound for one reason only: a failing check returns before anything reaches the store, so an entry's *existence* is the statement that this input passed, and skipping the check is reading its memoised result rather than not running it. The price is D7's discipline applied strictly - every input those checks consult has to be a dimension, and a future check that reads something outside the list must add it in the same commit or the cache starts approving inputs nobody checked. The emitted Rust and ADR-020's ledger now travel in **one envelope under one key**, because separate keys would allow a half-hit with the Rust present and the ledger missing and nothing to notice; an envelope that lacks an artifact the current build needs reads as a miss, which keeps adding an output a safe change. What a hit does *not* skip is `--locked`: whether the **committed** ledger still matches is the user's question about the working tree, not the compiler's about the source, and a test tampers with the file to prove the check still bites on a cached build.
- **The compiler's identity in the key is a fingerprint, not a version string** - a correction to how D3 was first built. `CARGO_PKG_VERSION` stays `0.1.0` across every edit to the emitter, so keying on it left the key still exactly while the thing it identifies moved: D7's second failure direction, serving the previous emitter's output and calling it fresh. It lands only on compiler developers, which is why it would have survived. `build.rs` now hashes the sources that decide the output - the compiler's own `src/`, and the `std` ledger `contracts::STD` bakes in with `include_str!`. A version string is a claim about the compiler; a fingerprint is a measurement of it.
- **A cache failure degrades the build and never fails it** (D12), which is the more important half of being a default. A read-only checkout, a full disk, a corrupt lockfile: each costs the *next* build its speed and leaves this one working, with a line on stderr. A cache that turns a succeeding build into a failing one has taken something the user had, and no amount of speed pays for that. The library still returns `Result` - it should be able to say what broke - and the caller is what decides it is not fatal. Driven through the real binary in the tests, because that decision lives in `main.rs` and nowhere else.
- **Every dimension of the key is named in one function**, `Key::build`, which is the whole of D7 in code: nothing is hashed that is not listed there. Fields are length-prefixed, so `("ab", "c")` and `("a", "bc")` cannot collide - there is a test for exactly that, because the alternative is a cache that is silently wrong for one pair of inputs in a thousand. The unit is named relative to its root rather than by absolute path, since a key that moves with the checkout never hits.
- **The profile is in the key, and it is checked against the real emitter.** `crates/nikaia/tests/cache.rs` lowers `examples/1brc.nika` under both profiles and asserts each comes back as itself - and *first* asserts that the two lowerings differ at all, so the test cannot quietly become vacuous the way D5 warns `the_profiles_agree_on_every_example` would if the cache confused them. The lockfile is asserted to contain the unit and its hashes and **not** the profile: a committed file that a profile switch rewrites carries a diff that means nothing. 15 tests in all, 11 on the key's dimensions and 4 end to end.
- **`--backend cranelift` and `--backend llvm` now fail instead of pretending.** Both were accepted by the CLI and silently ran as `bridge`, because the backend list in `main.rs` was a comment and nothing matched those strings; an unknown value fell through the same way. The dispatch is a `match` with named arms, and the error says which backends exist. Implementing the two remains open - ADR-021 D9 records it - but accepting a flag and doing something else no longer is.
- **The toolchain identity is resolved at build time**, not per invocation: `build.rs` records `NIKAIA_RUSTC_VERSION` beside the `NIKAIA_RUSTC` it already exported. It is the rustc that built the emitter, which is the one whose output the cache would be serving, and asking for it once costs no subprocess per build.
- **What is not done**, stated because the roadmap item it closes is easy to over-read: the orchestrator still does not wrap `cargo` or inject `RUSTC_WORKSPACE_WRAPPER` (ADR-003), nothing reports assets yet since compile-time I/O is unimplemented, and the cache covers the *lowering* only - the `rustc` subprocesses in `rustc-executor` and the test harness, which is where the measured repetition actually is, are still uncached.

### Decided (0.0.8 - ADR-021: the build cache is ours, and the lockfile is its key)
- **[ADR-021](docs/specification/adr/adr-021.md)** answers a question the specification had asked three times and never settled. `nikaia.lock` was called a "deterministic cache key" (ADR-002), `nikaia.contracts` an "incremental cache key" (ADR-005), and the orchestrator the place that does "hash-based incremental compilation checks" (ADR-003) - three descriptions of caching, no statement of what is hashed, what invalidates what, or where anything is stored. None of it exists in code: `bridge-orchestrator` is fifty lines that end at a `TODO`, and there is no hash, no lockfile reader and no artifact store anywhere in `crates/`. The ADR is written *before* that component, because a cache key is the one thing that cannot be widened later without invalidating everything built under it.
- **No external compilation cache.** `sccache` was considered and rejected, not because it works badly but because it caches the wrong layer: it memoizes `rustc` invocations, while the repeated work in a Nikaia build is macro evaluation, grammar expansion and lowering - all of it *before* `rustc` is reached and none of it visible to `rustc`. A cache keyed on inputs we already record covers that work; one bolted underneath it cannot.
- **One committed file records everything that determines a build** - asset hashes, source hashes, resolved dependency versions, the toolchain actually used, **and the Nikaia compiler's own version**. That last field is missing from every prior description and is the most dangerous omission available: `emit/mod.rs` is a pure function from source to Rust, which is what makes caching sound at all, but it is a function *we edit*. Without it in the key the cache serves artifacts from the previous emitter, and the failure lands only on compiler developers - which is exactly why it would survive undetected. `nikaia.toml` declares what is required, `nikaia.lock` records what was used; a constraint and a measurement can coexist where two constraints drift.
- **A key may be wrong in two directions, and both are silent.** Too much in it - absolute paths, mtimes, ambient environment - and it varies when nothing changed, so the cache never hits and merely looks useless. Too little in it and it fails to vary when something did, so the cache serves the wrong answer and looks like a miscompilation. Hence: dimensions are enumerated explicitly, nothing is captured incidentally, and git dependencies are hashed on **content** rather than revision - `docs/handoff.md` records what the alternative costs, where Cargo fingerprints `winnow-grammar` on its commit and local edits are silently inert.
- **Keys are per translation unit, and build-time choices never reach the file.** Hashing the whole lockfile is the easy implementation and destroys the property the cache exists for, since one changed asset would then invalidate the project. The profile, opt-level and backend are hashed into the key but never written, or a profile switch would rewrite a committed file for nothing. The profile is **not optional** in the key: Lite and Advanced lower the same source to different Rust, so omitting it would hand `the_profiles_agree_on_every_example` one artifact twice and the test would pass vacuously. A cache may make a test faster; it may never make a test empty.
- **Cranelift was measured rather than repeated.** ADR-002's "sub-second development iterations" claim was inherited from a superseded ADR and never checked. It is compatible - trivial crate, the `rustc_private`/`rustc_driver` linkage that was the plausible blocker, the full workspace including proc-macro crates, all **51 tests green**, identical binary output - and it buys **25s vs 26s** on a full build and **1s vs 2s** incrementally. At `opt-level = 0` the cost is the dependency graph and the proc macros, not codegen. So: a supported, documented option behind `[profile.dev] codegen-backend`, and **not** the default, since defaulting would oblige every contributor and CI job to install a toolchain component these numbers cannot justify. The measurements are in the ADR so the revisit is a measurement and not an opinion.
- **The contract ledger stays its own file** (D10), which was the one question the ADR first left open. `nikaia.contracts` and `nikaia.lock` each call themselves a "cache key", and that shared word is what makes folding one into the other look reasonable. Two properties make it impossible rather than unwise: the ledger **ships with published packages** (ADR-005 D3) while a library's lockfile is ignored by its consumers, so one file would have to be both shipped and not shipped; and **`--locked` would mean opposite things** - regenerate-and-compare byte for byte for the ledger, which is sound only because it is a pure function of (sources, toolchain), versus do-not-re-resolve for the lock, which is mandatory because resolved dependency versions are not a function of the source tree at all. Two softer reasons point the same way: the ledger is derived, so moving it into the lock adds nothing to reproducibility, and its diff *is* the diagnostic `NK2401` cites by line - a signal that does not survive interleaving with asset hashes that churn on every touched file.
- **The shared term "cache key" is retired**, because it named two mechanisms: the lock is read *before* any work and decides whether to start; the ledger is compared *after* inference and decides which callers to re-check. A skip decision and a blast radius, not two implementations of one idea. This also corrects an overstatement in D4: the `toolchain =` field in `nikaia.contracts` is **not** drift, because a ledger that travels downstream without the lock has to describe itself - otherwise a consumer cannot tell a compiler-upgrade diff from their own. Duplication a file needs to be readable alone is not duplication to remove.
- **Two defects found while writing it.** `--backend cranelift` and `--backend llvm` are accepted by the CLI and silently do what `--backend bridge` does - the backend list in `main.rs` is a comment and nothing matches those strings; accepting a flag and quietly doing something else is the worst of the available options and it is the one shipped. And ADR-001 and ADR-002 both still read `Active`/`Accepted` although ADR-003's own header supersedes them; their status lines now say so.

### Decided (0.0.8 - ADR-018: the handler sees the request, because the lambda already could)
- **[ADR-018](docs/specification/adr/adr-018.md)** closes G6's *decision*. Part III 17.1's server takes a handler that takes nothing - `.route("/") fn: "Hello World"` - so a handler could read no query parameter and set no status code. `fortunes.nika` never noticed, because the fortunes benchmark needs neither; the other six TechEmpower tests need both.
- **The request is the handler's first argument, under the rule the language already has.** A block lambda takes as many implicit arguments as its body reaches for (Part I, 5.3), so `fn: "Hello World"` keeps working *unchanged and for the same reason it worked before*, and `fn: a.query("name") ?? "world"` reads one. Nothing is added to the language, and there is no second implicit argument: a response is returned, not filled in.
- **What a handler returns is what answers the request**: a `String` is 200 `text/plain`, an `html::Raw` is 200 `text/html`, a `Response` is itself, and a `throws` that fails is **500 with a generic body** and the error in the log. That last row is a decision rather than an omission - an error's message is written for the operator, and a handler that hands one to the client is how internal paths and driver messages reach a bug bounty report. `html::Raw` earning `text/html` is [ADR-017](docs/specification/adr/adr-017.md) D2 read from the other end: the type that says "this is already markup" is the type that may be *sent* as markup, and a `String`, which might be anything, may not be.
- **A status, a header or a body of one's own is a `Response`**, built where it is returned - `http::Response(status: 400, body: "id is required")`, the anonymous-constructor form of Kap 4.2 with no builder chain. **The request's strings are views** into the bytes the connection read (ADR-008), so a parameter used inside the request's scope costs nothing and one kept past it has to be owned; `query` and `header` return Part I 3.5's nullable rather than an empty string, and `method` returns an enum rather than a string. The surface stops there on purpose: route patterns, cookies and multipart are each a decision of their own and none of them is what G6 was about.
- **Rejected**: a `current_request()` reading thread-local state, which is a lie under a work-stealing executor; the two-argument `fn(request, response)`, which makes "was it already sent?" a question every middle layer has to ask; an always-required `Request` argument, which would break the specification's own one-liner; and returning `String` as HTML, which would make every string in the program a potential injection.
- **This is a decision and not a delivery**, and its status says so: nothing here can be built before the runtime binding. What a handler *is* no longer waits on that work - `fortunes.nika` and `examples/README.md` say so instead of describing a hole.

### Decided (0.0.8 - ADR-017: escaping is the template's contract)
- **[ADR-017](docs/specification/adr/adr-017.md)** closes G7's *decision*. A template grammar escapes **every hole, unconditionally** - not a default, not a lint, not a mode. Provenance does not enter: ADR-010's Ledger decides hashing, where a wrong answer costs performance, and not escaping, where a wrong answer costs the site; one wrong `trusted: true` upstream must not become an XSS hole downstream in a file that does not mention escaping.
- **The one way to say "this is already markup" is a type, `html::Raw`, not a flag at the hole.** A flag is a property of the call site and the same value reaches many call sites; a type travels with the value, is decided where the value is built, and `Raw::new` is one line to grep for. It is the only constructor, so the audit is a grep rather than a type search.
- **A hole is only legal in a position the grammar can escape *for*.** "Escaped" is not one operation - a `<script>` body, a URL, an unquoted attribute and a CSS block each need something else - so a hole in one of those is a **compile error naming the position**. That is what lets the first decision be unconditional: a promise that held only in some positions would have to be qualified everywhere, which is the "escape unless trusted" answer wearing a different hat.
- **`std::html::escape` is implemented and tested** (`crates/nikaia-std/src/html.rs`), in `std` rather than in the code generator so there is one implementation, testable on its own, and a hand-written renderer gets what a template gets. It returns its input **unallocated** when nothing needs escaping - the common case for a database column - so the contract costs a scan rather than a copy. Two things the tests pin because a reviewer should check them: `&` is escaped first, since escaping it last would escape the ampersands the other four just produced, and escaping is *not* idempotent, which is precisely why an already-escaped value gets a type instead of being recognised by inspection.

### Added (0.0.8 - enums and `match`, which Part I specified and Stage 0 could not hear)
- **`enum` lowers**, in all three shapes Kap 4.4 shows: `Quit`, `Write(String)`, `Move { x: i32, y: i32 }`. An enum that carries a **view** takes the input lifetime exactly as a struct does - the analysis walks a variant's field types the way it walks a struct's - which is what lets one appear in a grammar rule's return type.
- **`match` lowers**, with five pattern shapes: `_`, a literal, a variant path (`Op::Times`), a variant with positional bindings (`Message::Write(text)`), and one with named bindings (`Message::Move { x, y }`). A bare name **binds**, which is one rule rather than two: a path with `::` names a variant, a name without one binds, and that is the line the enum's own syntax already draws. Every shape is one the language below spells the same way, so the lowering is a transcription rather than a translation (ADR-011 D2).
- The value is a `head_expr`, for the reason `if`'s condition is one: `match value {` would otherwise read `value { … }` as a struct literal and take the arms for fields.
- **Specified while implementing**: Kap 3.4 gains the table of what a pattern can be and what an arm's body may be; Kap 4.4 gains what an enum is *for* - a value that is one of a fixed set of things, where a string would say the same and check nothing.
- **`examples/calc.nika` closes G12 with it.** Its two operators were a `&str` and a comparison; they are an `Op` and a `match` now, and `mul_tail` yields `(Op, i64)`. The AST had carried stub definitions for `Item::Enum` and `Expr::Match` since an early draft - both unreachable, one of them mislabelled Kap 4.3 - and they are replaced rather than extended.

### Added (0.0.8 - a list can be put in an order, and the spec says so)
- **Part I 4.5 specifies `sort()` and `sort_by_key`, and that both are stable** - which closes G5. A map has no order to borrow: ADR-010 D6 seeds an untrusted one randomly, so its iteration order differs between runs, and a program that prints one has to say which. Stability is what makes two passes state a compound order without a comparator: `names.sort()` then `rows.sort_by_key fn: -a.1` is by hits descending, ties in name order. `examples/access-log.nika` prints its paths that way, and builds the rows as tuples so the key can be a number without looking anything up.

### Fixed (0.0.8 - a lambda that reaches for `a` inside a string)
- **An implicit lambda whose body mentions `a` only inside a string hole was generated with no arguments at all.** How many arguments such a lambda takes is read off which of `a`, `b`, `c` its body mentions, and a string literal keeps its *text* - the holes are parsed when it is emitted, so the scan never saw them. `xs.map fn { "{a.0}={a.1}" }` came out as `map(|| …)` and did not compile. The scan now parses the holes as the emitter does.
- **Part I 5.2 says what the three names are**: they belong to the lambda, and a body that binds one - `let c = …` - is asking for a third argument rather than shadowing anything. ### Documented (0.0.8 - findings for the parser backend)
- **`docs/upstream/winnow-grammar-findings.md`**, with a reproduction for each. (1) **Two expectations beat one and the one is discarded.** Every Nikaia syntax error names whitespace instead of the token that would fix it (`expected one of: '//', whitespace` where `,` is meant), because `WS = (WSE | COMMENT)*` fails with two expectations and is raised to `PRIO_AGGREGATED`, while the real expectation has one and is thrown away at the same offset. It is not about comments: a grammar with no custom `WS` at all (`xs:item* "."` over `1 2 x`) drops the `.` the same way, so *any* rule with two or more alternatives suppresses every single-expectation error at its position. Proposed shape, checked against `tests/diagnostics.rs` p06-p09 and leaving all four unaffected: union the expectations at equal offset instead of returning one side (with `fail(…)` and labels staying authoritative), and rank by **requirement** rather than by how many alternatives an error happens to carry. The criterion is that an expectation is worth reporting only if satisfying it can move the parse past this position - which whitespace provably cannot, the skip being greedy and already exhausted there. Its mechanical form already exists in `repeat_recording_bounded`: an error *returned* below the minimum is a requirement, one merely *recorded* at or above it is an optional continuation. So requirements make the headline, optional continuations a `note: also possible: …`, and optional whitespace is dropped - with no classification, no declaration and no list of rule names. `x+` below its minimum returns, so nothing suppresses a repetition. (2) **The word-at-a-time class scan loses below ~6-8 characters**: `out_mask` is a fixed ~30 instructions per call against ~4-5 per character, so 1BRC's `digit{1,2}` cannot come out ahead. Measured with branches and caches simulated, not instructions alone - the scan does buy 14 067 fewer mispredicts (~0.28 M cycles) for 12.7 M more instructions (~3.2 M cycles at IPC 4), about elevenfold against. A threshold in the code generator, not a change to undo. (3) `dec(p)` and `text(p)` cannot appear inside a `#[frame]`, where `intern(p)` is already excepted with the reasoning that fits all three. (4) The intern cache's 512 direct-mapped slots are sized for identifiers; at 413 keys it costs 617 instructions per row against 514 for a plain fast-hashed map.

### Documented (0.0.8 - what the missing provenance analysis costs)
- **ADR-011 §4** gains the item that was missing from it: **input provenance, and therefore the hasher**. ADR-010 decided this at the specification level - `fs::map` is a trusted source, so 1BRC's station map should get a fast hash with nothing written in the source about hashing - and Stage 0 cannot do it, because choosing the hasher means knowing that a map's keys are views into a trusted buffer, which is dataflow through the grammar's return types and a struct field, and ADR-011 D2 forbids the emitter from inferring one. Stage 0 therefore treats every buffer as untrusted (`RandomState` *is* ADR-010 D5's `Untrusted` row), which is ADR-010 D1's own "barriers widen to `Untrusted`" applied to the widest barrier there is. **Measured, 8M rows with 413 stations, byte-identical output: `--profile lite` 0.53 s / 656 instructions per row against 0.46 s / 514 with the fast hash; `--profile advanced` 0.15 s against 0.12 s.** 22 % of the flagship's instructions, and the largest single item left - the map is 39 % of all instructions, SipHash alone 27 %. No `.nika` file gains an annotation: ADR-010 §4 rejects both the constructor the user must remember and a global default in either direction. Also recorded there: the intern-cache route was measured and rejected (617 instructions per row at 413 keys against 514, because the cache is 512 direct-mapped slots with no collision handling - right for a compiler's identifier stream, wrong for an aggregation), and D5's "the build fails without a real entropy source" is not true yet.

### Added (0.0.8 - type arguments in a grammar)
- **Compiler/lowering**: a built-in may take a type argument - `dec[i32](digit{1,2})`, `intern[Symbol](...)`. Nikaia spells a type argument with brackets everywhere (Kap 4.3), which is what keeps `<` free in the language; the backend spells it with angles, and the emitter is the one place the two meet, so no `.nika` file writes the backend's spelling. Before this, `dec<T>` was simply unreachable from Nikaia - the grammar parser stopped at the `<`.
- **Measured, and the example was *not* changed:** `dec[i32](digit{1,2})` in 1BRC's `TENTHS` costs **693 instructions per row against 659** for the two-iteration `value * 10 + digit_value(d)` loop it would replace (0.55 s against 0.52 s on 8M rows). `str::parse` does its own scanning, sign handling and overflow check; over one or two digits that is more work than the loop, not less. `dec` earns its place on a wider field, not on this one. Also found on the way: the backend's frame check treats `dec(p)` and `text(p)` as consuming anything, so neither can appear inside a `#[frame]` - `intern(p)` is already excepted with exactly the right reasoning ("it is a map over its argument, and the argument is checked on its own"), and these two are the same case. Reported upstream; `@frame(..., unchecked)` is what made the measurement above possible.

### Changed (0.0.8 - lazy diagnostics upstream, and 1BRC below hand-written Rust)
- **std/ADR-016** "The UTF-8 Check Is Divided, Not Skipped". Closes ADR-015 §3's first item. `fs::map` cuts the mapping into one piece per core and validates the pieces in parallel; a cut walks forward off a continuation byte so no sequence is split, and the reported offset is the **earliest** failure, so a rejected file names the same byte however many cores looked at it (four tests hold this to `std::str::from_utf8` as the oracle, including a corruption at every cut +-8 bytes). Below 1 MiB it stays in one piece. D3: the profile does not reach into `std` and does not here - ADR-011 D4 lets nothing but the DSL driver read it, and a check with the same verdict and the same offset on one core and on sixty-four has no result to merge, so Lite is sequential *parsing*, not a vow of single-threadedness. Measured on 8M rows, 4 cores: **lite 0.57 s -> 0.52 s, advanced 0.19 s -> 0.14 s**; the check alone 63.7 ms -> 16.5 ms (1.7 -> 6.6 GB/s), ~7.6 s -> ~2.0 s projected onto 1BRC's 13 GB. Instructions per row unchanged at 659 - chunking moves work, it does not remove any; the check is 30 Ir/row, 4.5 % of the instructions and 11 % of the time, because it is a second pass over 105 MB rather than arithmetic. Deleting it outright buys 10 ms and prints a station name that is a `&str` and is not UTF-8, so it stays (D1). Also recorded: `std::str::from_utf8` runs at 10.3 GB/s on an ASCII-only twin of the file and 1.7 GB/s on the real one, because one non-ASCII byte drops its word-at-a-time fast path and 1BRC has a multi-byte character every ~68 bytes.
- **Compiler/ADR-015** "The Backend's Lazy Diagnostics - and What They Did to 1BRC". Supersedes the measurement in ADR-014 D3. `winnow-grammar` now parses with a zero-sized error type first and only diagnoses a *failed* parse, replaying from the item a `par_fold` stopped in (upstream ADR 17); Nikaia takes the default (`Diagnose::Replay`) and emits no choice of its own - a `--profile` that picked one would change what a program means, which ADR-011 D4 forbids. D2, the three migrations: `parse_<rule>_pieces` takes `&ParseContext` rather than a factory (the factory form is `parse_<rule>_pieces_with`); a repetition of a character class now yields the text it matched, so `digit{1,2}` is `&str` and the corpus says `for d in whole.chars()`; and a rule binding may not be called `input`, because the generated closure's parameter has that name and every action now ends with `let _state = &mut input.state;` - Nikaia's own `dsl_from_expr` shadowed it and binds `source` now. D3, re-measured on the same machine and the same 8 million rows: **`--profile lite` 3.99 s -> 0.57 s, `--profile advanced` 1.05 s -> 0.19 s, 4506 instructions per row -> 659** - against 840 for the same aggregation written naively in Rust and 688 for it hand-tuned, so a generated parser is now *below hand-written code* on instructions per row. The decisive experiment is gone with it: an all-negative file used to parse in half the time of a mixed one (one failing optional per row cost 52 %) and is now the same speed per byte.

- **Compiler/emitter**: all of the above, plus string interpolation with format specs, `println`/`eprintln` as macros, and `collect()` as `collect::<Vec<_>>()`.
- **`crates/nikaia-std`** (new): `fs::map`, `cli::args`, `HashMap`, `digit_value` and `List::map`. Nothing is stubbed - `fs::map` reads rather than maps, and says so where a reader would look.

### Added (0.0.8 - Bootstrap Compiler: diagnostics on the source line)
- **Compiler/ADR-012** "Diagnostics - Reporting Errors in the File the User Wrote". Closes ADR-011 §4. Stage 0 emits Rust, so everything that goes wrong - rustc's own type errors and the parser backend's frame check alike - was reported against a file nobody wrote. ADR-011 D3 had already refused the obvious fix (a second checker in Nikaia, which drifts), leaving the error's *provenance* open. Decisions D1-D7: the lowering emits a **source map** and that is the whole mechanism - one answer for every error class rather than one for the frame check; the map is **derived, never stored** (the lowering is deterministic, so `nikaia --explain` rebuilds it rather than keeping an artifact in step); **positions are corrected, messages are not**, which is ADR-011 D2 paying out - `NAME` and `MEASUREMENT` in the backend's message already are the user's rule names, and translating the text would be a second compiler; the innermost span wins and the granularity is stated (items, grammar rules, every pattern, statements - expressions not yet, so a type error blames its statement); an **unmapped diagnostic says so** rather than guessing a plausible line; spans come from the parser backend's `@=` injection rather than an offset scheme of Nikaia's own; and Nikaia is a **filter over `--error-format=json`**, not a build system.

### Added (0.0.8 - Bootstrap Compiler: the grammar lowering)
- **Compiler/ADR-011** "Stage 0 Lowering - the Grammar Protocol onto the Parser Backend". The parser backend has carried frames, `par_fold` and the piece driver since ADR-009; Nikaia could not reach them, because a `grammar` item was parsed as `content: String` - a shape from which no frame can be checked, no entry rule found and no driver generated. Decisions D1-D8: a grammar is **parsed, not carried as text**; the lowering is **syntactic and never guesses a meaning**, so a `&mut self` method used as a monoid's merge fails to compile rather than being adapted by an emitter inferring mutation from the shape of a tail expression (that is a typing question, and it waits for `impl` lowering); `@frame` lowers key for key with its boundary escape intact and Nikaia **does not re-implement the check** - two implementations of "checked, never rewritten" would drift, and the disagreement that matters is the one where Nikaia accepts what the backend rejects; the **profile chooses the `Parallelism` and nothing else** (Advanced `Auto`, Lite `Off`, one token apart), because a profile is a runtime and not a dialect; a rule that *is* a `par_fold` gets its binding from the compiler, since ADR-009 D2 leaves an action nothing to add; a view takes the input's lifetime and the struct holding it comes along, transitively (ADR-008 - the source never writes a lifetime); comments become whitespace through a `WS` override and string literals get a lexical rule of their own, the built-in's escape set being one short of the `"\n"` every frame is written with; and a `grammar` on the Bridge IR path is an error naming `--backend rust`, never a silently dropped item.
- **Compiler**: `--backend rust` (the Stage 0 transpiler) and `--profile lite|advanced`. `grammar Name { … }` emits `grammar! { … }`, `@frame(boundary: "\n")` emits `#[frame(boundary = "\n")]`, and `dsl Name from data` emits `Name::parse_<rule>_pieces(data, ParseContext::<()>::default, Parallelism::…)` - or the sequential driver where the entry rule is not a `par_fold`.
- **Compiler/parser**: the grammar construct (rules, alternatives, the commit point `=>`, bounded repetition `p{n,m}`, `until(… | frame_end)`, `fold`/`par_fold`, the keyed `@frame`), `struct` and `use` items, `@borrowed`, and the expression grammar action blocks are made of - paths, method calls, field access, struct literals, `fn(a, b) { … }` lambdas, unary and binary operators with precedence, `?`, `for`, assignment. `if`/`for` heads parse with a brace-free expression rule, so the brace that follows is the body and never a struct literal, which is the restriction Rust puts on the same position.
- **Tests**: `crates/nikaia/tests/grammar_lowering.rs`. The checked-in expected output is `include!`d, so the parser backend has to accept every line the emitter produced, and the generated driver is run at five cuts (`Off`, 1, 3, 64 pieces, `Auto`) to check that the answer does not depend on how the input was divided - on an input it accepts and on one it rejects. A further test takes the `grammar` block out of `examples/1brc.nika` itself, so the example and the compiler cannot drift apart.
- **Examples**: `1brc.nika`'s note and `examples/README.md`'s introduction now say which half of that file lowers and which does not.

### Changed (0.0.8 - Frames, corrected against winnow-grammar ADR 16)
- **Spec/ADR-009 D1 re-amended.** Yesterday's amendment ("bounded, not rejected; a rule reached from a frame is bounded wherever it is used") described an intermediate design that review upstream rejected, and rightly: a silent repair made the same rule text parse differently depending on what reached it. The principle adopted instead — **the compiler checks the grammar and never rewrites it**, the parsing-side twin of ADR-005 §3 — gives two verdicts and no third: safe, or rejected with the rule and pattern named. `frame_end` is the built-in that names the enclosing frame's boundary (written once in the attribute, referenced; resolved statically, an error outside a frame or under two boundaries); `until` takes an alternation, up to three fixed alternatives in one scan; `recover` under a frame is rejected with the frame-local alternative as the hint. The attribute is keyed — `@frame`, `@frame(boundary: "\n")`, `@frame(boundary: "\n", unchecked)`; the positional `@frame("\n")` is withdrawn — and `unchecked` is adopted as the greppable escape hatch, replacing "no unchecked escape hatch in this version", because the open flank is real: quoted fields, start patterns, escapes and custom scanners are cut points a byte-string boundary cannot find, and each is a future key. Lexical frames and "a frame ends in its boundary" stay; "bounded wherever used" is withdrawn.
- **Spec/ADR-009 D2**: a `par_fold` rule's parser skips no whitespace at its entry, so pieces and the sequential parse agree on every input including rejections — "chunk count does not change results" is now a property of accept *and* reject. Lite's degradation is the driver's `Parallelism::Off`, defined identical to the plain parser.
- **Spec/ADR-009 D3**: the driver exists upstream — `parse_<RULE>_pieces(input, new_context, Parallelism::{Off, Pieces(n), Auto})`, optional `rayon`, error offsets shifted into the whole input; what remains Nikaia's is choosing `how` from the profile, the `sync` check, and the executor (the cut and merge stay public for Nikaia's own pool). `dsl Measurements from data` lowers to `parse_file_pieces`.
- **Spec/ADR-009 D4**: alternation terminators, up to three in one pass.
- **Spec Part II (10.7)**: rewritten to match — `frame_end`, two verdicts, never rewritten, `unchecked` and the formats it is for, no whitespace at `par_fold`'s entry.

### Changed (0.0.8 - Frames, from the implementation)
- **Spec/ADR-009 D1 amended.** The check as first written ("reject when any reachable rule can consume the boundary") would have rejected the grammar it exists for: `NAME = until(";")` consumes anything up to the semicolon, a newline included. The implemented check sorts consumers into three classes — safe, **bounded** (`until` and `recover`'s skip stop at the terminator *or the boundary*, one `memmem2` scan, so a name with a stray newline fails at the newline instead of joining two frames), and rejected (a literal containing the boundary, `any`, `multispace0`, a syntactic rule). ### Added (0.0.8 - Input Provenance)
- **Spec/ADR**: ADR-010 "Input Provenance — Where the Security Requirement Is Stated" — resolves gap **G8** and **corrects ADR-009 §5's framing**, which posed the hasher question as a profile problem. The profile answers "which runtime", never "who supplied these bytes": a single-threaded Lite server hashing attacker-supplied header names is exactly as vulnerable as an Advanced one, and a compute job over operator-chosen data has no adversary in either. Decisions D1-D8: trust is a two-state lattice (`Trusted ⊑ Untrusted`) on *sources*, travelling the provenance edges ADR-008 already tracks, recorded in the Borrow Contract Ledger, solved by the same monotone fixpoint (so ADR-005 D8's determinism covers it unchanged) and **failing safe** at `dyn`/FFI barriers — the opposite direction from ADR-008 D7's representation barrier, deliberately; `std` classifies its own sources by channel (network, IPC and database rows untrusted — stored data is attacker-chosen data with a delay; files, argv, env and compile-time data trusted); the user has the last word at the place data enters, in both directions (`fs::map(path; trusted: false)`), with every assertion recorded in one auditable file; a grammar may pin an `@untrusted` floor its callers cannot lower, which is the DSL's answer, while no `@trusted` floor exists because a format cannot make its input safe; the compiler then picks only the hasher — keyed with a per-process random seed for untrusted keys, fast for trusted ones, with the build failing rather than falling back to a fixed seed where there is no entropy source — and never weakens equality or layout; map iteration order is consequently unspecified and may vary between runs; `nikaia explain --trust` makes every choice visible. D8 keeps the mechanism general (G7's HTML escaping is the obvious second consumer) while recording that escaping at a template hole must stay unconditional: provenance may add lints there, never switch escaping off.

### Added (0.0.8 - Parallel Parsing)
- **Spec/ADR**: ADR-009 "Parallel Parsing — Frames, Monoid Folds, and Format Assumptions in the Grammar" — closes gap **G4** by dissolving it. Decisions D1-D7: `@frame` marks a rule as a resynchronization unit and the compiler **verifies** the property (the boundary must not be consumable inside a frame, so CSV with quoted newlines is rejected instead of silently miscounted) rather than trusting an assertion; `par_fold(rule, init, step, merge)` supplies the second half, and parallel parsing is exactly a frame plus a monoid; the lowering (blind split, seam repair, frame ownership, EOF and oversized-frame edge cases, absolute error offsets) is normative; byte scanning is a **specified complexity** — never one byte at a time — with portable word-at-a-time SWAR as the baseline and SIMD only as a target-gated layer, so Lite and `wasm32` keep the same performance story; fixed-width numeric parsing requires bounded repetition in the grammar rather than compiler guesswork; a view may be hashed from its first bytes but equality stays full-content; a large read-only mapping may be left to the OS at process exit. - **Spec Part I (6.5–6.8)**: References & Borrowing guarantees ("no lifetime annotations, ever"), Tethered Slices rule ("transient = borrow, stored = tether"), Borrow Contract Ledger overview, diagnostics promise with worked `NK2301` example.
- **Spec Part III (13.5)**: The Borrow Contract Ledger (`nikaia.contracts`) — generated committed file serving as incremental cache and as the diff basis for narrated "what changed and what broke" errors (`NK2401`).
- **Spec Part III (Appendix C)**: The Diagnostics Contract — untranslated rustc errors are compiler bugs; NK error-code catalogue with testable requirements.
- **Spec/ADR (D8)**: Determinism requirement for contract inference — the ledger is a byte-deterministic pure function of (source tree, toolchain); parallel solving allowed, cross-toolchain stability explicitly not required, one profile-neutral ledger per project, violations are compiler bugs; includes implementer ban list and CI double-build/cross-OS test definitions.
- **Spec Part III (13.5)**: Determinism guarantee and `--locked` verification mode for `nikaia.contracts`.

- **Spec/ADR (ADR-006 D6)**: The Panic Hook (`std::panic::on_panic`) — global per application, `sync`, runs on every panic path including Lite's abort and the WASM trap (rides on the backend invoking the hook before abort under `panic = abort`); diagnosis-not-cleanup rule, brief-blocking allowance with Advanced nuance, recursion guard; `NK2604`; stackable hook chains rejected. ### Changed
- **Spec Part II (10.6)**: Zero-copy parsing respecified on Tethered Slices (`bytes::Bytes` model over `Shared`); buffer provably outlives tokens instead of borrow-checker rejection. Unsafe self-referential codegen recorded as future optimization note.
- **Spec Part II (12.2)**: "No I/O while holding a lock" is now a compile-time rule — `access`/`access_all` require a `sync` lambda in both profiles (`NK2201`); runtime reentrancy check/poisoning demoted to backstop.
- **Spec Part II (12.7)**: Scoped tasks respecified for soundness — Lite: runtime-owned scopes, any child task allowed; Advanced: child tasks must be `sync` (`NK2102`), async children use `spawn` + implicit move. Beginner-oriented rewrite with worked error messages.
- **Spec Part I (8.3)**: Resolved contradiction with 5.4/11.2 — `spawn` uses implicit move (no `move` keyword); rewritten with `.clone()` guidance and worked `NK2101` error.
- **Spec Parts I–III**: Version bumped to 0.0.6 (aligns with README badge); fixed a `nila` code-fence typo (Part I, 5.4) and an unclosed code fence (Part III, Appendix B).
